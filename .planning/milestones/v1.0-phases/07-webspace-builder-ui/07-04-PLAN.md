<objective>
**As a** person whose webspace is missing a source, **I want to** add it from the chip row — picking an already-configured instance or connecting a brand-new one — and edit what an existing source matches on, **so that** wiring a source into a topic never means hand-editing TOML and never means restarting.

Purpose: this is the phase's headline capability. 07-01 gave it a write path, 07-02 gave it apply-on-save and Describe-before-persist, 07-03 gave it the overlay primitives. This plan builds the picker, the two add flows, the shared vocabulary-driven match form, the secret-field contract, and the chip edit menu.

Output: a `+` affordance in the chip row that composes a webspace's source set end to end, and a `⋮` menu on every chip that edits it.
</objective>

SecretField.svelte. Props: `label`, `value` (the environment variable NAME), `placeholder`, `envVars: Record<string, boolean>`, `oninput`. Renders the label, a plain text `Input` whose content is the variable name — never a password input, never an autofill-eligible input, and never seeded from anything but the variable name already in config — and immediately below it a badge reflecting whether that variable is currently set in the kernel's environment: a `CircleCheck` icon at 14px in `text-success` beside Label-role text `Set`, or a `CircleAlert` icon at 14px in `text-warning` beside Label-role text `Not set — add it to .env and restart before this source can connect.` The badge does not render at all while the input is blank. Two-step flow in AddSourceModal.svelte. Choosing a `New {plugin type}…` row opens a `max-w-lg` `Dialog`. Above the title sits a two-dot step indicator at the Label role in `text-muted-foreground` with the current step in `text-foreground font-semibold`, reading `1. Connect` and `2. Match`.

Step 1 is titled `Connect {Plugin Type}` and renders `ConnectionForm`. Its footer is `Cancel` (ghost, left) and `Next` (default, right). `Next` derives the instance id from the display name — lowercased, spaces and punctuation collapsed to single hyphens, trimmed — and rejects locally only what the kernel cannot express: a blank id, or an id already present in `config.sources`. Everything else, including display-name uniqueness, is left to the kernel's own validator so there is one rule set. `Next` then calls `describePlugin` with the plugin binary and the assembled `SourceConfig`; nothing is persisted at this point. On success it advances to step 2 with the returned `match_vocabulary`.
