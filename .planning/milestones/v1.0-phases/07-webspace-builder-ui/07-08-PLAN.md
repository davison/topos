<objective>
**As a** person who opened a source's Edit connection…, typed something wrong, and clicked Cancel, **I want to** the next time I open that same source to show me what is actually configured, **so that** I can never save a value I already rejected over a connection that was working — the same promise the UI write path makes everywhere else in this phase.

Purpose: this plan closes the second of the two blocking gaps in 07-VERIFICATION.md — 07-REVIEW.md's CR-02 (Critical, unresolved as of `ccc9449`). `handleEditClose` and `handleEditSaved` in the webspace route only flip the modal's open flag; they never clear `editInstance`/`editMode`. Because `EditSourceModal` is rendered inside a `{#key}` built from exactly those two values, reopening the same source in the same mode produces an identical key, Svelte does not remount the component, and its form `$state` — seeded once at mount — survives from the previous session, discarded typing and all. The user then sees a pre-filled field indistinguishable from real data and can save it straight over the real connection config, silently reverting `base_url`, the `${VAR}` token reference, the display name, or the instance's agent grants. The one place this discipline IS implemented correctly, `ManageSourcesModal`, is not the primary entry point; the chip ⋮ menu is.
