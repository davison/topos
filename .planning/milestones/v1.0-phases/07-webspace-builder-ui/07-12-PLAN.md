<objective>
**As a** person opening topos for the first time, or after clearing out my webspaces, **I want to** land on "No webspaces yet" with a button that creates one, **so that** I am not told the service is down when it is running perfectly and answering my request.

Purpose: this plan closes 07-UAT.md `G-07-4`. With zero `[webspaces.*]` blocks, the root route renders "Couldn't load this webspace — the topos service didn't respond" and offers nothing at all — no CTA, no link, no way forward. The kernel is up and answers `200 OK`; the diagnosis confirmed this against a live ephemeral kernel on port 7799. Two defects compose. Kernel-side, `Webspaces map[string]Webspace` (`kernel/config/types.go:19`) carries no `omitempty` and is never allocated by `applyDefaults`, so with no blocks in the file it stays a nil Go map and `encoding/json` marshals it as `null`. Client-side, `web/src/routes/+page.svelte`'s `onMount` calls `Object.keys(res.config.webspaces)` — which throws a `TypeError` on `null` — inside the same blanket `catch` used to detect an unreachable kernel, so the throw lands on the `error` phase and renders copy that is simply untrue. The second defect is the more dangerous of the two: it is a general mechanism for misattributing any downstream bug on that route as a kernel outage, which is exactly how a one-line null deref presented to the user as a dead service.

Output: `applyDefaults` normalizes every collection the config API exposes, so `GET /api/config` never emits `null` for a field the client iterates — consistent with the null-to-empty convention `unknownKeysOrEmpty` already applies to the same response body; the root route reads the webspaces map defensively and computes its redirect decision outside the fetch's catch, so the service-unreachable copy is reachable only by an actual request failure; and both halves gain tests, including a wire-level assertion on the response body itself.

**Scope discipline (gap closure).** This plan closes `G-07-4` and nothing else. `G-07-3` is 07-11 (which this plan depends on, for `kernel/config/config.go`), `G-07-5` is 07-13, `G-07-6` is 07-14. No new route state, no new copy, no layout change, no dependency.

**Recorded planning choices.**

1. **Both halves are implemented, not one.** The diagnosis calls them independent and non-exclusive, and recommends the client guard "regardless". The kernel fix is the root-cause-aligned one and removes the hazard for every current and future client of `GET /api/config`; the client fix removes the misattribution mechanism, which would still be a live bug even with a perfectly-behaved kernel. Fixing only the kernel would leave the next null-deref on that route lying about its cause; fixing only the client would leave `"webspaces": null` on the wire for every other consumer to trip over.
2. **Normalization is placed in `applyDefaults`, which runs on BOTH the expanded and raw forms.** `LoadRaw` calls it at line 68 for the expanded config and line 83 for the raw one, and it is the raw form that `GET /api/config` serializes and `WriteCanonical` writes. Placing it there is what makes the API guarantee hold; it is also why the "no serialization change" prohibition matters — verified by the fact that `toml.Marshal` already emits `[]` for a nil slice, so the written bytes are unchanged.
3. **Per-webspace collections are normalized too, not just the top-level maps.** The gap's `missing` list names `Webspaces` and `Sources`. But `Webspace.Keywords`, `Webspace.Sources` and `Webspace.Match` carry no `omitempty` either, so a hand-written webspace that omits `sources` puts `"sources": null` on the wire — and `config-edit.ts`'s helpers and `WebspaceHeader`'s chip row read those fields directly. That is the same defect one level down, latent today only because the user's config has been through a UI save (the canonical writer emits `[]`). Normalizing one level and not the other would close the reported symptom and leave its sibling armed.
4. **`Filter` is deliberately excluded.** It is the one collection field with `omitempty`, so that a webspace with no permanent filter writes no `filter` key (D-17/D-18). Normalizing it would add a meaningless key to every webspace block on the next canonical save.
5. **The client keeps its defensive read even though the kernel now guarantees non-null.** Defence in depth: the SPA is served by a kernel binary the user may not have rebuilt, and the readers added by 07-11/07-14 in `participation.ts` are the same discipline. The kernel guarantee makes it unreachable; it stays because unreachable is not the same as impossible.
6. No package is installed by this plan; 07-RESEARCH.md's Package Legitimacy Audit needs no new row. No ORM schema files exist, so the Schema Push Gate does not fire.
