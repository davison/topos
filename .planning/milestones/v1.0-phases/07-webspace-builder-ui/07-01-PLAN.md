<objective>
**As a** person whose webspace has grown noisy, **I want to** turn a search I just ran into a permanent filter on that webspace, **so that** the stream stays narrowed to what I actually care about without me hand-editing TOML.

This is the phase tracer: the thinnest production-quality path that crosses every layer Phase 7 touches — browser affordance → typed API client → the kernel's first mutating HTTP route → dual-parse config model → canonical TOML writer with backup and atomic rename → in-process config swap → filtered index read → agent-surface parity.

Purpose: prove the config write path end to end on one real user capability before any expansion task builds on it. Every later plan in this phase (hot-apply, the switcher, the source picker, the manage-sources escape hatch) writes through the exact `PUT /api/config` + `config.Store.Save` seam this plan establishes.

Output: a working search-promotion flow, a persisted `filter` key that hand-editing and the UI both agree on, and the kernel's first mutating surface with its clobber guard, secret-safety invariant and validation reuse all under test.
</objective>

<assumption_delta_decision>
The `assumption-delta scan` detector fired `kind: chosen` on the phase goal ("choose from available plugin types, configure instances"). A configuration decision has become a modeling decision.

- **Primary noun:** the *running configuration* — no longer "the TOML file the kernel read once at boot", but a live, versioned, hash-identified resource with a raw (unexpanded, persistable) form and an expanded (runtime, secret-bearing) form.
- **Decision: `promote`.** `config.Store` becomes the primary representation and the bare `*config.Config` pointer is demoted to a detail of one variant — the value `Store.Expanded()` hands out for the duration of a single request. Adding a Store *alongside* a still-authoritative boot-time pointer is explicitly rejected: it is what makes Pitfall 1's stale-handler bug reachable, since a handler that captured the old pointer would keep serving pre-save config forever.
- **Accepted debt for this tracer only:** `webspaces.go`, `item.go` and `sources.go` keep reading a boot-time snapshot resolved once inside `Router`. That is a functionality gap (a display-name rename is not seen until restart), not an architectural gap — the fill is a mechanical parameter change, and `07-02` Task 2 does it. Nothing in those three files needs to change shape.
- **Companion invariant test (accepted, scheduled `07-02` Task 2):** an assertion that no handler constructor captures a `*config.Config` at `Router` construction time.
</assumption_delta_decision>

Wire ONE entry point — the Save as filter button — through every layer to config.toml and back into the stream. No other write surface, no other mutation kind, no modal.

Config model. Add `Filter []string` to `Webspace` in kernel/config/types.go with tags `toml:"filter,omitempty"` and `json:"filter,omitempty"`, documented in the same multi-sentence rationale style as the neighbouring `Keywords`/`Sources`/`Match` fields, citing D-16/D-17/D-18. Add `json` tags mirroring every existing `toml` tag across `Config`, `ServerConfig`, `IndexConfig`, `PluginsConfig`, `SyncConfig`, `Source`, `AgentGrant` and `Webspace`, so the config document has one stable wire shape for the browser. Add `omitempty` to `Source.BaseURL`, `Source.Token` and `Source.APIVersion` on both tags — without it a canonical rewrite of a local-path source such as Signal emits three keys the operator never typed (RESEARCH.md Pitfall 3).

Dual-parse load. In kernel/config/config.go add `LoadRaw(path string) (expanded *Config, raw *Config, fileHash string, unknownKeys []string, err error)`. It reads the file bytes once; runs today's `expandEnv` → `toml.Unmarshal` → `applyDefaults` → `expandIndexPathHome` → `expandSourceCACertPathsHome` → `Validate(missing)` path to produce `expanded`; then unmarshals the SAME unexpanded bytes into a second `Config` and applies only `applyDefaults` to it to produce `raw` — never `os.Expand`, never home-dir expansion, since both touch secret-shaped or machine-specific fields. `fileHash` is the hex-encoded `sha256.Sum256` of the raw bytes. `unknownKeys` comes from a new `UnknownKeys(raw []byte) []string` helper that decodes with `toml.NewDecoder(bytes.NewReader(raw)).DisallowUnknownFields()` into a throwaway `Config` and, on a `*toml.StrictMissingError`, returns its reported key paths sorted; any other decode error returns nil (the normal decode above already reports it). Keep the existing exported `Load` as a thin wrapper over `LoadRaw` returning just `(expanded, err)` so every current caller compiles unchanged.

Canonical writer. New kernel/config/writer.go: exported const `CanonicalHeader` holding exactly two comment lines followed by a blank line — first line `# managed by the topos UI — hand-edits are honored via Reload`, second `# see config.example.toml for full field documentation` (D-02: no per-key generated doc comments). Exported const `BackupSuffix = ".bak"`. `WriteCanonical(path string, rawCfg *Config) error` marshals `rawCfg` with `go-toml/v2`'s `Marshal` (its map-key sort is already deterministic), prepends the header, copies the current file at `path` to `path+BackupSuffix` when it exists (single rolling backup, D-04 — overwrite, never rotate), then writes via `os.CreateTemp` in the same directory, `Sync`, `Close`, `os.Rename`. Every error wraps with the package's `"config: ...: %w"` prefix. The parameter is named `rawCfg` and the doc comment states plainly that the expanded runtime config must never be passed here.

Store. New kernel/config/store.go: `Store` holds the config path, an `atomic.Pointer[Config]` for the expanded config, an `atomic.Pointer[Config]` for the raw config, and the last-known file hash guarded by a `sync.RWMutex`. `NewStore(path string) (*Store, error)` calls `LoadRaw` and seeds all three. Accessors `Expanded() *Config`, `Raw() *Config`, `Hash() string`, `Path() string`. Package-level sentinels `ErrConfigChangedOnDisk = errors.New("config: file changed on disk since it was last read")` and `ErrConfigHasUnknownKeys = errors.New("config: file contains keys topos does not recognise")`, mirroring pluginhost's sentinel shape. `Save(next *Config, baseHash string) error`: re-read the file from disk; if its hash differs from `baseHash` return `ErrConfigChangedOnDisk`; if `UnknownKeys` over those same bytes is non-empty return `ErrConfigHasUnknownKeys` wrapped with the sorted key list (a canonical rewrite would delete them, and silent deletion is the prohibition this guard closes); build the would-be expanded config by marshalling `next`, running it back through the same expand-then-unmarshal-then-defaults path `LoadRaw` uses, and calling `Validate` on the result — this is the D-09 dry run and reuses the existing validator with no second rule set; on validator failure return that error unchanged so its message reaches the UI verbatim; only then `WriteCanonical`; then re-read to recompute the hash and `Swap` both pointers plus the hash under the write lock. `Reload() error` re-runs `LoadRaw` and swaps on success; on failure it returns the error and leaves the previous pointers in place untouched.

HTTP surface.
