<objective>
Close the producer half of G-08-1's AND-gate, and restore the observability that
made the failing run undiagnosable.

Three defects live behind the kernel/plugin boundary. The link wire vocabulary
(`qr`/`paired`/`error`/`timeout`) has no way to say "the scan landed, I am
completing login" — the plugin's existing `pairingAccepted()` hook writes only
to stderr. And `execLinkSpawner` never assigns `cmd.Stderr`, so os/exec routes
the subprocess's stderr to /dev/null: every plugin diagnostic and every
whatsmeow WARN/ERROR from the failing run was destroyed, which is precisely why
the UAT report reads `errors: None`. On top of that the production spawner has
no automated coverage at all — all seven existing handler tests inject a fake.

Plan 08-05 already taught the browser to handle both progress states and to keep
polling through anything it does not recognise, so emitting them now cannot hang
the panel.

Purpose: the 5-65 second post-pair window becomes an announced state rather than
silence, and the next failure in this path leaves evidence.
Output: two non-terminal wire events, a kernel that logs what its child says,
and the first real test of the process boundary.
</objective>

**Turn the spawner into a constructor.** Replace the free function
`execLinkSpawner` with `newExecLinkSpawner(logger hclog.Logger) linkSpawner`
returning a closure with the identical signature the `linkSpawner` type already
declares. Update `routes.go`'s single call site to pass the `logger` it already

`context.WithCancel`, the same `StdoutPipe` + `bufio.Scanner` with its raised

**Capture stderr.** Add a small line-oriented `io.Writer` in this file — buffer
whatever is written, emit each complete line through the logger (a single
`Info` call carrying the line as a field, under a named sublogger so plugin
diagnostics interleave legibly with kernel logs), and retain any trailing
partial line for the next write. Bound the retained buffer: if it grows past a
fixed cap without a newline, emit what is held and reset, so a subprocess
emitting one endless line cannot grow kernel memory without limit. Skip
whitespace-only lines.

deliberately: os/exec then creates the pipe itself and runs its own copy
goroutine, and `cmd.Wait()` waits for that copy to finish. That is the
documented-correct shape — the alternative (`cmd.StderrPipe()` read
concurrently with `Wait`) is the same incorrect-usage pattern the debug session
flagged on the stdout side, and there is no reason to add a second instance of
it. After `cmd.Wait()` returns in the existing `done` goroutine, flush any
retained partial line before sending the wait error, so a diagnostic written
without a trailing newline is not silently dropped.

this process's environment. Rewrite it to state the actual behaviour and why it

`~` in its `-path` value through `os/user`, which reads `HOME`, and a host that
relocates its TLS trust store through the standard certificate environment
variables would otherwise break the linked-device websocket. Leave `cmd.Env` set
to nil; the fix here is the comment and the test that pins it, not a behaviour
change. Reference `08-UAT.md`'s G-08-1 as where the false comment was found.

a mutex if any assertion reads the buffer while the process is still running).
Do not modify `whatsapplink_test.go` in this task — its fake-spawner harness
stays exactly as it is, and this file adds the coverage that harness structurally
cannot provide.
