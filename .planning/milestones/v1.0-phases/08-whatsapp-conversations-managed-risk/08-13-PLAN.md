<objective>
Close the KERNEL half of `08-VERIFICATION.md`'s new regression (gap **G-08-5**): a plugin
subprocess that is slow to launch freezes every other source's HTTP routes kernel-wide.

`kernel/supervisor.Supervisor.SuspendInstance`'s resume closure holds `s.mu` for its entire
duration, including the `s.host.Reconcile(...)` call that relaunches the suspended instance's
subprocess. `s.mu` is the same mutex `Host()` and `Coordinator()` take, and `Fetch`,
`ProbeSources`, `Refresh` and `RefreshAll` — which back every item-open, health-probe and
manual-refresh HTTP route for **every** source — resolve through `Host()`/`Coordinator()` on
every call. The resume closure runs synchronously inside `WhatsAppLinkPollHandler`'s terminal
poll and inside `WhatsAppLinkCancelHandler`, so at the exact moment a real WhatsApp re-link
completes, every other configured source's routes are frozen for as long as the relaunch takes.
That directly contradicts phase success criterion 4's "every other source is unaffected".

Plan 08-14 removes the current 15-second contributor to that relaunch time. This plan removes
the *structural* dependency: after it, the length of a plugin launch is irrelevant to whether
every other source stays responsive. Both are needed — 08-14 alone would leave the freeze intact
for any future slow launch (go-plugin's own client `StartTimeout` default is a full minute), and
this plan alone would leave the boot-latency half of the regression open.

There is a second, latent defect this plan must close as a precondition of its own fix:
`Supervisor.Fetch` already calls `s.Host()` (taking and releasing `s.mu`) and *then* calls
`Host.Fetch` with no lock held, concurrently with a `Reconcile` that writes `h.plugins` in place.
That is a genuine data race at HEAD, merely narrow enough that no existing test provokes it. The
new gate in this plan provokes it deliberately, so `pluginhost.Host` must become internally safe.

Purpose: make "every other source is unaffected" a property the kernel structurally guarantees
and a hermetic test enforces, rather than a property that happens to hold while every plugin
launches quickly.

Output: an opt-in launch-delay fixture in `plugins/mock`, an internally-synchronised
`pluginhost.Host`, a reader-only lock on the supervisor, and the first automated gate in this
repo for criterion 4's cross-source isolation clause.

Scope note — Playwright: this plan changes kernel-internal locking, a fixture-only plugin env
var, and test/doc files. It changes no component, no route, no response shape and no user-visible
copy, so the project's standing "any UI-touching phase extends the Playwright e2e suite" rule
(`.claude/CLAUDE.md`, `docs/testing.md`) adds no new spec here. The existing suite must still
pass unchanged; plan 08-15 runs it as this wave's gate. This decision is recorded rather than
assumed.

Scope note — COVERAGE.md: this wave integrates no new external API or SDK surface. The phase's
existing `COVERAGE.md` matrix is unchanged and is deliberately left as-is.
</objective>
