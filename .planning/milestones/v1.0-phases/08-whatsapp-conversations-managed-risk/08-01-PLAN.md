<objective>
Stand up `plugins/whatsapp` as a working, end-to-end WhatsApp source: link once from the terminal, hold a live linked-device connection, capture every inbound message into the plugin's own local store, and surface matching group chats as conversation-day digests that render through the Phase 4 chat transcript.

Purpose: prove the whole architecture — a plugin that holds a persistent connection, owns its own message store, and answers Match/Fetch purely from local data — on one real path before any of the in-app pairing UX or degradation taxonomy is built on top of it.

Output: a new pure-Go `go.work` member producing `topos-plugin-whatsapp`, a CLI link mode, and a WhatsApp digest row in a real webspace stream.

**Phase goal (verbatim from ROADMAP.md — not restated as a user story; see the planner note in this phase's planning output):** "User's WhatsApp groups for a topic appear in the webspace stream via a linked-device session, and everything else keeps working when that session breaks"
</objective>

<assumption_delta_decision>
**Signal:** `pluralization` — the phase scope introduces a second matchable chat kind (D-05 widens SRC-03's groups-only wording to groups AND 1:1 chats).

**Primary noun:** `chat`, identified by its WhatsApp JID.

**Decision:** `promote`. The message store's primary key, the digest grouping key, the `source_id` encoding, and the matching pipeline are all keyed on `chat_jid` from the outset, with "group" demoted to one variant of a chat (`is_group`) alongside 1:1. Keying any of these on "group" would force a parallel identity path for 1:1 chats in Plan 08-02 and a migration of already-captured rows.

**Suggested contract test (advisory):** a test asserting `sourceIDForDigest`/`decodeSourceID` round-trip identically for a group JID and a 1:1 JID, so no code path can special-case one kind's identity.
</assumption_delta_decision>

No 1:1 matching, no health taxonomy, no in-app QR — those are Plans 08-02 and 08-03. Every stub below is one that can later be filled without an architectural change.

    **Module and build.** `plugins/whatsapp/go.mod` declares module `github.com/davison/topos/plugins/whatsapp`, `go 1.25.0`, and a plain `require` (no `replace` — whatsmeow's upstream has no missing-feature gap, unlike Signal's SQLCipher fork) pinning `go.mau.fi/whatsmeow` to the exact pseudo-version Task 1's checkpoint returned, plus `modernc.org/sqlite` v1.54.0 and `github.com/mdp/qrterminal/v3` v3.2.1. Add `./plugins/whatsapp` to `go.work`. Add `go build -o bin/plugins/topos-plugin-whatsapp ./plugins/whatsapp` to the `plugins:` target (before the `$(MAKE) signal` line — this plugin is CGO-free and must not sit behind the cgo target) and add a `cd plugins/whatsapp && CGO_ENABLED=0 go build ./... && go test ./...` line to `test-portable:`, updating both targets' leading comments to name the new plugin.

    **`main.go`.** Copy `plugins/signal/main.go`'s shape verbatim: decode `WEBSPACES_SOURCE_CONFIG` into a `sourceConfig` carrying only `Path`, fatal on empty, `expandHome` the path, then `goplugin.Serve` with `sdk.Handshake`, the `"source"` plugin key wrapping `&sdk.SourcePluginGRPCPlugin{Impl: impl}`, and `sdk.GRPCServer`. Two divergences: (a) no build tag and no cgo — this binary builds under `CGO_ENABLED=0`; (b) before `goplugin.Serve`, branch on a `-link` flag: when present, run `runLinkCLI` (link.go) and exit instead of serving. Keep the `cfg.Path == ""` fatal guard — the frontend's required-field table derives from exactly this guard.

    **`storelock.go`.** `acquireStoreLock(dir string) (*storeLock, error)` creates/opens `<dir>/whatsapp.lock` and takes an exclusive non-blocking advisory lock via `syscall.Flock` with `LOCK_EX|LOCK_NB`, returning the sentinel `ErrStoreInUse` when the lock is already held. `(*storeLock).Release()` unlocks and closes. This is the CONTEXT hard requirement's mechanism: the link-mode subprocess and the pluginhost-launched instance must never both hold the same whatsmeow sqlstore open. Both `runLinkCLI` and `startBackgroundClient` acquire it before touching either database and hold it for their process lifetime.

    **`connect.go`.** `startBackgroundClient(ctx)` acquires the store lock, opens `sqlstore.New` against `<path>/whatsmeow.db` using the pure-Go `modernc.org/sqlite` driver registration, calls `container.GetFirstDevice(ctx)`, constructs `whatsmeow.NewClient(device, waLog)`, registers `p.handleEvent` via `AddEventHandler`, and — only when `client.Store.ID` is non-nil — calls `client.Connect()` and holds it for the whole process lifetime. When `client.Store.ID` is nil the plugin is not linked: record that state and return without connecting. Logging goes through the plugin's own `waLog` at a level that never emits message bodies or key material.

    **`messagestore.go`.** `openMessageStore(path)` opens `<path>/messages.db` — a SECOND, separate `modernc.org/sqlite` file the plugin fully owns, never a table inside whatsmeow's `sqlstore` (whatsmeow migrates that schema itself). Enable WAL journal mode and a busy timeout so the background writer and the Match/Fetch readers share one `*sql.DB` without lock contention. Schema, created idempotently at open: a `chats` table keyed on `chat_jid TEXT PRIMARY KEY` with `is_group INTEGER`, `name TEXT` (the group's own subject for a group; left empty here — the 1:1 contact-name column is Plan 08-02's work), `updated_at_unix_ms INTEGER`; and a `messages` table keyed on `message_id TEXT PRIMARY KEY` with `chat_jid TEXT`, `sender_jid TEXT`, `sender_name TEXT`, `is_from_me INTEGER`, `sent_at_unix_ms INTEGER`, `body TEXT`, `is_deleted INTEGER`, `is_edited INTEGER`, plus an index on `(chat_jid, sent_at_unix_ms)`. `Append` uses `INSERT ... ON CONFLICT(message_id) DO UPDATE` so a re-delivered event never duplicates a row. Reads are day-scoped and ordered by `(sent_at_unix_ms, message_id)` so ordering is stable when timestamps tie. Never store attachment bytes — the hybrid data model keeps content in the source; an attachment is recorded as a placeholder marker only.

    **`eventhandler.go`.** `handleEvent(evt any)` switches on whatsmeow's event types: `*events.Message` appends to the message store (resolving the chat row's `is_group` from the JID's server component); group-metadata events refresh the chat row's `name`; `*events.LoggedOut` and `*events.StreamReplaced` are recognised here and record a not-healthy state — Plan 08-02 gives them their distinct named taxonomy, so for now a single non-healthy flag is enough. `*events.HistorySync` payloads are appended through the same `Append` path so first-link backfill lands in the store identically to live messages. This loop runs continuously, fully decoupled from when the kernel next calls Match.

    **`plugin.go`.** Constants `sourceType = "whatsapp"`, `displayName = "WhatsApp"`, `contractVersion = "topos.v2"` (match Signal exactly), and `var matchVocabulary = []string{"groups"}` — the second `contacts` field is Plan 08-02's D-05 work, deliberately absent here. `Describe` mirrors Signal's verbatim. `Match` reads `req.GetMatchFields()["groups"].GetValues()`; on zero values it returns an empty successful `MatchResponse`; when the plugin is NOT linked-and-healthy it returns `nil, status.Errorf(codes.Unavailable, ...)` — never an empty success, because `kernel/correlate` wipes a source's rows on empty success and preserves them on error. It then reads matching chats from the local store, builds digests, and maps each to an Item via a `toItem` mirroring Signal's: stable `source_id`, plugin-composed title, tail snippet, `LINK_FIDELITY_CONVERSATION_ONLY`, non-empty `deep_link`, and `CONTENT_SHAPE_CHAT_TRANSCRIPT`. `Fetch` decodes `(chat_jid, day)` from `source_id`, re-reads that day from the local store, calls `renderTranscript`, and returns the fragment with `transcriptMimeType` and `CONTENT_SHAPE_CHAT_TRANSCRIPT`; the thumbnail variant returns Signal's no-thumbnail shape. `Health` reports reachable when linked and connected, and reachable false with a `last_error` naming the cause otherwise. Only matched chats are ever converted to Items — a captured message from a chat matching nothing must never reach the kernel.

    **`digest.go`, `match.go`, `render.go`.** Port `plugins/signal/digest.go` and `plugins/signal/render.go` near-verbatim, renaming the conversation identity to `chat_jid`/`ChatJID` throughout and keeping `previewRuneCap`, `tailMessageCount`, `runGapThreshold`, `ownSenderLabel`, the base64 `source_id` round trip, `localDay`/`localDayKey` on `time.Local`, and — critically — `escapeText`'s escape-every-interpolated-field discipline and the exact closed class-token set (`run`, `own`, `other`, `sender-name`, `bubble`, `tombstone`, `quote`, `timestamp`, `edited-suffix`, `attachment`, `reaction`, `body`). Emitting any token outside that set makes the kernel's sanitizer drop the whole class attribute. `match.go` ports `matchesAnyKeyword` (exact, case-insensitive via `strings.EqualFold`, no substring or prefix matching) and an `eligibleChats` that, in this plan, derives candidate names from the group subject only.

    **`deeplink.go`.** `conversationDeepLink` returns the bare `whatsapp://` scheme — the direct analogue of Signal's bare `sgnl://` fallback, which raises the desktop app without navigating to a particular conversation, an honestly conversation-only fidelity and a non-empty value that satisfies PLUG-03's sync-time validation. Add a comment recording that the scheme is NOT yet hands-on verified and that Task 3's spike closes `08-RESEARCH.md` Open Question 3.
