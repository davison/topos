<objective>
Close the presentation half of `08-UAT.md` gap G-08-3. The user's report —
"Couldn't load this webspace / The topos service didn't respond — check that it's
running, then retry" — was rendered from a **200 OK** response. The kernel
answered normally; the quoted "kernel error" was the `sync.error` field of that
successful response.

Two defects compose into it. First, `aggregateSyncStatus` folds *any* configured
source's latest errored run into the single global `sync` object embedded in
*every* webspace's stream response, regardless of whether that source
participates in the requested webspace. Second, the SPA's `streamVariant` maps
`sync.status === 'error' && items.length === 0` to a full-page `StreamError`
whose fixed Phase-1 copy asserts the service did not respond. So a zero-item
webspace renders as a total outage because one source — participating or not —
has a failing latest sync. Phase 8's own degradation guarantee ("de-link, ban or
session expiry surfaces as an explicit plugin-health error in the UI while every
other source is unaffected") is structurally violated for every zero-item
webspace in the product, not just for WhatsApp.

This is the same family as G-07-1, whose client half `07-15` closed by giving a
distinct cause its own distinct, honest state (`StreamMissing`) instead of
routing it through the outage copy. This plan applies the identical shape to the
one remaining cause still mis-routed there, and narrows the kernel-side aggregate
so a webspace's status only ever reflects sources that participate in it.

Purpose: one source failing must degrade that source, not the whole webspace —
and the copy must never send a user to restart a service that is running.
Output: a new neutral degraded stream state, an outage state with exactly one
documented cause, a participation-scoped sync aggregate across all four of its
callers, and browser plus structural armor so neither half can silently return.
</objective>

## Flagged assumptions and probe bookkeeping

- **Edge probe.** Applicable edges for SRC-03 on this seam: adjacency (a sync
  failure beside items that did load), empty (an index-only webspace with no
  configured participants), ordering (the four aggregate callers staying
  consistent with each other), encoding (which instance ids a webspace's error
  string may name). Idempotency and concurrency are not applicable — this pass is
  a pure read-path projection with no state to re-enter. 4 surfaced = 4 authored,
  0 dropped.
- **Prohibition recall.** Four kept (all integrity), authored descriptor-less so
  each disposes flagged-unverified.
- **Hermetic scripting rather than a real failing sync.** The e2e cases script the
  stream response instead of provoking a genuine failed `Match`. The harness's
  plugin directory is a closed, cgo-free set (`docs/testing.md`) containing no
  plugin that can be made to fail on demand, and the behaviour under test is
  entirely the SPA's presentation of a response it was handed. The kernel half's
  own correctness is proven by Go tests against the real handlers in Task 2, not
  by the browser. Recorded so a later reader does not mistake the scripting for a
  shortcut around an available real path.
- **`format.ts` deliberately unmodified** despite being named in the gap's
  artifact list. `streamVariant`'s decision — a failed sync with zero items beats
  every empty state — is correct and is the T-02-16 guarantee; the defect was
  what `StreamList` renders from that decision. Changing the predicate would
  reintroduce the masking defect Phase 1 fixed. Recorded here because a reader
  auditing the gap's artifact list against the diff will otherwise see an
  apparent omission.
- **No new API fields.** A per-source sync array on the stream response would
  make the client's job easier and is deliberately rejected (prohibition 4):
  `GET /api/sources` already carries per-source `last_status`/`last_error`, the
  SPA already fetches it independently of the stream, and the chips already
  render it.
- **Assumption-Delta Checkpoint.** The `assumption-delta scan` query is not
  available in this GSD install; per that checkpoint's own instruction the result
  is treated as `detected: false` and it does not block.
- **API Coverage Checkpoint.** `COVERAGE.md` exists for this phase and is
  complete; this plan adds no external-API capability, so the matrix stands
  unchanged.
</assumptions>
