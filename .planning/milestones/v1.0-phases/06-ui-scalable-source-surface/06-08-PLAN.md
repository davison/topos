<objective>
Close gap G-06-3b: the merged source chip (D-01's single per-instance affordance) reads as three
separate cosmetic defects rather than one polished pill control.

Three co-located causes, all in `SourceChip.svelte`, all shipped in 06-02 and none introduced by
06-06 — per `.planning/debug/chip-pill-polish.md`:

1. **Dead oversized padding.** The chip's height is dictated by its 44px refresh button plus the
   wrapper's own vertical padding, while the filter `onclick` lives only on an inner label button
   about 20px tall. The bands above and below the label are visually chip but click-dead, and the
   chip stands roughly 10px taller than the `h-11` overflow trigger sitting next to it in the same
   row. D-01 says clicking the chip body toggles the filter; today most of the chip body does not.
2. **Square hover highlight.** The refresh `Button`'s class override sets a size but no radius, so
   `buttonVariants`' base radius shapes the ghost hover fill as a rounded square inside a
   `rounded-full` pill.
3. **Sticky refresh icon.** The reveal is keyed on the wrapper's `:focus-within`, which also matches
   the persistent focus a mouse click leaves on a button — so after a refresh click the icon stays
   pinned visible until the user clicks elsewhere on the page. D-03 asks for a hover **and keyboard
   focus** reveal; `:focus-within` cannot tell keyboard focus from click focus.

Causes 1 and 3 are faithful implementations of decisions written into `06-UI-SPEC.md` (its 44px
touch-target floor for the chip's refresh control, and its literal `:focus-within` reveal). Fixing
only the code leaves both contradictions live to reintroduce the defects on the next spec re-read —
exactly the doc-code drift pattern G-06-3 already demonstrated once in this phase.

Purpose: the chip is the phase's headline surface (UI-07). A control that is 60% click-dead and
paints a square highlight inside an oval undercuts the "one merged affordance" claim even though
every behaviour behind it is correct.

Output: a 44px pill matching the overflow trigger, whose filter button owns the full chip surface;
a circular refresh hover surface; a focus-visible-scoped reveal that keeps the keyboard path and
drops the mouse-click pin; the spec reconciled on both points; and a dedicated recurrence guard.

**No tracer task.** Surgical class-level fix to one shipped component whose wiring, ARIA and
behaviour are already correct and already guarded — nothing architectural is being proven here.
</objective>

**Defect 1 — the chip's height and its dead bands.** Restructure so the pill's height is declared

- The wrapper `div`'s base class string becomes `group flex h-11 shrink-0 items-center rounded-full border border-border bg-card pr-1`. conflict group against the base. Confirm that resolution actually holds in the rendered class
string rather than assuming it. The 16px icon inside is already explicitly sized and does not
change. The `selected` re-toning branch and the `source.syncing` force-visible branch are 06-06's

focus-*within* state must be replaced with one keyed on keyboard focus specifically:
`group-has-[:focus-visible]:opacity-100`. This keeps the reveal chip-scoped (tabbing to the chip
body still reveals the refresh control, which is what D-03's "and keyboard focus" clause and the
spec's Tab-order note both require) while a pointer click — which sets focus but not
`:focus-visible` on a button — no longer pins the icon after the pointer leaves. Keep
`group-hover:opacity-100` and `transition-opacity` exactly as they are.

silently fails to generate would remove the keyboard reveal entirely, a worse regression than the
