<objective>
Land UI-09: after an in-webspace search, matched terms are highlighted in the detail pane's rendered content across every content variant.

This plan carries the phase's **tracer slice** — the only work in Phase 6 that crosses the Go kernel boundary. The rendition iframe is served under `Content-Security-Policy: ...; sandbox` with no same-origin token, which forces an opaque origin the SPA cannot script into. Highlighting inside email HTML, SilverBullet markdown and Signal chat transcripts is therefore *only* possible kernel-side, inserted after `bluemonday.SanitizeBytes` and before the document-wrap step. Task 1 proves that whole path end-to-end on one content shape before anything else is built on it.

Purpose: close success criterion 3 without touching the sanitizer contract or the sandbox CSP.
Output: a kernel tree-walk highlighter, a client-side text highlighter, the `?hl=` rendition parameter, and regression tests proving the sanitizer boundary is intact.
</objective>

**Kernel — `kernel/httpapi/rendition.go`:**

Add `highlightTerms(raw string) []string`, the single shared term-derivation rule. It trims, splits on whitespace (the `strings.Fields` behaviour `ftsQuery` uses), lowercases, de-duplicates, drops terms shorter than 2 runes, caps the result at the first 8 terms, and returns nil for an empty or all-dropped input. The 2-rune floor and the 8-term cap are the bounded-work controls for threat T-06-03; the client half in Task 2 implements the identical rule so the two halves never disagree.

Add `highlightTextNodes(roots []*html.Node, terms []string)`. Mutate the parsed tree, never the byte slice:
- Parse with `html.ParseFragment` against a `body` context node built from `golang.org/x/net/html/atom`, so the fragment round-trips as a fragment and does not gain a nested `html`/`head`/`body` wrapper inside the wrap step's own `<body>`.
- Walk the tree. Return without descending when the node is an element named `script` or `style`.
- On a `TextNode`, scan its `Data` with a case-insensitive literal index scan. At each scan position try the terms in descending length order and take the first hit, so a longer term always wins over a shorter overlapping one and no nested marks are ever produced. This fixes the tie-break deterministically.
- Replace a matching text node with an ordered sequence of siblings: plain `TextNode`s for the unmatched spans, and for each match an `ElementNode` named `mark` with `DataAtom` set to the mark atom, carrying a single `TextNode` child holding the matched source substring verbatim (preserving the document's original casing) and **no attributes and no class**. A bare, attribute-free element needs no sanitizer-policy entry, which is why the chat-transcript class allowlist is unaffected.
- Snapshot each node's children before iterating and continue the walk past the replaced sequence, so newly inserted mark elements are never re-walked. Re-walking inserted nodes is the infinite-loop failure mode here.
- Never perform byte-level or pattern substitution over the sanitized HTML — attribute values, tag bytes and multi-byte runes must all be untouchable, which tree mutation gives for free.

Change `sanitizeAndWrapRendition` to `sanitizeAndWrapRendition(shape toposv1.ContentShape, fragment []byte, terms []string) ([]byte, error)`. The new step sits strictly between `sanitized := policy.SanitizeBytes(fragment)` and the buffer write: parse `sanitized`, highlight, render back with `html.Render` into a buffer, and write those bytes where `sanitized` was written before. When `terms` is empty, skip the parse/render round trip entirely and write `sanitized` unchanged — that keeps the no-search path byte-identical to today. The highlighted output is never fed back through `policy.SanitizeBytes`; the existing doc comment on this function already states that rule and must be extended, not contradicted, to describe the new step.

Add the highlight style to `renditionBaseStyle` as a bare element rule: background `#fbbf24`, colour `#020617`, `border-radius: 2px`, `padding: 0 1px`. Both hex values are already-declared theme tokens (`--warning` and `--background` in `web/src/app.css`) — introduce no new colour.

The selector is more specific than the neutraliser, so it wins among priority-marked declarations without depending on source order. The markdown and chat deltas carry no neutraliser and need no restoring rule.
