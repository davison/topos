Signal Desktop keeps the authoritative message record in a JSON blob column; the indexed
columns beside it are a partial projection. Everything richer than plain body text —
attachments, reactions, quotes, edit history, the deleted-for-everyone marker — lives only
in that blob. Introduce a single parsed record type so the digest and the transcript both
read one structure rather than each re-parsing the blob.

**message.go.** Define a `messageRecord` type carrying: the message id, the conversation
id, the sent-at time, the sender's identifier, the display body, whether the message was
deleted for everyone, whether it has been edited, the attachments (each with a filename
that may be empty and a content type), the reactions (each an emoji plus a reactor
identifier), and the quoted excerpt text if the message is a reply. Write `parseMessage`
to decode the blob into it, using the exact JSON field names recorded in 04-01's SUMMARY.
Rules that matter:

  - A message deleted for everyone must present as deleted with no body, regardless of
    what remains in the body column — some Signal versions erase the blob and leave the
    column, some the reverse. Check both signals and treat either as deleted.
  - A message with edit history presents its LATEST revision as the body and sets the
    edited flag. Never present an earlier revision, and never build a diff.
  - Parsing is defensive: an unparseable or absent blob yields a record with an empty
    body and no richness, never an error. One malformed row must not fail an entire day's
    digest, mirroring the per-item rejection discipline the repo already uses at sync
    time. Count malformed rows and emit one count-only log line per Match, never content.
  - Bound the blob read the way `plugins/proton/body.go` bounds MIME parts, so a crafted
    or corrupt row cannot exhaust memory.

Resolve a sender identifier to a display name using the conversations already loaded for
this Match — the same name fields D-06 permits, so the transcript never surfaces a
contact's self-chosen profile name either. Fall back to the identifier itself when no
name is known, never to an empty string.

**digest.go.** Make the tail snippet richness-aware, using the exact copy from the UI
contract. A tail line for a message with no body but with an attachment renders as the
paperclip glyph, a space, and the filename — or the paperclip glyph and the word

  <action>
Build the transcript as a self-contained HTML document the plugin owns end to end, exactly
as `plugins/proton` and `plugins/silverbullet` already own theirs. The producing plugin
decides readability (the Phase 3 precedent); the detail pane is shared and must not learn
anything Signal-specific.

**render.go — sanitize policy.** Build a package-level `signalTranscriptSanitizePolicy`
once at init from `bluemonday.UGCPolicy()`, following `plugins/proton/body.go`'s
construction pattern but not reusing its policy variable, because the content shape
differs. Message text is untrusted user input from a third party, so widen the base policy
as little as possible: no `style` attribute on message content at all. All presentation
comes from the document's own stylesheet, which is applied after sanitization. Sanitize
each message's body text on its own, then assemble the sanitized fragments into the
transcript structure — never sanitize the assembled document, which would let a crafted
body break out of its bubble before the sanitizer sees the boundary.

**render.go — the transcript structure.** Render the day's messages, in chronological
order, grouped into runs. A run breaks on a sender change or on a gap greater than five
minutes. Within a run the sender name is rendered once at the top and the timestamp once
at the end of the run's last bubble. For the user's own messages no sender name is
rendered at all: ownership is signalled by alignment and background tier only. Only the
digest's own day is rendered — no cross-day context is pulled in — and no day-header
divider is drawn, because the pane header already shows the date and a transcript spans
one day by construction.

Per message, in order: the quoted excerpt if the message is a reply, then the body (or the
tombstone copy if the message was deleted for everyone, in place of the body, keeping the
sender and timestamp chrome), then the attachment placeholder chips, then the reaction
line if any. The exact copy comes from the UI contract: a deleted message reads
`This message was deleted`; an edited message's body is followed by the timestamp then a
single space then `(edited)`, never on its own line; an attachment chip is the paperclip
glyph, a space, and the filename, or the paperclip glyph and the word `Attachment` when
none is known; a reaction line is the emoji, a space, and the reactor names comma-joined.

**render.go — the stylesheet.** Copy `plugins/proton/body.go`'s `themeStyle` discipline:
one fixed, self-contained constant with no external fetch, no import rule and no URL
reference, applied strictly after sanitization. Base document typography is the existing
rendered-content stack this repo already uses for `proton` and `silverbullet` — the same
system font stack, 15px, line height 1.6 — not the SPA's Inter/16px chrome. Keep the rule
that hides images, with its existing rationale comment: the rendition is served under a
policy permitting no subresource, so an image could only ever render broken. On top of
that base, add exactly the transcript rules the UI contract specifies:

  - Other-participant bubble background `#1e293b`, left-aligned. Own-message bubble
    background `#0f172a`, right-aligned. Both are existing secondary-tier tokens; add no
    new colour value.
  - Bubble border radius 12px, padding 8px vertical and 16px horizontal, max width 75% of
    the transcript column, 4px gap between bubbles within a run, 16px gap between runs.
  - Sender name 14px weight 600 colour `#f1f5f9`. Timestamp 14px weight 400 colour
    `#94a3b8`. Message body 15px weight 400 line height 1.6. The edited suffix 14px weight
    400 colour `#94a3b8`. Quoted excerpt 14px weight 400 italic colour `#94a3b8`, one line
    with ellipsis overflow and no wrapping. Deleted tombstone 15px line height 1.6 italic
    colour `#94a3b8`. Attachment chip 14px weight 400 colour `#f1f5f9` inside a pill.
    Reaction line 14px weight 400 colour `#94a3b8`.
  - The accent `#60a5fa` is reserved for inline links inside message text only. It is
    explicitly not used for a bubble background, a sender name, a timestamp, or any
    per-participant differentiation — the accent budget is protected exactly as Phase 3
    protected it for search.
  - A long message wraps within its bubble's max width. Nothing in the transcript
    truncates or ellipsis-clamps message text; only the compact stream-row preview does.

**render.go — the wrap.** Copy `WrapDocument`'s shape verbatim: doctype, head with only a
charset meta tag and the stylesheet, then the already-sanitized fragment as body content,
unchanged. Never re-run the wrapped output through the policy, and never wrap before
sanitizing.

**plugin.go — Fetch.** Replace 04-01's named-unavailable stub for FULL and PREVIEW with
the real path, mirroring `plugins/proton/plugin.go`'s `fetchFull` discipline: decode the
source_id back into its conversation id and day, re-open the database read-only through
the same `openReadOnly` path (never a handle cached from Match, and never a cached copy of
the content itself — content is fetched live on open, per the hybrid data model), run the
schema guard, re-read that conversation's messages for that day, parse them into records,
render, wrap, and return with `MimeType` `text/html`, `SizeBytes` set and `Available` true.
An unknown source_id returns a not-found error naming it. Keep THUMBNAIL returning

variant returning an invalid-argument error. Read `DetailPane.svelte` to confirm the
returned shape lands in its existing `html` body-variant branch, and record that

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Signal message body → rendered transcript document | Arbitrary third-party-authored text, including anything a sender chose to type, crosses into HTML the user's browser renders. |
| Signal message body → `sgnl://` deep link | Conversation-derived values cross into a URI the desktop's scheme handler executes. |
| plugin `Fetch` response → kernel `/content` route → iframe | Source-controlled bytes cross into the browser under the kernel's fixed policy. |
