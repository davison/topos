# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Everything not explicitly called out below is inherited verbatim from `01-UI-SPEC.md`/`02-UI-SPEC.md`/`03-UI-SPEC.md`** — this document does not re-derive the design system, spacing scale, base typography, or base palette. Per `04-CONTEXT.md`, this phase "introduces the chat-thread renderer that Phase 5 reuses — extends the existing UI contract rather than defining a new one," and `04-RESEARCH.md`'s Architecture confirms this needs **zero proto change and zero new `DetailPane.svelte` branch**: the thread view is rendered by the Signal plugin itself as sanitized HTML (mirroring `plugins/proton/body.go`/`plugins/silverbullet/render.go`'s existing `WrapDocument` pattern) and served through the pane's already-existing `text/html` iframe branch. Consequently **this UI-SPEC's real new content is prescriptive guidance for that plugin-authored HTML document** (the chat-transcript stylesheet the executor writes in Go, e.g. `plugins/signal/render.go`), not new Svelte components — the SPA-side surface area is a new `source_type` value flowing through already-generic components (`StreamRow`, `OpenInSource`, `SourceHealthChip`), same shape as Phase 3's email addition.

**No new agent-facing UI surface.** SRC-02 has no AGENT-01/02 dimension — same "no UI surface" note Phases 2/3 made for their own non-agent requirements.

**No destructive UI actions.** Read-only source, no write paths — no destructive-confirmation copy needed this phase.

## Spacing Scale

**Unchanged from Phase 1/2/3 for the SPA chrome.** Reuse verbatim — no new spacing exceptions in `StreamRow`/`DetailPane`/`OpenInSource`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tag pill inline padding, gap between bubbles in the same transcript run |
| sm | 8px | Compact element spacing, bubble internal padding (top/bottom) |
| md | 16px | Default element spacing, bubble internal padding (left/right), gap between transcript runs (different sender or >5 min gap) |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exception (new, scoped to the plugin-rendered transcript document only):** the transcript document's own prose spacing (quote-strip padding, reaction-line margins) follows the existing rendered-content convention already set by `plugins/proton/body.go`/`plugins/silverbullet/render.go` (em-based, e.g. `0.75em`/`0.25em` margins) rather than the 4px grid — that convention is a separately-styled HTML document, not SPA chrome, and this phase does not change or tighten that existing precedent. Bubble-level structural spacing (padding, inter-bubble/inter-run gaps) DOES use the 4px-multiple tokens above (4/8/16), since bubble layout benefits from grid precision the prose paragraphs inside proton/silverbullet's renditions don't need.

Phase 1's 44px minimum touch-target floor still applies to nothing new this phase (no new icon-only controls).

## Typography

**Unchanged from Phase 1/2/3 for the SPA chrome — still exactly 2 weights, 4 sizes project-wide.** No new sizes or weights introduced in `StreamRow`/`DetailPane` itself.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**New usage of the existing 600 weight (not a third weight), scoped to the digest tail-snippet (SPA-rendered, StreamRow):** each sender-name prefix in the tail snippet (D-02: "last 2-3 messages... each prefixed with sender name") renders in the already-declared semibold (600), the message text itself in the already-declared Body (16px/400/1.5) — the identical pattern Phase 3 established for search-match emphasis (600 weight, new context, not a new weight).

**Plugin-rendered transcript document (separate document, not SPA chrome — new this phase):** the thread view inherits the exact base font treatment already established verbatim by `plugins/proton/body.go`/`plugins/silverbullet/render.go`'s `themeStyle` (`font-size: 15px; line-height: 1.6;`), not the SPA's 16px/1.5 Body role — this is a deliberate continuation of existing precedent (both prior HTML-rendering plugins already made this exact choice for readability inside the iframe document), not a new typography decision requiring separate reasoning. Within that document:
- **Sender name** (shown once per message run, omitted for the user's own messages — see Color below): 14px, weight 600, color `#f1f5f9`.
- **Timestamp** (trailing, end of each run's last bubble): 14px, weight 400, color `#94a3b8` (muted).
- **Message body text:** 15px/400/1.6 (the inherited base, above).
- **"(edited)" suffix:** 14px, weight 400, color `#94a3b8`, appended directly after the timestamp with a single space, never its own line.
- **Quoted-reply excerpt** (inside a bubble, above the replied-to message's own text): 14px, weight 400, italic, color `#94a3b8`, single line with ellipsis overflow — never wraps to a second line.
- **Deleted-message tombstone text:** 15px/400/1.6 (same as body), italic, color `#94a3b8` — replaces the message body text entirely, sender/timestamp chrome unchanged.
- **Attachment placeholder chip:** 14px, weight 400, color `#f1f5f9`, inside a pill (see Color below) — never attempts to decrypt/render the actual attachment file this phase (explicit scope limit, consistent with the project's minimal-plaintext-exposure stance; D-03 already limits FTS to the tail snippet for the same reason).
- **Reaction line** (below a bubble, when present): 14px, weight 400, color `#94a3b8` — format `"{emoji} {reactor name(s)}"`, multiple reactors comma-joined.

## Color

**Unchanged from Phase 1/2/3 for the SPA chrome — no new tokens.** `#020617`/`#0f172a`/`#1e293b` dominant/secondary/border, `#60a5fa` accent, `#f87171` destructive, `#4ade80` success, `#fbbf24` warning — all live today in `web/src/app.css`. Zero new CSS variables added.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (slate-950) — unchanged | Page background, stream pane |
| Secondary (30%) | `#0f172a` (slate-900), border `#1e293b` — unchanged | Cards, header, detail pane, **and (new, transcript document) other-participant bubble background = `#1e293b`; own-message bubble background = `#0f172a`** — both are the existing secondary-tier tokens, no new hex value |
| Accent (10%) | `#60a5fa` (blue-400) — unchanged | "Open in Signal" CTA, inline links (unchanged reservation list); **explicitly NOT used to color-code own-vs-other bubbles or per-participant identity** — ownership is signaled by alignment (own = right, others = left) and background tier only, never by the accent color, to keep the accent budget uncontaminated exactly as Phase 3 protected it for search |
| Destructive | `#f87171` (red-400) — unchanged | Destructive actions (none new); unreachable-source health dot (Signal's keyring-failure/missing-DB/unknown-schema-version failures all render through this same dot — see UI Considerations E4) |

Accent reserved for: exactly the same list as Phase 2/3 — "Open in source" CTA, inline text links, focus-visible rings, the selected stream-row indicator, and the active source-filter chip. **Explicitly not used for:** bubble backgrounds, sender-name text, timestamps, or any per-participant differentiation in the transcript document — all of those use neutral/muted tokens only.

| populated | E2 chat-thread transcript | ✅ covered | **The phase's core new visual pattern.** Bubble layout, not a flat transcript list: own messages right-aligned, background `#0f172a`, no sender-name label (ownership signaled by alignment/background alone, never the accent color — see Color); other-participant messages left-aligned, background `#1e293b`, sender name shown once per contiguous run (14px/600/`#f1f5f9`).
