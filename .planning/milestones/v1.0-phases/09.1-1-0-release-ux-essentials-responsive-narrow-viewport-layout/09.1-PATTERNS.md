## Pattern Assignments

### `web/src/routes/w/[webspace]/+page.svelte` — pane composition (controller/component, request-response)

**Analog:** itself, current `main` block (verified read, lines ~799-895 above).

**Current structure to extend** (imports already present, lines 1-3):
```svelte
import { page } from '$app/state';
import { goto } from '$app/navigation';
```
Add `pushState` from `$app/navigation` alongside the existing `goto` import — same module, no new dependency.

**Current stream-pane wrapper** (load-bearing comment documents the sizing invariant — extend
the comment, do not delete it):
```svelte
<div class="relative min-h-0 min-w-0 {selectedItem ? 'w-[480px] shrink-0' : 'flex-1'}">
```
Becomes (per D-02): full-width below `md`, proportional in the 768-1024 band, unchanged fixed
480px at `lg`+:
```svelte
<div class="relative min-h-0 min-w-0 {selectedItem
  ? 'w-full md:w-[clamp(240px,30vw,400px)] lg:w-[480px] shrink-0'
  : 'flex-1'}">
```
(Same substitution applies to the inner scroll `div` that duplicates the same conditional class
string — both must move together, exactly as they do today.)

**Current detail-pane wrapper**:
```svelte
{#if selectedItem}
  <div class="flex min-w-0 flex-1 flex-col overflow-hidden border-l border-border pl-8">
    <DetailPane ... />
  </div>
{/if}
```
Becomes a takeover below `md` (D-01/D-04): `fixed inset-0 z-* bg-background` full-viewport
overlay with no `border-l`/`pl-8` (those are the side-by-side desktop treatment only, gated to
`md:` and up).

**Takeover history wiring — analog is the file's own existing `?sources=` filter pattern**
(verified quote, `web/src/routes/w/[webspace]/+page.svelte:651-654`):
```typescript
// replaceState (not a new history entry) so toggling a chip
const url = new URL(page.url);
...
goto(`${url.pathname}${url.search}`, { replaceState: true, keepFocus: true, noScroll: true });
```
This is the file's existing precedent for "browser navigation API driven by in-app state" —
the new takeover code follows the same shape but calls `pushState` (new entry, not replace) per
D-03:
```typescript
import { pushState } from '$app/navigation';

function onselect(id: string) {
  selectedId = id;
  if (window.matchMedia('(max-width: 767px)').matches) {
    pushState('', { itemOpen: true });
  }
}

function closeTakeover() {
  history.back(); // same popstate path as the phone back button/gesture
}
```
Source for the shallow-routing shape: https://svelte.dev/docs/kit/shallow-routing (cited in
RESEARCH.md, Pattern 2) — the `page`/`pushState` imports are consistent with this route's
existing `$app/state`/`$app/navigation` usage, no new import source.

**Error handling / edge case:** none new — this is pure client-side layout state, no
try/catch pattern applies. The one behavioral edge case to verify explicitly (RESEARCH.md
Pattern 2): a `?sources=` chip toggle (`replaceState`) while the takeover's `pushState` entry is
active must not clobber it — verify via manual toggle-then-back in the e2e spec, no existing
code precedent to copy for this interaction.

### `web/src/lib/components/StreamRow.svelte` — compact card variant (component, request-response)

**Analog:** itself (verified full read above).

**Imports** (lines 1-13) — unchanged, no new imports needed; compact variant is pure Tailwind
class additions on existing elements.

**Core pattern — title** (lines 95-99), extend with `max-md:` typography per D-06 (~16px title):
```svelte
<p class="truncate text-[20px] max-md:text-[16px] leading-[1.2] font-semibold text-foreground">
```

**Core pattern — meta strip** (lines 102-104): today's `.stream-row-meta` class carries a
`max-height: 40px` desktop-tuned clip (`web/src/app.css:255-258`, cited in RESEARCH.md Pitfall
4) that is NOT safe to reuse unmodified at compact size. Per D-07, compact meta needs a
single-line `flex-nowrap truncate` strip (source name now rendered as visible text, not just a
`title` attribute — currently only the icon carries `title={sourceDisplayName}`, line 113):
```svelte
<div class="stream-row-meta mt-1 flex flex-wrap items-center gap-2 text-[14px] max-md:flex-nowrap max-md:overflow-hidden max-md:text-[12px] leading-[1.4] text-muted-foreground">
  <span class="shrink-0" title={sourceDisplayName || undefined}>
    <PluginIcon {plugin} size="size-3.5" />
  </span>
  <!-- D-07: source name becomes visible truncating text at compact size -->
  <span class="hidden max-md:inline max-md:truncate">{sourceDisplayName}</span>
  {#if item.group_label}
    <span class="shrink-0 max-md:truncate">{item.group_label}</span>
  {/if}
  <span class="shrink-0">{formatItemDate(item.timestamp_unix)}</span>
  <!-- warning dot (lines 126-146): unchanged, must survive every width per D-07 -->
```

**Core pattern — snippet** (lines 158-170): `line-clamp-2` → `max-md:line-clamp-1` per D-06 (one
line at compact size, two-line unchanged elsewhere):
```svelte
<p class="mt-1 line-clamp-2 max-md:line-clamp-1 text-[16px] max-md:text-[13px] leading-[1.5] text-foreground">
```

**Why this is safe (cascade, not a rewrite):** `.stream-row-surface`'s fixed `height: 152px`
lives in `app.css`'s `@layer components` (verified quote, `app.css:236-251`); any Tailwind
utility class (including `max-md:h-[58px]`) placed directly on the row element lands in
`@layer utilities`, which Tailwind v4's layer order guarantees wins regardless of source order
— add `max-md:h-[58px]` (or similar, tuned to D-06's ~55-60px target) alongside the existing
`stream-row-surface` class on the `<button>` (line 82) without touching `app.css`.

**Search highlighting** (lines 96-98, 161-163) — `.search-highlight` class and `highlightText`/
`parseSnippet` calls are unchanged; D-06 explicitly requires highlighting to survive at compact
size, so these lines are copied verbatim, not modified.

```go
func setup(ctx context.Context, logger hclog.Logger) (*config.Store, *index.Store, error) {
	path := configPath()
	cfgStore, err := config.NewStore(path)
	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			if mkErr := os.MkdirAll(filepath.Dir(path), 0o700); mkErr != nil {
				return nil, nil, fmt.Errorf("bootstrap config dir: %w", mkErr)
			}
			defaultCfg := &config.Config{
				Server:    config.ServerConfig{Listen: config.DefaultListen},
				Index:     config.IndexConfig{Path: config.DefaultIndexPath},
				Plugins:   config.PluginsConfig{Dir: config.DefaultPluginsDir},
				Sync:      config.SyncConfig{Interval: config.DefaultSyncInterval},
				Sources:   map[string]config.Source{},
				Webspaces: map[string]config.Webspace{},
			}
			if wErr := config.WriteCanonical(path, defaultCfg); wErr != nil {
				return nil, nil, fmt.Errorf("bootstrap config write: %w", wErr)
			}
			cfgStore, err = config.NewStore(path) // re-load through the normal path
		}
		if err != nil {
			return nil, nil, err
		}
	}
	cfg := cfgStore.Expanded()

	store, err := index.Open(cfg.Index.Path)
	if err != nil {
		return nil, nil, err
	}
	return cfgStore, store, nil
}
```

**Error handling pattern:** identical to the file's existing discipline — every error wraps with
`fmt.Errorf("...: %w", err)` and propagates to `fatal(err)` at the call site (`main()`, lines
28-33); the bootstrap branch must not swallow any error other than the initial
`os.ErrNotExist` check.

**Anti-pattern (explicit, from RESEARCH.md):** do not write `cfgStore.Expanded()` (secret-
resolved) to disk — only ever the raw `defaultCfg`, matching every other write path in this
codebase (`config.WriteCanonical`'s own doc comment, D-05 secret discipline).

### `web/e2e/specs/` + fixtures — mobile-viewport and bootstrap specs (test, request-response)

**Analog:** existing spec files in `web/e2e/specs/` plus `web/e2e/fixtures/kernel.ts` /
`config-builder.ts` (not re-read this session in full; RESEARCH.md's Pitfall 1 is the load-
bearing finding to carry forward — cited here rather than re-verified, since it was already
verified in the upstream RESEARCH.md session against `web/e2e/fixtures/kernel.ts:261-276` and
`config-builder.ts:53-58`).

**Critical constraint (do not rediscover at execution time):** `launchKernel` always calls
`allocateEphemeralPort()` and writes a `config.toml` with that port before spawning the kernel.
A genuine "no config file" bootstrap e2e spec cannot simply skip `writeConfig`, because the
kernel would then bootstrap its own default at the **fixed** `127.0.0.1:7777`, not the fixture's
allocated port — `waitForKernelReady` would poll the wrong address. RESEARCH.md's recommended
resolution: test the bootstrap **logic** (missing file → written default → loads) at the Go
level (a `kernel/config` or `cmd/topos` test using a temp dir), and let the **e2e** spec assert
only the UI-visible consequence (the greeting) using the **existing** empty-shell fixture shape
(zero-webspace `configSpec` — normal port allocation, no genuinely-missing file needed, since
`GET /api/config` returning `{webspaces: {}}` is indistinguishable to the browser either way).

**Mobile-viewport specs:** follow the existing spec file structure/imports (Playwright
`@playwright/test`, existing fixture helpers); use `use.viewport` override or a dedicated
Playwright project (RESEARCH.md Standard Stack table) rather than a new plugin.

## Shared Patterns

### Breakpoint mechanism: Tailwind `md:`/`lg:`/`max-md:` prefixes, not JS-computed layout state
**Source:** Tailwind v4 defaults (`md`=768px, `lg`=1024px — exact match to D-02, zero `@theme`
customization needed).
**Apply to:** `+page.svelte` pane composition, `StreamRow.svelte`/`SearchResults.svelte`
compact geometry, `StreamDateMarkers.svelte` visibility, `WebspaceHeader.svelte` touch
affordances. Reserve JS/`matchMedia` only for behavior that cannot be expressed in CSS (the
takeover's `pushState` trigger, which needs a JS branch to decide whether to push a history
entry at all).

### Shallow-routing history entry: `pushState`/`page.state`, not a hand-rolled `popstate` listener
**Source:** `$app/navigation` (`pushState`), `$app/state` (`page`) — already imported in
`+page.svelte`; official pattern at https://svelte.dev/docs/kit/shallow-routing.
**Apply to:** `+page.svelte` takeover open/close only. Do not duplicate with a manual
`window.addEventListener('popstate', ...)`.

### `errors.Is(err, os.ErrNotExist)` for "file missing" detection, not string matching
**Source:** `kernel/config/config.go:57-60` (`LoadRaw`'s `%w`-wrapped error).
**Apply to:** `cmd/topos/main.go`'s `setup()` bootstrap gate only — every other `LoadRaw`
failure (malformed TOML, permission denied, EISDIR) must continue to `fatal(err)` unchanged.

### Canonical config writing: always `config.WriteCanonical`, never a hand-rolled TOML string
**Source:** `kernel/config/writer.go` (atomic temp-file+rename, `.bak` rotation,
`CanonicalHeader`).
**Apply to:** the bootstrap default write — the only other config-writing surface in this
codebase (the UI's `PUT /api/config`) already goes through this same function.
