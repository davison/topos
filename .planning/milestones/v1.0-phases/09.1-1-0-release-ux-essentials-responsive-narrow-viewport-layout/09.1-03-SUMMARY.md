# Phase 09.1 Plan 03: Compact Stream Cards Summary

**Stream and search-result rows collapse from 152px to a fixed 60px below 768px (title, one jointly-truncating meta strip, one-line snippet, thumbnail/tags dropped), the date-marker ruler hides and reclaims its 12px gutter below the same breakpoint, and an 11-case Playwright spec measures every density claim in a real browser at 390/900/1280px.**

- **Duration:** ~35 min
- **Tasks:** 3 of 3 completed
- **Files modified:** 5 modified, 1 created

## Accomplishments

- `StreamRow.svelte` gained a `max-md:`-scoped compact geometry: `max-md:h-[60px]` row, hidden thumbnail/tag pills, a `max-md:text-[16px]` title, and a restructured `flex-nowrap` meta strip whose new source-name/group-label text unit truncates as one — with zero edit to `web/src/app.css` (Tailwind v4's layer order does the work, per 09.1-RESEARCH.md Pattern 3).
- `StreamDateMarkers.svelte`'s ruler overlay gained `max-md:hidden`; `+page.svelte`'s stream scroll region gained `max-md:pr-0` in the same class attribute as its existing `pr-6`, reclaiming the ruler's 12px lane below 768px. `marker-overlay.test.ts` widened with a structural guard asserting both halves move together.
- New `web/e2e/specs/09-1-compact-cards.spec.ts` (11 cases): row height at all three bands, source-name-as-visible-text, date visibility, thumbnail/tag-pill hidden, jointly-truncating long name (via a deliberately long fixture display name), stale-dot survival on a degraded source (via a scripted `GET /api/sources` route), search-result geometry/highlighting parity, and date-marker ruler visibility per band.
- Found and fixed a real regression in Wave 1's own `09-1-mobile-takeover.spec.ts`: the compact row's height reduction meant its 2-instance/8-item fixture no longer produces enough content to overflow the scroll region at 390x844, breaking the D-01 scroll-preservation test outright. Bumped to 4 instances (16 items) and re-verified all 11 of that spec's cases, plus a full 92-test e2e sweep.

## Decisions Made

- Followed both `planner_resolutions` exactly as locked: R1 (CSS breakpoint classes, no `compact` prop, no `app.css` edit) and R2 (the compact meta line is a different `flex-nowrap` layout strategy, not a shrunk version of the desktop `flex-wrap` badge-clip strip).
- Wrapped the tag-pills `{#each}` block in a `<span class="contents max-md:hidden">` rather than a plain `<span>` — `display: contents` keeps the badges as direct flex-wrap children at desktop size (identical layout to before), while `max-md:hidden` removes the whole group at compact size. A plain wrapping span would have broken the desktop flex-wrap badge layout by introducing a new flex item.
- e2e assertions for thumbnail visibility target the Thumbnail component's wrapper `div` (carrying `max-md:hidden`), not the `<img>` inside it — the mock plugin's `Fetch(THUMBNAIL)` always reports unavailable (no real bytes to serve), so the `<img>`'s `onerror`-driven swap to the `FileText` fallback icon is a genuine race; the wrapper is stable regardless of which branch is currently rendered.
- The stale/degraded-source e2e case scripts `GET /api/sources` via `page.route` (browser-side only, registered after `waitForFirstSync`'s own Node-side fetch has already confirmed real sync landed) rather than trying to provoke a genuine plugin failure — matches `g-08-3-degraded-source-not-outage.spec.ts`'s established interception pattern, extended to a different endpoint.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `09-1-mobile-takeover.spec.ts`'s scroll-preservation case broke under the new compact row height**
- **Found during:** Task 3, running this plan's own required regression check (`web/e2e/specs/09-1-mobile-takeover.spec.ts`) before the final commit
- **Issue:** That spec's fixture seeded 2 mock instances (8 items). At 390x844, 8 items × the new 60px compact row height = 480px of content against a measured ~586px scrollable area — no overflow at all, so case 4's own "the fixture stream must be tall enough to scroll" guard failed outright (a real, reproducible zero, not a timing flake). Desktop's unchanged 152px rows never had this problem; only the `max-md:` band did.
- **Fix:** Bumped the fixture from `mockInstances(2)` to `mockInstances(4)` (16 items, 960px), comfortably clearing the measured scroll area with margin for the header-collapse feature reclaiming further height. Updated the module comment to document both the original checkpoint-fix rationale and this plan's own compact-row rationale.
- **Files modified:** `web/e2e/specs/09-1-mobile-takeover.spec.ts`
- **Verification:** All 11 cases in that spec pass, repeated 2x for stability; full 92-test e2e suite passes.
- **Committed in:** `2b4b96c` (Task 3 commit)
