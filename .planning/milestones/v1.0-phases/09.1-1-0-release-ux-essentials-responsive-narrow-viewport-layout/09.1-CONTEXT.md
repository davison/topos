# Phase 09.1: 1.0 Release UX Essentials - Context

**Gathered:** 2026-08-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Two release-blocking UX essentials before the Phase 10 docs pass (inserted deliberately ahead of docs so Phase 10's screenshots capture the final UI):

1. **Responsive narrow-viewport layout** — the stream + detail UI works on phone-width viewports: below a breakpoint the detail pane becomes a full-viewport takeover with a back affordance (it no longer sits beside the stream), and stream cards render in a compact form (roughly halved height, reduced font sizes). Desktop behavior above 1024px is byte-identical to today.
2. **First-run bootstrap** — a missing `config.toml` no longer aborts startup: the kernel writes a default config and the UI greets the new user with a friendly prompt to create their first webspace. (Phase 7 already ships the zero-webspaces empty state and create-webspace modal; this closes the gap that the process currently dies in `config.NewStore` before any of that can render.)

No new sources, no new correlation behavior, no agent surface changes. Phase 07.1's standing rule applies: all UI work here extends the Playwright e2e suite (`web/e2e/specs/`) as part of definition of done — narrow-viewport behavior should be pinned by specs running at a mobile viewport size.

</domain>

<decisions>
## Implementation Decisions

### Narrow-layout shape (mobile detail takeover)
- **D-01:** **Takeover + back, not literal stacking.** At mobile width, tapping a stream item opens the detail as a full-viewport takeover with a back affordance; the stream's scroll position is preserved for the return trip. The roadmap's "stacks below" wording is superseded by this decision — no half-visible side-by-side or scroll-down-to-detail states.
- **D-02:** **Breakpoint is 768px, with a proportional mid-range band.** Below 768px (Tailwind `md`): takeover layout + compact cards. Between 768–1024px: side-by-side survives, but the stream pane gives up its fixed `w-[480px]` and shrinks proportionally so the detail pane stays usable. At ≥1024px: today's layout exactly (fixed 480px stream when a detail is open).
- **D-03:** **Back = visible control + browser history entry.** Opening the takeover pushes a history entry so the phone's back gesture/button closes the detail and returns to the stream instead of leaving the app. A visible back control in the detail bar does the same. (No edge-swipe gesture — explicitly declined as extra work that can fight rendition-iframe scrolling.)
- **D-04:** **Takeover hides the app header.** While the takeover is open, the webspace switcher / chip row / search header gives way to one slim detail bar: back control, item title, open-in-source affordance. Back restores the full header with the stream. Maximum reading height for renditions on a phone.

### Compact stream cards
- **D-05:** **Compact cards apply below 768px only.** The 768–1024px band and desktop keep today's card geometry exactly (20px title, 14px meta, 16px two-line snippet). Compact is part of the mobile layout, not a global density change.
- **D-06:** **Compact card composition: title + one merged meta line + one-line snippet.** Target ~55–60px per card (vs ~110px today): title ~16px, meta ~12px, snippet clamped to a single line at ~13–14px. Search highlighting still lands in title + snippet segments exactly as today.
- **D-07:** **The merged meta line keeps everything, truncating to fit:** plugin icon + source display name + group label + date on one line, with source name / group label truncating first when space runs out. Rationale: the plugin icon alone is ambiguous when two instances share a plugin type (Home email vs Work email). The degraded-sync warning dot survives at every width — health honesty is not negotiable.
- **D-08:** **Search-result rows adopt the compact geometry below 768px** (highlighting intact); **the date-marker scrollbar ruler is hidden below 768px** — reclaims its 12px lane and avoids building touch affordances for a hover-designed control. The ruler is unchanged at ≥768px.

### Claude's Discretion
- **Header at narrow widths** (area offered, not selected): how the webspace switcher, source chip row, search box, and branding lockup adapt below 768px — wrapping, the existing overflow popover, hiding the branding lockup, touch replacements for hover-revealed refresh and tooltips. Constraint: every existing affordance must remain reachable on touch (chip menu, filter toggle, refresh, manage-sources) even if relocated; nothing may silently disappear.
- **First-run bootstrap** (area offered, not selected): default config contents (empty `[webspaces]`/`[sources]` vs seeded example), whether `topos sync` also bootstraps or only `serve`, XDG path creation, and how the friendly first-webspace greeting relates to Phase 7's existing zero-webspaces empty state (reuse vs a distinct welcome treatment). Constraints: the written default must pass the kernel's own load validation (Phase 7 D-20 empty-shell semantics make a zero-webspace config valid); the canonical writer + `${VAR}` secret discipline (Phase 7 D-01/D-05) governs anything written; never overwrite an existing file.
- Transition/animation for the takeover open/close, scroll-restoration mechanics, and how the history entry interacts with existing URL state (search/filter query params).
- Compact-card padding and tap-target sizing (44px minimum touch targets where OS conventions expect them).
- Mobile e2e strategy: Playwright viewport project(s) or per-spec viewport overrides — as long as takeover, back-gesture (history) behavior, and compact-card rendering are pinned by specs.

</decisions>

## Existing Code Insights

### Reusable Assets
- `web/src/routes/w/[webspace]/+page.svelte` (~line 799–885) — the two-pane `main`: stream wrapper `w-[480px] shrink-0` when `selectedItem`, else `flex-1`; detail pane `flex-1 border-l pl-8`. - `web/src/lib/components/StreamRow.svelte` — the card to give a compact variant: 20px title, 14px meta row (PluginIcon, source name, group label, date, warning dot), 16px `line-clamp-2` snippet with search-highlight segments.
- `web/src/lib/components/DetailPane.svelte` — becomes the takeover's content; its header region is where the slim bar (back + title + OpenInSource) composes.
- `web/src/lib/components/SearchResults.svelte` — rows adopting compact geometry (D-08).
- `web/src/lib/components/StreamDateMarkers.svelte` + `marker-overlay.test.ts` — the ruler hidden below 768px (D-08).
- `kernel/config/writer.go` — canonical TOML writer + `CanonicalHeader`; the natural producer of the bootstrap default config.
- `cmd/topos/main.go` — `configPath()` (XDG resolution) and `setup()` → `config.NewStore` (the currently-fatal missing-file path); the bootstrap intercepts here.
- Phase 7's `CreateWebspaceModal.svelte` + root-route zero-webspaces empty state — the existing first-run creation flow the friendly greeting builds on.

### Established Patterns
- Zero media queries exist today — Tailwind responsive prefixes (`md:`, `lg:`) are available but unused in the pane layout; this phase introduces the app's responsive system, so pick one consistent mechanism (Tailwind breakpoints align with the 768/1024 decisions).
- Structural UI tests are comment-stripped source scans (Phase 6 pattern) — compact-card and takeover class changes will trip existing guards (`pane-layout.test.ts`, `source-chip-pill.test.ts` etc.); update them as behavior contracts, not obstacles.
- Fail-loud validation naming field + plugin — the bootstrap-written default must load through the same validation, not bypass it.
- Filter/search state persists in URL query params (Phases 2/6) — the takeover's history entry (D-03) must compose with, not clobber, that state.
- Hermetic e2e fixtures generate temp `config.toml` pre-boot (07.1 D-03) — the bootstrap spec inverts this: boot with *no* config file and assert the kernel writes the default and the greeting renders.

### Integration Points
- `web/src/routes/w/[webspace]/+page.svelte` — breakpoint-conditional pane composition; selected-item state drives takeover visibility below 768px.
- `web/src/lib/components/` — compact StreamRow variant (prop or CSS-driven), slim detail bar, back control.
- `cmd/topos/main.go` + `kernel/config` — missing-file branch: write default via the canonical writer, continue boot.
- `web/e2e/specs/` + fixture helpers — mobile-viewport specs; a no-config fixture mode.

<specifics>
## Specific Ideas

- The takeover is the chosen reading of the roadmap's "detail pane stacks below the stream pane" — the user picked the mobile-standard master-detail takeover over literal stacking when offered both.
- Density numbers agreed as targets, not pixel contracts: compact card ~55–60px (vs ~110px today), title ~16px / meta ~12px / snippet ~13–14px, one-line snippet.
- The warning-dot-stays constraint was presented as non-negotiable and accepted without pushback — degraded-sync honesty survives every viewport size.

</specifics>

<deferred>
## Deferred Ideas

- Edge-swipe-to-go-back gesture in the takeover — declined (D-03) as meaningful extra work that can fight rendition-iframe scrolling; revisit only if the button + history-entry pattern feels insufficient in real phone use.
- Global stream density change (compact cards on desktop) — declined (D-05); could return as a user preference toggle in a later polish phase.
- Touch adaptation of the date-marker ruler — sidestepped by hiding it below 768px (D-08); a tap-to-jump ruler could return if narrow-viewport date navigation proves wanted.
