# Phase 07.1: Browser E2E Harness - Context

**Gathered:** 2026-08-09
**Status:** Ready for planning

<domain>
## Phase Boundary

A Playwright browser-automation suite running against a hermetic kernel — built `topos serve` binary, embedded SPA, mock-shaped plugins, no live sources, no network, no credentials — that turns Phase 7's UAT items (1–7 and 10) into permanent regression armor before Phase 8 (WhatsApp) churns the codebase, plus a small core-journey smoke set (stream → detail → search → filter). The phase also introduces the project's first CI: a GitHub Actions workflow running units + e2e on push/PR to main. `scripts/e2e-smoke.sh` and its `make smoke` target are retired; the hermetic suite absorbs their portable guards.

No app-behavior changes are in scope beyond what the harness itself needs (one new e2e-only test plugin binary and its UI required-fields entry). UAT items 8–9 (kill-timing windows) stay excluded as not browser-automatable — accepted risk, consistent with the UAT record.

</domain>

<decisions>
## Implementation Decisions

### Kernel-under-test shape
- **D-01:** Playwright runs against the **built kernel binary serving the embedded SPA** — the exact shipped artifact, one process. Not the Vite dev-server path.
- **D-02:** Isolation is a **fresh kernel per spec file**: each file boots its own kernel on an ephemeral port with its own temp `config.toml` + index DB, torn down after. Test cases within a file may share that kernel where safe. (`scripts/dev-guard-smoke.sh` already models hermetic ephemeral-port boots — reuse the pattern.)
- **D-03:** State is **seeded by generating the temp `config.toml` before kernel boot** (a fixture helper builds N webspaces / N mock instances, zero-webspace, pre-attached-sources shapes as each spec needs). The UI is driven only for the behavior actually under test — never to build preconditions.
- **D-04:** Specs **assert on-disk config effects directly** — read the temp `config.toml` and assert its *parsed TOML* content (never string matching) alongside UI assertions. Several UAT items literally specify file outcomes ("config.toml gains `[webspaces.<name>]`", "narrows correctly, other webspaces untouched"); a canonical-writer bug must not be masked by the UI rendering from memory.

### Plugin surface (hermetic, cgo-free)
- **D-05:** UAT item 5's two-step "New Signal…" flow is **ported to a mock-shaped plugin**: a hermetic test plugin declaring a required connection field with a seeded default runs the full flow (pre-fill → clear → blocked with zero network requests → restore → Match step → chip appears). The spec covers every UI mechanism item 5 guards without cgo, SQLCipher, or Signal internals.
- **D-06:** That plugin is a **separate e2e-only binary under a distinct plugin-type name** (e.g. `plugins/mockstrict` — naming is planner's choice). `plugins/mock` stays untouched as the config-free PLUG-05 contract reference; the UI's required-fields table (07-13's helpers) gains an entry for the new type.
- **D-07:** The harness plugins directory contains **mock + the e2e plugin only**. Item 7's 15+ instances are mock instances. Real plugins (paperless, silverbullet, proton, signal) never enter the suite — their connection behavior is covered by their own Go tests, and keeping them out is what makes the suite cgo-free and CI-able.

### Spec scope
- **D-08:** **All of UAT items 1–7 and 10 become specs** — the six deferred items (3, 4, 5, 6, 7, 10) plus items 1–2, which passed live but guard the highest-value regressions (G-07-1 create-webspace vs outage copy; G-07-7 removed source's items leave with the chip, no skeleton flash). Item 10 uses Playwright route interception to delay the first chip's describePlugin response and prove the second click's state wins.
- **D-09:** A **core-journey smoke set** ships alongside the UAT ports: stream renders seeded mock items, detail pane opens with content, search returns and highlights, source filter chips toggle. This is the armor Phase 8's stream/detail churn actually needs, and it absorbs e2e-smoke.sh's portable guards (SPA serves a real stylesheet with the theme token; stream item shape).
- **D-10:** **`scripts/e2e-smoke.sh` and `make smoke` are retired** — deleted, not kept alongside. The Playwright suite fully replaces them; live-source verification happens via UAT only. — **Reversibility:** reversible — the script stays in git history if a live-credential smoke is ever wanted again.
- **D-11 (standing rule, user-stated):** **Future UI work always extends the e2e suite** — from Phase 8 onward, phases that touch the UI add/extend Playwright specs as part of their definition of done, and future UAT items that are browser-automatable get specs rather than staying manual. Downstream planners must carry this into phase plans. — **Reversibility:** reversible — process rule, but dropping it silently defeats the phase's purpose.

### Runner, CI & failure policy
- **D-12:** Invocation is a **separate `make e2e`** target: builds the kernel + test plugins, ensures Playwright browsers are installed, runs the suite. `make test` stays units-only and fast; `make e2e` takes the retired `make smoke`'s place as the pre-ship gate.
- **D-13 (user-requested):** This phase **creates the project's first CI: a GitHub Actions workflow running units + e2e on push and PR to main** — Go tests, vitest, svelte-check, then `make e2e`. Signal's cgo tests (`make test-signal`) stay desktop-only, which D-07's mock-only harness already permits.
- **D-14:** **Chromium is the default and the only engine CI runs**, but the Playwright config defines Firefox and WebKit projects too, invocable manually on demand (e.g. `make e2e` browser flag or `--project=` passthrough) for an occasional cross-engine pass. Firefox/WebKit are never part of the automated gate.
- **D-15:** **Zero retries everywhere** — local and CI. A flaky test is a bug and gets fixed (fail-loud house ethos; hermetic per-file kernels remove the usual flake sources). Every failure saves Playwright trace + screenshot artifacts for diagnosis.

### Claude's Discretion
- Playwright project layout (where specs/fixtures/helpers live — `web/e2e/` vs top-level `e2e/`), TypeScript config, and Playwright version pinning.
- The e2e plugin's name, its required field's name/seeded default value, and its fixture item corpus (deterministic items for stream/search/detail assertions).
- Kernel boot/teardown helper mechanics: ephemeral port selection, temp-dir layout (config, index, plugins dir), readiness probing, process-group cleanup — reuse `dev-guard-smoke.sh` patterns where sensible.
- Parallelism (Playwright workers vs per-file kernels), timeouts, and how `make e2e` handles browser installation idempotently.
- GitHub Actions workflow details: runner image, caching (Go modules, npm, Playwright browsers), artifact upload wiring.
- Exact spec-to-UAT-item mapping granularity (one file per item vs grouped by surface), as long as all of 1–7 + 10 and the core journeys are covered and traceable to their UAT item numbers.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `plugins/mock/` — working, config-free source plugin over the real go-plugin gRPC handshake; the e2e plugin copies its skeleton and adds a required-field pre-Serve guard.
- `scripts/dev-guard-smoke.sh` — ephemeral-port allocation, kernel-readiness polling, loud-failure teardown; port these mechanics into the Playwright global fixture (in TS or by shelling out — planner's choice).
- `web/` vitest setup — existing TS/test tooling conventions (colocated `*.test.ts`); Playwright is new but should follow the repo's existing TS config style.
- `kernel/config` load path — the temp `config.toml` seeding exercises the kernel's real load/validation path for free (D-03).
- 07-13's required-fields helpers (web/src/lib, three pure functions) — the table the new e2e plugin type must join for the blank-required-field guard to fire.

### Established Patterns
- Hermetic guards bind only self-selected ephemeral ports and are safe to run beside a live kernel (`dev-check`) — `make e2e` must keep that property.
- Fail-loud everywhere: no retries, no vacuous passes (e2e-smoke.sh's stale-listener pre-check exists because a vacuous pass burned a session once).
- Contract enforcement by test (RPC allowlist, read-only AST, egress pinning) — the suite adds browser-level enforcement to the same philosophy.
- Secrets never in files/CI: the hermetic suite needs zero credentials, which is what makes GitHub Actions viable at all.

### Integration Points
- `Makefile` — new `e2e` target; `smoke` removed; `plugins` target likely gains the e2e plugin build (or a dedicated e2e-plugins target keeps it out of dev builds).
- `.github/workflows/` — new; first CI workflow in the repo (D-13).
- `web/package.json` — Playwright dev-dependency + script entry.
- Plugin discovery (kernel scans the plugins dir) — the harness points the kernel at a temp plugins dir containing exactly mock + e2e plugin binaries (D-07).

</code_context>
