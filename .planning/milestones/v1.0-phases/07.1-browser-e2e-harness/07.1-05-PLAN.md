<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Blank required field -> plugin subprocess launch | Without the UI guard, the kernel launches the plugin with a blank mandatory field and the plugin fatals before the handshake, producing an unexplained failure. |
| Delayed/failed responses -> SPA state machine | Specs induce timing the app must survive; a mis-registered handler induces nothing. |
| Config writer -> webspaces other than the edited one | A save that rewrites more of the document than requested silently damages unrelated configuration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.1-16 | Tampering | blank-required-field guard | high | mitigate | Item 5's spec asserts the observed describe-plugin request count is exactly zero on a blocked submit, not merely that a message appeared — the guard's purpose is to stop the subprocess launch, and only the request-count assertion proves it. |
| T-07.1-14 | Tampering | config writer scope | high | mitigate | Item 6's spec captures a full parsed-config baseline and asserts deep equality of the untouched webspace after each write, catching a writer that rewrites beyond its edit. |
| T-07.1-04 | Repudiation | race and geometry assertions | high | mitigate | The race spec asserts the winning state BOTH before and after the delayed response lands, and includes a control case proving the loser can win when not raced — so a spec that passes for the wrong reason is detectable. The scroll spec asserts geometry with an explicit fixed viewport rather than class names, so a layout regression that keeps the class and loses the behaviour still fails. |
| T-07.1-13 | Tampering | shipped SPA source | medium | mitigate | `git diff --stat HEAD -- web/src` must be empty in every task. |
</threat_model>
