Then create `.github/workflows/ci.yml`, the repository's first workflow. It runs on push to `main` and on pull requests targeting `main`, in a single job on the standard Ubuntu runner.

Before writing any `uses:` line, verify each action's current major version rather than copying the research skeleton's — 07.1-RESEARCH.md's Assumptions Log entry A4 explicitly flags those version numbers as a low-confidence snapshot. Use actions from the official `actions` organisation only (checkout, setup-go, setup-node, cache, upload-artifact); introduce no third-party action, since a third-party action at a floating tag is arbitrary code with repository-scoped permissions.

Step order, and the reasoning that fixes it:
  1. Check out the repository.
  2. Set up Go, reading the version from `go.work`, with the action's built-in module cache enabled.
  3. Set up Node at a version `actions/setup-node` actually provides and that builds this SPA, with npm caching keyed on `web/package-lock.json`.
  4. Cache the Playwright browser download directory, keyed on `web/package-lock.json`, so a cache hit skips the browser download on subsequent runs. `make e2e` performs the install itself and is idempotent, so no separate install step is needed — the cache simply makes it fast.
  5. `npm --prefix web ci`.
  6. `npm --prefix web run check` (svelte-check), `npm --prefix web run test` (vitest), and `npm --prefix web run check:e2e` (the spec tree's typecheck).
  7. `make test-portable` — the Go half. Do NOT call `make test`: it chains to `test-signal`, which is `CGO_ENABLED=1` against the system SQLCipher library and would fail on a runner that has no reason to install it, for a plugin the harness never launches.
  8. `make e2e`, with `E2E_PW_INSTALL_FLAGS` set to Playwright's system-dependency install flag for this step only (the runner needs it; a developer's own machine must not have `make e2e` invoke a privileged installer). Leave `E2E_PROJECT` at its `chromium` default — D-14 makes Chromium the only engine the automated gate runs.
  9. Upload the Playwright artifact directory as a build artifact, conditioned on failure, so a red run carries its own traces and screenshots (D-15).

The workflow must reference no repository secret and no live-source credential variable of any kind — D-07 and D-10 make that structurally unnecessary, and this is the property that makes CI viable for this project at all. It must also not add a `.env` file or source one.

Finally, confirm the tracked placeholder that keeps `//go:embed all:build` resolvable on a clean checkout is still tracked; if the working tree shows it deleted, restore it. A checkout without it fails the Go build before any SPA build has run, which would break CI for a reason entirely unrelated to this phase.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> repository contents and token | The workflow executes with a repository-scoped token; every action it invokes runs as that identity. |
| Workflow file -> secrets store | A workflow that references a secret makes that secret reachable from CI logs and from any step that follows. |
| Deleted gate -> remaining coverage | Removing an automated gate is only safe if its coverage genuinely moved somewhere else. |
