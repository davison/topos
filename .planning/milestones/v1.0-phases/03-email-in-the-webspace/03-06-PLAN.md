<objective>
Close the new, confirmed code-level BLOCKER in 03-VERIFICATION.md's `gaps:` block (first surfaced as 03-REVIEW.md CR-01): `plugins/proton/plugin.go`'s `mailboxCache` — the only state `Fetch`/`fetchFull` has for resolving a `source_id` back to the IMAP mailbox it must EXAMINE — is REPLACED, not merged, on every `Match` call. `kernel/correlate/correlate.go`'s `SyncSource` calls `Match` once per configured webspace, sequentially, within one sync cycle, against the single long-lived plugin instance `kernel/pluginhost` launches per source. Each webspace's `Match` only rediscovers messages in mailboxes matching THAT webspace's keywords, so the replacement discards every entry an earlier webspace's `Match` just inserted. With two or more webspaces sharing the Proton source — the product's designed core use case, not an edge case — opening an email from any webspace but the last one processed returns `codes.NotFound` even though the item is visible in the stream and the index genuinely was synced. Go's randomized map iteration means which webspace "wins" can change between consecutive cycles.

Also closes the WARNING from the same gap (03-REVIEW.md WR-01): `web/src/lib/components/DetailPane.svelte` declares its own local date formatter that omits the `timeZone: 'UTC'` pin `web/src/lib/format.ts`'s `formatItemDate` enforces and `format.test.ts` explicitly asserts, so the same item can show a different calendar day in the detail pane header than in its own stream row for any viewer west of UTC.

**User-visible outcome** (ROADMAP Phase 3 Success Criterion 1, quoted verbatim — the ROADMAP `**Goal:**` line is not in `As a / I want to / so that` form, so no user story is invented here, following 03-05's precedent): *"Emails in Proton folders or labels matching the webspace keyword appear in the stream with sender, subject, and date, and **render their body inline in the detail pane**."* Sender, subject and date all work as of 03-05; this plan makes the body render for every webspace rather than only for the luckiest one, and makes the date agree with itself across the two surfaces that show it.

This is one complete vertical slice, not a layer: plugin resolution state → the kernel's unchanged per-webspace sync loop (reproduced in-test) → the detail pane the user actually opens.

Purpose: SRC-01's implicit "readable" contract is unmet across the multi-webspace deployment the project is designed for, and no test in the repository exercises two sequential `Match` calls followed by a `Fetch` for an item only the first call discovered — which is precisely why this shipped with every suite green. This plan fixes the state semantics and installs the assertion that makes this class of cross-call state loss impossible to repeat.

Output: one renamed-and-inverted cache method, one deleted cache mutation on the zero-match path, one rewritten field doc comment, one new seeded fixture mailbox, two new Go regression tests that fail with `codes.NotFound` before they pass, one component import change, and one frontend source-scan guard test.
