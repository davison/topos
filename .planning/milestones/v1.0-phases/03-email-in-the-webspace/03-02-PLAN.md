<objective>
Expand the tracer's plain-text Fetch into the full email reading experience and
convert the phase's central guarantee — reading an email in webspaces never marks
it read in Proton — from an implementation detail into mechanically enforced,
automatically tested behaviour.

Two things ship here. First, the HTML body path: prefer the message's `text/html`
part, sanitize it with a bluemonday policy scoped for untrusted third-party mail,
wrap it in the same fixed dark-theme document SilverBullet already uses, and
return it as a `text/html` rendition so the detail pane's existing sandboxed
iframe branch renders it with zero new UI code — plus the sender line the detail
pane has never rendered. Second, the proof layer: a wire-level transcript test
that needs no live Bridge, an AST scan that fails the build on any IMAP-mutating
identifier, the outbound-host predicate table, and an environment-gated live test
that reads a real message's flags through a second connection before and after a
full plugin cycle.

Purpose: SRC-01's second success criterion is worded "proven by an automated
test". A guarantee that only holds because nobody happened to call the wrong
method is not proven; this plan makes it enforced.

Output: a readable HTML email in the detail pane, and four independent
read-only proofs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| arbitrary email sender -> proton plugin -> browser | Message HTML is fully attacker-controlled content authored by anyone who can email this mailbox, rendered inside the user's own application |
| proton plugin -> kernel rendition route -> sandboxed iframe | The sanitized document crosses from plugin bytes into a browser rendering context |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Tampering | Untrusted email HTML reaching a rendering context | high | mitigate | bluemonday sanitization before wrapping, plus the kernel's existing MIME allowlist, `sandbox` directive and `default-src 'none'` CSP, plus the SPA rendering it only in an iframe and never through a raw-HTML directive — three independent layers |
| T-03-10 | Information Disclosure | Email tracking pixels and remote-resource exfiltration from a rendered body | medium | mitigate | The rendition route's `default-src 'none'` blocks every subresource request the document could attempt, including CSS `url()` background fetches; no new code needed, and the behaviour is asserted by the render test's remote-image fixture |
| T-03-11 | Tampering / Information Disclosure | Over-permissive inline `style` allowlist enabling CSS-based UI redress or exfiltration | medium | mitigate | The style attribute is permitted only on a named element set with a presentational-only CSS property allowlist; positional and behavioural properties stay denied; bluemonday's own email demo's global style allowance is explicitly not copied |
| T-03-12 | Denial of Service | Crafted MIME (huge part, thousands of parts, malformed structure) during Fetch | medium | mitigate | `io.LimitReader` per part under a package byte ceiling below `sdk.MaxMessageSize`, bounded maximum part count, and a parse failure returned as a gRPC error rather than a panic |
| T-03-13 | Tampering | An IMAP-mutating command reaching the user's mailbox | high | mitigate | EXAMINE-only sessions and BODY.PEEK fetches, enforced by a build-failing AST scan with a negative control and asserted at the wire level by the transcript test; confirmed end to end by the live \Seen-unchanged test |
| T-03-14 | Information Disclosure | Email plaintext persisted outside the source of record | high | mitigate | Fetch is request-time only and its response is never written to the index; the plugin sets `Preview` empty at Match time and the index stores metadata and preview columns only — enforced structurally because `kernel/correlate` persists only `item.Item` fields, which have no body field |
