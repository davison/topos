## Phase Goal

**Note (MVP mode):** the ROADMAP `**Goal:**` line for this phase is not in
`As a / I want to / so that` form, so no user story has been invented here. The
goal is reproduced verbatim; run `/gsd mvp-phase 3` if a user-story framing is
wanted.

> User's Proton mail for a topic appears in the webspace stream and stays readable
> there, and the volume it brings is navigable by searching within the webspace

<objective>
The tracer slice for Phase 3: one real Proton email travels the entire stack —
`config.toml` -> kernel config -> plugin subprocess env -> IMAP over TLS to the
Bridge forwarder -> EXAMINE + ENVELOPE scan -> Message-ID dedup -> `MatchResponse`
-> `correlate.SyncSource` -> SQLite index -> `GET /api/webspaces/{ws}/stream` ->
a stream row in the browser showing sender, subject and date — and clicking it
fetches the message body with `BODY.PEEK` and renders its plain-text part.

This is production code, not a prototype. The never-mark-read guarantee, the TLS
pinning, the outbound-host allowlist and the Message-ID dedup all land here in
their final form, because each of them is architectural: getting any of them
wrong later would mean re-deriving item IDs, re-indexing, or re-plumbing config.
The one deliberate functionality gap is HTML rendering of email bodies — the
sanitized `text/html` rendition path is plan 03-02, and adding it does not change
any interface this plan defines.

Purpose: prove the riskiest, least-verifiable parts of this phase (Bridge LAN
reachability, self-signed cert trust through a forwarder, IMAP read-only
semantics, Message-ID identity) on the executor's best early-context tokens,
before any expansion work is committed on top of them.

Output: the `plugins/proton` Go module and its binary, the two new
`config.Source` fields plumbed through all three hand-maintained places, and the
sender field rendered in the stream for the first time.
</objective>

  <read_first>

  <decision>How an email's Message-ID is encoded into the plugin's `source_id`, which becomes the kernel-wide item id `proton:{source_id}`.</decision>
  <context>
    This id is the `items.id` primary key, the `webspace_items` foreign key, the
    `{id}` path segment of `/api/items/{id}` and its `/content` child, and the
    "stable ID" AGENT-02 publishes to programmatic consumers (docs/api.md "The
    stable-ID scheme" promises it never changes across syncs). Changing the
    encoding after mail is indexed orphans every previously indexed email row,
    breaks any bookmarked or agent-held id, and requires a re-index — a data
    migration, not a refactor. That is why this is gated before the tracer runs
    rather than decided inside it.

    Fixed regardless of the option chosen: the source_id encodes the Message-ID
    and nothing else. Encoding the matched mailbox into it would give the same
    message two ids when it carries two matching labels, which breaks the dedup
    requirement (SRC-01 criterion 3) outright.

    Also fixed: `plugins/paperless` already needed a `url.PathUnescape` fix for
    ids containing reserved characters, so any option that leaves reserved
    characters in the id inherits that hazard.
  </context>
  <options>
    <option id="option-a">
      <name>URL-safe base64 of the normalized Message-ID (recommended)</name>
      <pros>Reversible with no extra state, so Fetch recovers the exact Message-ID from source_id alone; contains only [A-Za-z0-9_-] so it is safe in a URL path segment with no escaping subtleties; fixed alphabet means no percent-encoding round-trip hazard.</pros>
      <cons>Not human-readable in the URL bar or in a log line; slightly longer than a truncated hash.</cons>
    </option>
    <option id="option-b">
      <name>Raw Message-ID with surrounding angle brackets stripped</name>
      <pros>Immediately human-readable and directly usable as the argument to IMAP SEARCH HEADER Message-Id; zero encode/decode code.</pros>
      <cons>Real Message-IDs contain @ and . and can contain / and % and spaces, so every consumer must percent-encode correctly on the way out and PathUnescape on the way in — the exact class of bug already hit once in this repo.</cons>
    </option>
    <option id="option-c">
      <name>Truncated SHA-256 hex of the normalized Message-ID</name>
      <pros>Fixed short length, URL-safe, uniform.</pros>
      <cons>Not reversible, so the plugin must persist a hash-to-Message-ID map in addition to the Message-ID-to-mailbox map Fetch already needs, and a lost map means Fetch cannot resolve anything after a restart.</cons>
    </option>
  </options>
  <reversibility rating="one-way">Item ids are the index primary key and a published stable-ID contract (docs/api.md); changing the encoding later orphans every indexed email row and requires a re-index.</reversibility>

`WebmailBaseURL` is a config field rather than a constant deliberately: the

`plugins/proton/main.go`: copy the SilverBullet entrypoint verbatim in shape.
The `sourceConfig` struct decodes `base_url`, `username`, `token`, `ca_cert` and
`webmail_base_url`. Fail loudly via `fatal()` naming the specific key when
`base_url`, `username`, `token` or `webmail_base_url` is empty after expansion;
`ca_cert` is optional. Construct via `NewSourcePlugin` and serve with
`sdk.Handshake`, the `"source"` plugin key, and `sdk.GRPCServer`.

`plugins/proton/client.go`: the IMAP connection layer.
- Sentinel errors `ErrNotFound`, `ErrForeignHost` and `ErrNoMessageID`, all
  prefixed `proton:`.
- `Client` holds the parsed dial address, the allowed host, username, password,
  a `*tls.Config`, and whether the scheme requires implicit TLS. Parse `base_url`
  with `net/url`: scheme `imaps` means implicit TLS via
  `client.DialWithDialerTLS`; scheme `imap` means `client.DialWithDialer` followed
  by a mandatory `StartTLS` whose failure is returned as an error — there is no
  plaintext fallback path, and no code path may call Login on a connection that
  did not complete TLS. Reject any other scheme at construction time.
- `allowHost(hostport string) error`: copy the SilverBullet predicate verbatim in
  shape — split off the port, trim IPv6 brackets, lowercase, permit the configured
  base host, the literal `localhost`, and any `net.ParseIP` loopback address;
  otherwise return an error wrapping `ErrForeignHost` and naming the refused host.
  Wire it through a `pinnedDialer` whose `Dial(network, addr string)` method
  (go-imap v1's `Dialer` interface) calls `allowHost` before the inner
  `net.Dialer` opens anything.
- TLS config: `RootCAs` from the exported Bridge certificate when `ca_cert` is
  non-empty (an unreadable or unparsable PEM falls through to the system trust
  store rather than panicking startup, matching SilverBullet), and `ServerName`
  set to the SAN reported in Task 1 so hostname verification passes against a
  certificate that was issued for Bridge's loopback address but is being reached
  through a LAN forwarder. Do not disable certificate verification wholesale, and
  do not name the verification-skipping TLS option anywhere in this file including
  comments — a mechanical gate greps for it.
- Timeouts are mandatory, not optional: a 10s dial timeout for sync work, a 5s
  dial timeout for Health, and `c.Timeout` set on every returned client so a
  single IMAP round trip cannot block forever. Nothing in the kernel wraps the
  Health RPC in its own timeout.
- Expose the dial step as an unexported struct field of function type on
  `Client`, defaulting to the real TLS dial, so plan 03-02's transcript test can
  substitute a plaintext connection to a local fake server without changing any
  production path.
- Credential discipline: never include the password in an error string, a log
  line, or a `HealthResponse.LastError`. Wrap Login failures with the operation
  name and the server's own message only.

`plugins/proton/plugin.go`: the `sdk.SourcePlugin` implementation.
- Constants `sourceType = "proton"`, `displayName = "Proton Mail"` (03-UI-SPEC.md
  Copywriting Contract), `contractVersion = "webspaces.v1"`, and a rune-based
  preview cap mirroring SilverBullet's `previewRuneCap`.
- `Match`: return an empty response immediately for zero keywords. Otherwise open
  one connection, `List("", "*")` the mailboxes, and select the mailboxes whose
  leaf name (the segment after the last hierarchy delimiter, so `Labels/House Move`
  has leaf `House Move`) case-insensitively equals one of the keywords. For each
  matched mailbox call `Select(name, true)` — the readOnly argument is what makes
  go-imap issue EXAMINE rather than SELECT — then fetch `imap.FetchEnvelope`,
  `imap.FetchInternalDate` and `imap.FetchUid` over the whole mailbox.
- Dedup, per 03-RESEARCH.md Pattern 2: accumulate into a map keyed by the
  normalized Message-ID (trim whitespace, then trim one leading `<` and one
  trailing `>`). On a first sighting record the envelope, the uid and the mailbox
  name; on a repeat sighting append the new mailbox's leaf name to that entry's
  label list without overwriting anything, deduplicating labels. A message whose
  normalized Message-ID is empty is skipped and counted; report the skip count in
  the Match log line. Relying on the index's ON CONFLICT upsert instead of merging
  here is not sufficient — it prevents duplicate rows but silently discards the
  label list of every earlier sighting.
- Item shape per match: `SourceId` is the Task 2 encoding of the normalized
  Message-ID and encodes nothing else; `Title` is the envelope subject (falling
  back to a fixed no-subject placeholder when empty); `TimestampUnix` is the
  INTERNALDATE as Unix seconds with the envelope Date as
  `SecondaryTimestampUnix`; `GroupLabel` is the formatted first From address
  (personal name when present, otherwise mailbox@host) and `GroupId` is that
  address; `Labels` is the merged matched-label list; `Preview` is empty at this
  stage (Match must not open message bodies — a body read per message during sync
  would multiply the sync cost by the mailbox size); `HasThumbnail` is false;
  `Fidelity` is `LinkFidelity_LINK_FIDELITY_ANCHORED` and `DeepLink` is the
  configured webmail base joined with the escaped slug of the first matched
  mailbox's leaf name. ANCHORED is the correct declared value, not a placeholder:
  no verified mapping exists from an IMAP Message-ID or UID to Proton's internal
  webmail message id, and a fabricated per-message URL would open the wrong
  message or 404. `Provenance` carries the same five keys the other plugins set:
  source_type, source_system (the configured base_url), source_id, plugin
  ("webspaces-plugin-proton") and contract_version.
- Maintain an in-process map from source_id to the mailbox name the message was
  first found in, rebuilt on every Match. Fetch consults it; a miss returns
  `codes.NotFound` with a message saying the index has not been synced since this
  plugin started. This is sound because the kernel launches plugin subprocesses
  once at startup and only kills them at shutdown, and the scheduler runs a sync
  before the UI can show any item to click.
- `Fetch`: switch on the variant exactly as SilverBullet does — FULL and PREVIEW
  share one path, THUMBNAIL is always unavailable with a fixed reason string,
  unspecified is `codes.InvalidArgument`. The FULL path resolves the mailbox from
  the cache, opens it with `Select(name, true)`, resolves the current UID by
  `Uid Search` on `HEADER Message-Id` with the reconstructed angle-bracketed
  Message-ID (never a cached UID: UIDs are only meaningful within one selected
  mailbox and are reassigned when UIDVALIDITY changes), then fetches the body
  through an `imap.BodySectionName` with `Peek` true. `Peek` is what serializes
  the request as BODY.PEEK instead of BODY, and is the mechanism that stops the
  server implicitly setting the \Seen flag. Return the extracted plain-text part
  in `FetchResponse.Text` with `Available` true; leave `MimeType` and `Data`
  unset in this plan.
- `Health`: open a connection with the 5s dial timeout and 5s command timeout,
  Login, Logout. Any failure returns `HealthResponse{Reachable: false, LastError:
  <specific message naming the address and the failing step>}` and a nil error —
  never a gRPC error, matching the other plugins.
- Error mapping throughout: `errors.Is(err, ErrNotFound)` in Match means "this
  mailbox or message vanished between LIST and FETCH", which is a safe per-item
  skip; every other error fails the whole Match with
  `status.Errorf(codes.Unavailable, "proton: <op>: %v", err)`. Returning an empty
  successful MatchResponse for a genuine outage is what caused the 02-05 gap: the
  kernel then replaces the source's rows with nothing and records the run as ok.

`plugins/proton/body.go`: MIME extraction only in this plan. Use

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| desktop kernel -> LAN forwarder -> Proton Mail Bridge | Untrusted network hop carrying IMAP credentials and full message content, protected only by a self-signed certificate reached through an address that certificate was not issued for |
| Bridge/IMAP server -> proton plugin subprocess | All mailbox names, envelopes and message bytes are attacker-influenced input (anyone can send this mailbox a message) |
| proton plugin -> kernel index | Plugin-supplied `Item` values cross into persisted kernel state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing / Tampering | `plugins/proton/client.go` TLS setup | high | mitigate | `RootCAs` pinned to the exported Bridge certificate plus a `ServerName` override matching the certificate's real SAN; full chain and expiry verification retained; certificate verification is never disabled wholesale |
| T-03-02 | Spoofing / Tampering | `plugins/proton/client.go` STARTTLS path | high | mitigate | `imap://` performs a mandatory `StartTLS` whose failure aborts the connection; no code path calls `Login` on a connection that did not complete TLS, and there is no plaintext fallback |
