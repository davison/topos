<objective>
Promote the config map key to be the kernel's source identity (D-08). Today `source_type` — the plugin kind the kernel learns from `Describe` — doubles as the identity key for item ids, `items`/`sync_runs` rows, agent grants, and every HTTP JSON response, so two instances of one plugin binary would silently share one identity. This plan splits the two concepts apart: a new `source` (instance id) carries identity everywhere, and `source_type` keeps its existing, unchanged meaning of "which plugin kind is this".

Purpose: KERN-06. Without this, "Home email" and "Work email" conflate their items, their sync history, and — the security-relevant case — their agent grants.
Output: an instance-keyed kernel spine, an instance-keyed HTTP/agent surface, a UI that reads instance identity, and an index that rebuilds itself on the schema change (D-07).
</objective>

<assumption_delta_decision>
The `assumption-delta scan` fired on this phase with `pluralization` ("configured multiple times") and `chosen` ("user-chosen display names") signals.

- **Primary noun:** the **source instance** — an entry under `[sources.<id>]`, identified by its TOML map key.
- **Decision:** `promote`. The generalized noun becomes primary everywhere identity is required (index rows, sync runs, agent grants, HTTP responses, UI labels). The previously-singular noun, `source_type`, is **demoted** to a descriptive attribute of one instance ("which plugin kind runs here"), retained for provenance, vocabulary lookup, and contract-version checks. This is deliberately *not* add-alongside: no kernel key remains `source_type`-valued after this plan.
- **Invariant test (accepted, wired into Task 1):** `TestTwoInstancesOfOnePluginType_StayDistinct` in `kernel/syncer/coordinator_test.go` goes red the instant a future phase reintroduces the singular assumption anywhere on the sync/index/grant path.
