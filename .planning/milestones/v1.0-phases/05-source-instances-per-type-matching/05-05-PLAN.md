`docs/plugin-contract.md`:
  - `Handshake and the plugin-map key`: state the new `ProtocolVersion` value, why it moved (a plugin built against the previous generation must fail at handshake, never at its first Match), and how it relates to `DescribeResponse.contract_version`.
  - `Discovery and launch`: state explicitly that the kernel may launch the same plugin binary several times, once per `[sources.<id>]` entry, each with its own `WEBSPACES_SOURCE_CONFIG`; that the config map key is the instance identity the kernel uses for index rows, sync history, agent grants and API responses; and that a plugin never learns, asserts, or needs its instance identity — it still declares only its `source_type` (T-01-07 unchanged).
  - `Describe`: document `match_vocabulary` — what it is for, that the kernel validates operator config against it and fails startup by name on an unknown field, that a plugin declaring an empty vocabulary cannot participate in matching, and the four in-repo examples shown as illustrations rather than a closed set.
  - `Match`: document the `match_fields` map and the `StringList` wrapper, the exact/case-insensitive/no-normalization rule (D-04), the requirement that a plugin ignore a key it did not declare, and the semantics of an empty value list. State that a Match request carries only that one instance's own resolved fields.
  - `Fetch`: document `content_shape`, that `data` is now an unwrapped, unthemed, unsanitized fragment for HTML content, that the kernel sanitizes and themes it at its own content boundary, that a plugin must not emit a full HTML document or its own stylesheet, and that an HTML rendition with an unspecified shape is refused by the kernel.
  - `Build your first plugin`: update the walkthrough and every code excerpt so it compiles against the shipped SDK, and cross-check each excerpt against `plugins/mock/plugin.go`.
  - `What this document does not cover`: remove anything this phase now covers.

`docs/api.md`: complete the surface plan 05-01 started — document the `unsupported_content_shape` error code in `Error codes`, describe the kernel-side wrapping and theming behaviour under `GET /api/items/{id}/content`, and state under the `/agent/v1` section that grants are per instance and that two instances of one plugin type are granted independently.

`README.md`: update any statement about a shared per-webspace keyword list or per-plugin theming that this phase has invalidated.
