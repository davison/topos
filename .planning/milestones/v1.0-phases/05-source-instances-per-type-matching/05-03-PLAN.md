`kernel/config/types.go`: add `type MatchBlock map[string][]string` documented as "field name (from the plugin's declared vocabulary) to exact, case-insensitive values (D-04)". Change `Webspace` to `{ Keywords []string toml:"keywords"; Sources []string toml:"sources"; Match map[string]MatchBlock toml:"match" }`, with doc comments stating: `Keywords` is the optional fallback applied to every field of a participating instance's declared vocabulary; `Sources` is the optional participation allowlist, empty meaning all configured instances participate; `Match` is keyed by instance id and an explicit block replaces the fallback outright for that instance. Add `func (w Webspace) Participates(instance string) bool`.

`kernel/config/config.go`: rewrite the webspace half of `Validate` as structural, plugin-independent checks in sorted deterministic order (sort webspace names, then instance names, then field names within a block — Go map iteration order must never decide which error the operator sees first).   - a participating instance with no explicit block, in a webspace whose `keywords` list is empty, fails, naming the webspace and the instance and pointing at both shapes (D-06's "clear error pointing at the documented new shape").

`kernel/correlate/correlate.go`: extend `matchFieldsFor(ws config.Webspace, src Source) (map[string][]string, bool)` to the full D-01/D-02/D-03 resolution — allowlist check first (returning `false`), then an explicit `ws.Match[src.Name()]` returned verbatim, then the fallback fanned across `src.MatchVocabulary()`. Add the second validation phase D-05 requires. It cannot live in `config.Validate`, which is deliberately plugin-independent and runs before any subprocess exists (05-RESEARCH.md Pitfall 1); it belongs beside the launched `*Host`.

Create `kernel/pluginhost/matchconfig.go` with `func ValidateMatchConfig(cfg *config.Config, h *Host) error`. Build an instance-id-keyed index of launched plugins from `h.Plugins()`. Iterate webspaces in sorted name order; within each, iterate `ws.Match` keys in sorted order; within each block, iterate field names in sorted order. For each field, check membership in that instance's `MatchVocabulary()`. On failure return, mirroring `config.Validate`'s idiom:
`config: webspace %q match block for source %q declares unknown match field %q — plugin %q (source_type %q) declares: [%s]` with the declared vocabulary joined by ", " (or the literal none when it is empty).

Also fail when: a `match` block names an instance with no launched plugin (naming the webspace and instance); or a participating instance relying on the `keywords` fallback has an empty declared vocabulary (naming the webspace, the instance and the plugin, and stating that the plugin declares no match fields for the fallback to apply to).

Wire it into `cmd/topos/main.go`'s `setup()` immediately after `pluginhost.Discover` returns and before `setup` returns, shutting the host down and closing the store on failure so a rejected config never leaves subprocesses running. Both `runServe` and `runSync` inherit the gate through `setup`.

Add `kernel/pluginhost/matchconfig_test.go` covering: the unknown-field case with an exact error-text assertion, the deterministic-ordering case (two offending fields across two webspaces, asserting the same error over repeated runs), the unlaunched-instance case, the empty-vocabulary-with-fallback case, and a passing case with a two-field vocabulary. Use a small fake plugin list rather than launching subprocesses.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config → kernel | the webspace match map is operator-authored input validated against a plugin-declared allowlist before any sync runs |
| kernel → index | a participation change must clear, not orphan, previously persisted rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-11 | Tampering | match-field validation (ASVS V5, positive allowlist) | high | mitigate | Field names are validated against the plugin's declared vocabulary and rejected by name at startup; a typo'd field can never degrade to "matches nothing" silently (D-05) |
| T-05-12 | Information Disclosure | webspace participation allowlist | high | mitigate | A de-allowlisted instance is skipped before `Match` is called and its rows are cleared, so a work webspace cannot keep serving a personal instance's already-indexed items after the operator excludes it |
| T-05-13 | Repudiation | non-deterministic validation error ordering | medium | mitigate | Sorted iteration over webspaces, instances and fields makes the reported error reproducible, so an operator debugging a rejected config sees a stable message |
| T-05-14 | Denial of Service | startup refusal on a rejected config | low | accept | Failing closed at startup is the intended behaviour for a single-user desktop tool (D-06); a running kernel is never taken down by this check |
</threat_model>
