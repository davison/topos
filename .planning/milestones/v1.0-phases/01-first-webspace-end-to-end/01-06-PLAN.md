<objective>
Close gap G-01-6 (minor): 01-01-PLAN.md classifies "MUST NOT transmit indexed item data, config file contents, or usage telemetry to any host other than the user's own configured paperless-ngx instance and the loopback interface" as `verification: test`, but no committed test enforces it. `plugins/paperless/readonly_test.go` restricts HTTP *methods*, not destination *hosts*. The user chose a committed allowlist test over downgrading the verification tier.

An honest test requires the guarantee to actually hold. Today it does not hold by construction: the plugin's `http.Client` sets no `CheckRedirect`, so Go's default policy would follow a cross-host redirect served by paperless-ngx — a compromised, spoofed, or misconfigured source could steer the plugin at an arbitrary host. So this plan does both halves: enforce the allowlist at the two points where an outbound connection can originate (redirect policy and dialer), then assert it with committed tests, plus a repo-wide static scan covering the kernel side, which makes no outbound requests at all and must stay that way.

Purpose: turn a prohibition backed only by manual grep into one backed by tests that fail the build the moment it stops being true.
Output: a host-pinned paperless client, a runtime allowlist test suite, a repo-wide AST audit with a non-vacuous negative control, and a traceable `verified_by` record in 01-01-PLAN.md.
</objective>

  <files>plugins/paperless/client.go, plugins/paperless/outbound_hosts_test.go</files>
  <behavior>
    Write these tests in plugins/paperless/outbound_hosts_test.go first, watch them fail, then implement:

    - Host predicate table: a client built against a given base URL permits that hostname (any letter case, any port), 127.0.0.1, ::1, and localhost; and refuses exfil.example.invalid, the non-loopback literal 203.0.113.5, and an empty host. Every refusal returns an error satisfying errors.Is(err, ErrForeignHost) and naming the refused host.
    - Cross-host redirect is refused: an httptest server standing in for paperless-ngx answers /api/documents/1/ with 302 and a Location on host exfil.example.invalid; Document(ctx, 1) returns an error satisfying errors.Is(err, ErrForeignHost). The assertion is on the sentinel specifically, not on "any error" — an unresolvable name would also produce an error, and only the sentinel proves the guard fired before the request left the process.
    - Same-host redirect is still followed: the server answers a path with 302 to the same path plus a trailing slash on its own host (paperless-ngx's Django APPEND_SLASH behavior) and serves a real document body there; Document succeeds and returns that document. The guard must not break legitimate redirects.
    - Redirect cap survives: a base-host endpoint that redirects to itself indefinitely makes Document return an error rather than looping forever, and the handler is hit no more than 11 times. Supplying a custom CheckRedirect replaces Go's built-in 10-redirect default, so the cap has to be re-implemented deliberately.
    - Foreign pagination next is re-pinned, not followed: a /api/documents/ page-1 response whose next field is an absolute URL on host exfil.example.invalid results in the page-2 request arriving at the same httptest server with the page=2 query intact, and ListDocuments returning documents from both pages.
    - The existing suites in client_test.go and fetch_test.go still pass untouched: they build clients against loopback httptest servers, which the allowlist permits.
  </behavior>
  <action>
    Harden plugins/paperless/client.go with a host allowlist, keeping NewClient's three-string signature (plugin.go's NewSourcePlugin depends on it).

    Add an exported sentinel error ErrForeignHost, in the style of the file's existing ErrNotFound.

    In NewClient, parse baseURL with url.Parse and store the lowercased Hostname() in a new unexported Client field alongside the existing baseURL/token/apiVersion fields. If parsing fails or the hostname is empty, leave that field empty so the predicate below permits loopback only — fail closed, since a malformed base_url must never widen the allowlist.

    Add an unexported predicate method on Client that takes a host string and returns an error: it strips any port and IPv6 brackets, lowercases, and permits the value when it equals the stored base hostname, when net.ParseIP reports a loopback address, or when it is the literal localhost; otherwise it returns an error wrapping ErrForeignHost and naming the refused host. Port is deliberately outside the comparison — the configured host is the user's own instance and a reverse proxy legitimately moves between ports (80 to 443) on that same host; the prohibition is about foreign hosts, not foreign ports. Say that in a comment so the next reader does not "tighten" it into a false failure.

    Wire the predicate into both places an outbound connection can originate:
      - the transport's DialContext: keep MaxConnsPerHost at 4, wrap a net.Dialer with a connection timeout, split the address with net.SplitHostPort, and return the predicate's error without dialing when it refuses;
      - the client's CheckRedirect: refuse when the predicate refuses the next request's hostname, and also refuse once the via slice reaches ten entries, restoring the redirect cap that installing a custom CheckRedirect removes.

    Two hooks rather than one is deliberate: CheckRedirect stops the common, source-controlled case before a connection is opened, and DialContext is the backstop that catches any future call site in this file that forgets the rule.

    Change no request-building code: the three http.NewRequestWithContext call sites, splitNextURL's re-pinning of absolute next URLs, and every method signature stay as they are. Follow client_test.go's fixture-server helper style rather than inventing a different one.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| paperless-ngx response → plugin control flow | Redirect Location headers and pagination `next` URLs are attacker-influenceable data that can steer the plugin's next outbound request |
| plugin process → network | The only egress point in the whole system; it carries the API token in an Authorization header |
| kernel process → network | Must have no egress at all: the kernel holds config contents, the index, and item metadata |
| repository → future contributors | A new outbound call site added later would silently widen the egress surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06-01 | Information disclosure | plugins/paperless/client.go redirect handling | high | mitigate | Task 1 installs a CheckRedirect that refuses any hop to a non-base, non-loopback host before the request is issued; proven by the errors.Is(ErrForeignHost) test |
| T-01-06-02 | Spoofing | Authorization token on a cross-host hop | high | mitigate | Same guard: the hop never happens, so the token cannot reach a foreign host regardless of Go's own cross-domain header-stripping behavior; no test or log line ever prints the token (D-04) |
| T-01-06-03 | Tampering | pagination `next` URL from the source | medium | mitigate | splitNextURL's existing re-pinning becomes a committed guarantee via the foreign-next-URL test, with the dialer guard as backstop |
| T-01-06-04 | Elevation of privilege | future outbound call site anywhere in the repo | medium | mitigate | Task 2's AST audit fails the build on outbound HTTP construction outside plugins/paperless/client.go and on any foreign absolute URL literal in shipped code |
| T-01-06-05 | Denial of service | custom CheckRedirect removing Go's redirect cap | low | mitigate | The cap is re-implemented explicitly at ten hops and asserted by a redirect-loop test |
