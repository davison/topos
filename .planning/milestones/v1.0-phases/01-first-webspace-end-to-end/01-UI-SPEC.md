**Status:** No `web/` directory exists yet (greenfield repo — confirmed via codebase scout, no `package.json`/`components.json` anywhere in the tree). `shadcn_initialized: false` above is accurate as of this spec; the executor must run the init sequence below as part of Phase 1 scaffolding, not before.

### Init sequence (executor runs this once, before building any UI component)

```bash
# 1. Scaffold the SvelteKit app (TypeScript, no extra options needed beyond defaults)
npx sv create web
cd web

# 2. Tailwind CSS v4 (Vite plugin form, not the old PostCSS config)
npm install -D tailwindcss @tailwindcss/vite
# In vite.config.ts: add `tailwindcss()` to the plugins array
# In src/app.css: `@import "tailwindcss";`

# 3. shadcn-svelte init — when prompted, answer:
#    base color: slate | style: new-york | CSS variables: yes
npx shadcn-svelte@latest init

# 4. Static adapter for go:embed (per 01-RESEARCH.md — SPA mode, fallback NOT index.html)
npm install -D @sveltejs/adapter-static@3.0.10
# svelte.config.js: adapter({ fallback: '200.html' })
# src/routes/+layout.js: export const ssr = false; export const prerender = false;

# 5. Components needed for Phase 1 (add only these — no more than the stream/detail surface requires)
npx shadcn-svelte@latest add button card badge skeleton scroll-area separator alert tooltip

# 6. Icons + font
npm install lucide-svelte
npm install @fontsource-variable/inter
```

**Dark-mode-only, no toggle:** add `class="dark"` directly to the `<html>` element in `src/app.html`. Do not install `mode-watcher` or ship a theme-switcher control — Phase 1 has exactly one visual mode.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tag pill inline padding |
| sm | 8px | Compact element spacing (between metadata fields in a stream row) |
| md | 16px | Default element spacing (row padding, form/section gaps) |
| lg | 24px | Section padding (detail pane content padding, header padding) |
| xl | 32px | Layout gaps (gap between stream pane and detail pane) |
| 2xl | 48px | Major section breaks (empty-state vertical centering) |
| 3xl | 64px | Page-level spacing (top-level page padding on wide viewports) |

Exceptions: Icon-only buttons (e.g. a collapsed "open in source" icon affordance, if used instead of a labeled button) get a 44px minimum touch target via padding, even though the icon itself renders at 16–20px — accessibility floor, not a scale violation.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Exactly 2 weights used project-wide: **400 (regular)** for body/label text, **600 (semibold)** for headings, item titles, and the display/page title. No other weights (no light, no bold-800+) are introduced in Phase 1.

Usage mapping:
- **Display (28px/600):** webspace page title (e.g. "house-move") in the top header
- **Heading (20px/600):** stream item title, detail pane document title
- **Body (16px/400):** preview snippet text, extracted document text in the detail pane
- **Label (14px/400):** timestamps, tag pills, metadata row (date, source badge), button labels

## Color

Dark-mode-only palette (Tailwind slate scale as the neutral base):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020617` (slate-950) | Page background, stream pane background, empty negative space |
| Secondary (30%) | `#0f172a` (slate-900), border `#1e293b` (slate-800) | Stream item cards, detail pane surface, top header/nav bar |
| Accent (10%) | `#60a5fa` (blue-400) | Links, "Open in source" CTA, focus rings, active/selected stream row indicator |
| Destructive | `#f87171` (red-400) — reserved, not exercised in Phase 1 | Destructive actions only (none exist in Phase 1's read-only viewer; reserved for future phases) |

Text colors (not primary/secondary/accent roles but required for contrast on the dark palette): primary text `#f1f5f9` (slate-100), secondary/meta text `#94a3b8` (slate-400).

Accent reserved for: the "Open in source" button, inline text links, focus-visible outline/ring on any focusable element, and the current/selected stream-row left-border indicator. **Not** used for tag pills, section headers, or general iconography — those stay in the secondary/neutral palette so the accent stays a genuine 10% signal.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved (probe engine run 2026-07-27 over 5 elements, 22 applicable): 17 covered, 1 backstop, 4 dismissed (with reasons), 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | list-collection: stream list | ✅ covered | Empty state renders the heading and body copy from Copywriting Contract when no items match the webspace's keywords. |
| loading | list-collection: stream list | ✅ covered | Initial stream load shows a skeleton list (3–5 placeholder rows matching item-card dimensions) until the first sync completes; subsequent navigations read from the local index and render near-instantly. |
| error | list-collection: stream list (kernel API unreachable) | 🧪 backstop | Stream fetch failure shows the "Couldn't load this webspace" message + retry button (see Copywriting Contract "Stream-load error" row) — held out because the kernel and SPA share one process, making this state rare and hard to exercise without a wired fault-injection test. |
| populated | list-collection: stream list | ✅ covered | Each row renders: leading thumbnail (paperless `/thumb/` endpoint, 40×52px, document-icon placeholder if unavailable), title, formatted date, tag pills, and a truncated preview snippet, ordered chronologically (`created` primary, `added` tie-break per 01-RESEARCH.md Pitfall 4). |
| partial | list-collection: stream list | ✅ covered | An item missing a thumbnail (fetch failure or unsupported type) renders a generic document icon instead of a broken image; an item with no preview text renders title + metadata only — never a blank or visually broken row. |
| overflow | list-collection: stream list | ✅ covered | The stream list scrolls independently within its own pane; it never affects the detail pane's scroll position. No horizontal overflow — row content wraps or truncates per the long-text rule below. |
| zero-one-many | list-collection: stream list | ✅ covered | Zero items → empty state. One item → single full-width row, no pagination chrome. Many items → constant row height/spacing regardless of count, no artificial cap in Phase 1 (virtualization deferred unless volume demands it). |
| long-text | static-content: item title / preview snippet (in stream row) | ✅ covered | Item title truncates to one line with ellipsis; preview snippet clamps to 2 lines with ellipsis (CSS line-clamp). Full text is available by opening the detail pane. |
| loading | media: detail pane document preview | ✅ covered | Detail pane opens immediately with locally-indexed metadata (title, tags, date) rendered instantly; the live-fetched preview area shows a skeleton/placeholder while the kernel proxies the paperless-ngx fetch. |
| error | media: detail pane document preview | ✅ covered | A failed live fetch renders the approved error copy (see Copywriting Contract "Error state" row) in place of the preview; metadata and the "Open in paperless-ngx" deep link remain usable regardless. |
| populated | media: detail pane document preview | ✅ covered | Populated detail pane shows title, date, tag pills, an embedded preview (PDF via `<embed>`/`<iframe>` against paperless `/preview/`, images via `<img>`), extracted text, and the "Open in paperless-ngx" CTA with its fidelity badge (exact). |
| overflow | static-content: detail pane extracted text | ✅ covered | Extracted text scrolls within its own contained region inside the detail pane; it never pushes page layout or affects the stream pane's scroll position. |
| long-text | static-content: detail pane extracted text | ✅ covered | Extracted text wraps naturally with no truncation — this is the primary content the pane exists to show. Only stream-row previews truncate, not the detail pane's full text. |
| long-text | interactive-control: "Open in source" button | ✅ covered | CTA label is a fixed static string ("Open in paperless-ngx"), never user-generated content, so no truncation/wrap handling beyond standard button padding is needed. |
| empty | media: detail pane document preview | ✅ covered | When paperless-ngx has no previewable rendition for the file type, the preview region falls back to the extracted text plus a generic document icon — never a broken embed. |
| overflow | media: detail pane document preview | ✅ covered | The embedded preview is sized to the detail pane's preview region; PDF embeds scroll internally within that region and never push the pane layout or affect the stream pane's scroll. |
| long-text | media: detail pane document preview | ➖ dismissed | Media preview is not a text surface; long-text handling belongs to the extracted-text rows above. |
| overflow | interactive-control: "Open in source" button | ➖ dismissed | Fixed static label with standard button padding, no user-generated content — same rationale as its long-text row. |
| loading | nav: top header (webspace title) | ➖ dismissed | The webspace title renders synchronously from route/config state; no async load state exists for the header. |
| error | nav: top header (webspace title) | ➖ dismissed | The header renders from local route state; API failure states surface in the stream-load error (backstop row), not in the header. |
| overflow | nav: top header (webspace title) | ✅ covered | The webspace title truncates to one line with ellipsis at the header's available width. |
| long-text | nav: top header (webspace title) | ✅ covered | Webspace names are user-defined config keywords and may be arbitrarily long — same one-line ellipsis rule; the full name is exposed via a tooltip/title attribute. |
