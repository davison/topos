<objective>
Add the second slice of the phase: opening an item. A click on a stream row produces a detail pane that renders locally-indexed metadata instantly, then fills with content fetched live from paperless-ngx through the plugin — proving the hybrid store's read side (KERN-03) — and carries a working, fidelity-declared deep link back to the source (PLUG-03, UI-04).

Purpose: this is the boundary that makes the hybrid data model real. Everything the stream shows comes from the local index; everything the pane shows beyond metadata comes from the source, live, at open time. Getting the split wrong here would either duplicate personal content locally or make the stream depend on network latency.

Output: `GET /api/items/{id}`, `/content` and `/thumbnail` routes backed by the plugin's streaming `Fetch`, and a detail pane implementing every UI-SPEC state for the document preview surface.
</objective>

**Plugin RPC (already in `proto/webspaces/v1/plugin.proto`, locked one-way in 01-01):**

```protobuf
rpc Fetch(FetchRequest) returns (stream FetchChunk);

message FetchRequest { string source_id = 1; ContentVariant variant = 2; }

enum ContentVariant {
  CONTENT_VARIANT_UNSPECIFIED = 0;
  CONTENT_VARIANT_FULL        = 1;   // extracted text + inline rendition
  CONTENT_VARIANT_PREVIEW     = 2;   // rendition bytes only
  CONTENT_VARIANT_THUMBNAIL   = 3;   // thumbnail bytes only
}

message FetchHeader {
  bool   available            = 1;
  string unavailable_reason   = 2;
  string mime_type            = 3;   // "" when there is no binary rendition
  int64  size_bytes           = 4;
  string text                 = 5;   // extracted text, may be ""
  map<string, string> provenance = 6;
}
message FetchChunk { oneof chunk { FetchHeader header = 1; bytes data = 2; } }
```

The stream carries exactly one `header` chunk first, then zero or more `data` chunks.

**Kernel JSON envelope this plan adds (same shape family as 01-01's stream response):**

```
GET /api/items/{id}
  200 {"schema_version":1,
       "item":{ ...identical object to a stream item, incl. link{url,fidelity} and provenance... },
       "content":{"available":true,"unavailable_reason":"",
                  "text":"full extracted text …",
                  "rendition":{"mime_type":"application/pdf","size_bytes":184320,
                               "url":"/api/items/paperless:42/content"}}}
  200 {"...","content":{"available":false,"unavailable_reason":"no previewable rendition",
                        "text":"…","rendition":null}}
  404 {"schema_version":1,"error":{"code":"item_not_found","message":"…"}}
  502 {"schema_version":1,"error":{"code":"source_unavailable","message":"…"}}

GET /api/items/{id}/content    -> raw rendition bytes, Content-Type from the plugin header
GET /api/items/{id}/thumbnail  -> raw thumbnail bytes
```

**paperless-ngx live endpoints (verified in 01-RESEARCH.md against `main`, 2026-07-27):**

```
GET {base}/api/documents/{id}/           -> detail incl. full extracted `content`
GET {base}/api/documents/{id}/preview/   -> inline rendition
GET {base}/api/documents/{id}/thumb/     -> thumbnail
Headers: Authorization: Token <token>  |  Accept: application/json; version=10
```

Implement the streaming `Fetch` RPC in the paperless plugin and expose it through three kernel routes. Replace the `codes.Unimplemented` return from plan 01-01 — no stub survives this task.

**Plugin side.** Add `Client.Document(id)` fetching `GET {base}/api/documents/{id}/` for the full extracted `content` field, and `Client.Rendition(id, path)` performing a streaming `GET` of `{base}/api/documents/{id}/preview/` or `/thumb/` and returning the response body reader plus its `Content-Type` and `Content-Length`. Both use the existing shared `http.Client` with its 4-connection bound and 30-second timeout, and both use the GET method — no other HTTP method appears anywhere in this file.

`Fetch` dispatches on the requested variant. For the full variant, send one header chunk carrying `available` true, the extracted text, the rendition MIME type and size, and the provenance map, then stream the preview rendition body in chunks of at most 64 KiB. For the preview and thumbnail variants, send the header then only that rendition's bytes. When paperless returns 404 for a rendition, send a header with `available` false and `unavailable_reason` set to a short human-readable string (for example `no previewable rendition`) and no data chunks — this is a normal outcome, not an error, and the pane falls back to extracted text. When paperless is unreachable or returns 5xx, return a gRPC error with `codes.Unavailable` and a message that names the failure without including the token or the `Authorization` header. When the document id is unknown to paperless, return `codes.NotFound`.

**Kernel side.** Extend `pluginhost` with a `Fetch(ctx, sourceType, sourceID, variant)` wrapper that opens the server stream, reads the single header chunk, and returns the header plus an `io.ReadCloser` over the remaining data chunks so the kernel never buffers a whole rendition in memory. Map gRPC status codes to kernel errors: `NotFound` to a not-found error, `Unavailable` to a source-unavailable error.

Create `kernel/httpapi/item.go` with three handlers registered in `routes.go`. `GET /api/items/{id}` splits the composite id on the first colon into source type and source id, loads the item row from the index (404 with the `item_not_found` error envelope if absent), calls the plugin with the full variant, and returns the JSON in this plan's interfaces block — the item object identical in shape to a stream item, plus a `content` object. A source-unavailable failure returns 502 with the `source_unavailable` error code; it must not return 200 with a silently empty content object. `GET /api/items/{id}/content` and `GET /api/items/{id}/thumbnail` stream the rendition bytes straight through with `io.Copy`.

**Security on the content routes (this is the sharpest surface in the phase).** These routes serve source-controlled bytes from the app's own origin, so an HTML or SVG rendition would run script against the kernel API. Before writing any body, reject any MIME type not on an allowlist of `application/pdf`, `image/png`, `image/jpeg`, `image/gif` and `image/webp` with a 415 and the error envelope. On every accepted response set `Content-Type` to the allowlisted value only, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`, `Content-Security-Policy: default-src 'none'; object-src 'none'; sandbox`, and `Cache-Control: private, no-store`. Never echo a plugin-supplied MIME string into the header without matching it against the allowlist first.

**Validation moved to the sync path.** In the correlation engine, reject any item arriving from a plugin whose fidelity is the unspecified enum value or whose deep link is empty: skip it, and return an error naming the plugin and the source id so the sync run records it. Such items must never reach the index.

**Tests.** Table-test `Fetch` against an `httptest` server for: a full fetch with both text and rendition, a document with empty extracted content, a 404 rendition producing an unavailable header with no data chunks, and an unreachable source producing `codes.Unavailable`. Test the kernel routes for: 404 on an unknown id, 502 on source-unavailable, the exact security headers on a content response, a 415 rejection of a disallowed MIME type, and that both `paperless:42` and `paperless%3A42` resolve to the same item.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → kernel content routes | The kernel serves source-controlled bytes from its own origin into an embed/iframe. |
| kernel → plugin subprocess (streaming Fetch) | Request-time, user-triggered RPC returning attacker-influenceable bytes and MIME strings. |
| plugin → paperless-ngx rendition endpoints | LAN hop returning arbitrary binary content and headers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Elevation of Privilege | `GET /api/items/{id}/content` serving source bytes same-origin | high | mitigate | MIME allowlist (`application/pdf`, `image/png`, `image/jpeg`, `image/gif`, `image/webp`) enforced before any body is written; anything else returns 415. Every accepted response carries `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`, and `Content-Security-Policy: default-src 'none'; object-src 'none'; sandbox`. |
| T-01-11 | Elevation of Privilege | source-controlled title / OCR text rendered in the detail pane | high | mitigate | Svelte escapes all interpolated text; `{@html}` is absent from the pane and asserted so by an acceptance criterion. |
| T-01-12 | Information Disclosure | error text from a failed live fetch surfacing credentials or internal URLs | medium | mitigate | Plugin gRPC error messages name the failure class only; the kernel maps them to the fixed `source_unavailable` code and the SPA renders the approved static copy rather than the raw message. |
| T-01-13 | Denial of Service | a very large rendition buffered in kernel memory | medium | mitigate | The plugin streams in 64 KiB chunks and the kernel `io.Copy`s straight through — no full-rendition buffering on either side. |
| T-01-14 | Tampering | an item reaching the index with an empty or attacker-chosen deep link | medium | mitigate | The correlation engine rejects any item with an unspecified fidelity or an empty deep link, naming the plugin and source id in the recorded sync error. |
| T-01-15 | Information Disclosure | rendition bytes cached by the browser or an intermediary | low | mitigate | `Cache-Control: private, no-store` on every content and thumbnail response; the kernel is loopback-only so no intermediary exists in Phase 1. |
| T-01-SC | Tampering | dependency installs during this plan | high | mitigate | No new Go or npm dependency is introduced by this plan beyond the shadcn-svelte components already added and audited in 01-01. If any install becomes necessary, re-run the `01-RESEARCH.md` Package Legitimacy Gate before adding it. |
