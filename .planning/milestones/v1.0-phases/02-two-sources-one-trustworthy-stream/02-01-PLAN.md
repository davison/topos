<objective>
Make the stream genuinely cross-source: a SilverBullet page and a paperless-ngx
document sit next to each other in one chronological list, each opening in the
detail pane with content fetched live from its own source.

This is the phase's tracer. It is deliberately the first thing built because it
forces the one architectural correction the rest of Phase 2 depends on: Phase 1's
sync path was written for exactly one source, and it is *actively wrong* for two
(see `02-RESEARCH.md` "Critical Architecture Finding"). `correlate.Engine.SyncAll`
skips persisting a webspace entirely if *any* source's `Match` errors, and
`Store.ReplaceWebspaceItems` replaces a webspace's whole item set regardless of
which source triggered the write. With one source those were correct; with two,
a healthy source's fresh items get thrown away whenever its sibling is offline.

The identity that owns a sync is therefore **promoted** from `webspace` to
`(webspace, source_type)`. `ReplaceWebspaceItems` is replaced outright rather than
kept alongside a new per-source path — an add-alongside would leave a second,
still-wrong write path for Phases 3-5 to inherit.

Purpose: prove the plugin contract is genuinely source-agnostic (documents vs.
wiki pages) and land the per-source persistence every later plugin builds on.
Output: a working `plugins/silverbullet` module, a source-scoped index write
path, a source-major correlation loop, and a detail pane that renders sanitized
page markdown.

Locked decisions this plan implements (from `02-CONTEXT.md`):
**D-01** one page = one item, source id is the page path without the extension,
exact-fidelity deep link to `{base_url}/{page-path}`; **D-02** chronological order
driven by the page's last-modified timestamp from the `/.fs` listing, with the
created timestamp as the secondary tie-break; **D-03** exact case-insensitive
keyword matching against both tags (frontmatter and inline) and page name (full
path and final segment, extension stripped), either match including the page;
**D-04** hybrid-model preview (page name as title, frontmatter-stripped plaintext
snippet, tags as badges) with the detail pane rendering sanitized markdown fetched
live.
</objective>

## Flagged Assumptions (unresolved probe rows)

The spec-less edge probe returned `SRC-05` as **`unclassified` / `unresolved`** —
no shape category could be assigned automatically. It is surfaced here rather
than dropped. The planner's reading, which the executor should treat as the
working assumption and flag if reality differs:

- **A-SRC-05:** SilverBullet's `/.fs` listing is the only enumeration surface;
  there is no server-side tag or name filter, so matching is a client-side pass
  over every markdown page's body on every sync. Sync cost therefore scales with
  total space size, not with matched-item count. This is accepted for this phase
  (RESEARCH.md Pitfall 2); incremental `lastModified`-based skipping is a later
  optimization, not scope here.

Three research assumptions (`02-RESEARCH.md` Assumptions Log A1/A2/A3) are
resolved by Task 1's first step against the user's real instance rather than
carried forward: the `/.fs` envelope shape (bare array vs. wrapped object), the
absence of a filter query parameter, and bearer-token auth.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SilverBullet instance → plugin subprocess | Page bodies are user-authored content of arbitrary shape; they may contain HTML, scripts, or hostile links, and the instance itself may be misconfigured or spoofed. |
| plugin subprocess → kernel (gRPC) | The plugin supplies MIME types, deep links, provenance and rendition bytes the kernel must not trust blindly. |
| kernel `/api/items/{id}/content` → browser | Source-controlled bytes served from the kernel's own loopback origin. |
| config/env → plugin subprocess | `SB_AUTH_TOKEN` crosses into the subprocess environment. |
