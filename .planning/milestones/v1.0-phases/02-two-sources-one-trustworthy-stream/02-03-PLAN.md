<objective>
Make the stream *trustworthy*: at a glance the user can tell which sources are
feeding it, whether each is up, when it last synced, what broke, and whether what
they are looking at is everything or a filtered slice of it.

Phase 1's UI was written for exactly one always-present source, and it shows: the
header is a title and nothing else, and the detail pane's failure copy names
paperless-ngx in a literal string that a SilverBullet failure would print verbatim
and wrongly. This plan generalises those surfaces and adds the three that make a
multi-source view honest — health chips, a source filter, and explicit stale and
unavailable states.

Purpose: UI-02 (filter by source), UI-05 (explicit stale/unavailable states, never
a silent 404), UI-06 (sync status and plugin health visible).
Output: two new components, a generalised header, and staleness branches in the
stream and the detail pane — all composed from Phase 1's already-installed
shadcn-svelte primitives, with zero new registry blocks.

Locked decisions this plan implements (from `02-CONTEXT.md`):
**D-07** manual refresh is offered both per source (from the health UI) and as
refresh-all on the webspace header, with a non-blocking syncing indicator while a
run is in flight and a stream re-fetch on completion; **D-08** per-source health
lives in the webspace header as compact status chips (coloured dot plus source
name, green ok / amber stale or last error / red unreachable) with a tooltip
carrying the relative last-sync time and the last error, plus the per-source
refresh action, reusing the existing badge and tooltip components; **D-09** the
source filter is a chip row of All plus one chip per source, single-select and
toggling back to All, with the selection persisted in the URL query so reloads and
deep links preserve it; **D-10** staleness semantics — an unreachable source marks
its own rows and shows an explicit alert over the last-synced preview in the
detail pane, an item deleted at source shows an explicit no-longer-available state
over its cached preview, and Phase 1's rule that a failed sync never renders as an
empty webspace carries forward.
</objective>

## Flagged Assumptions (unresolved probe rows)

The spec-less edge probe returned `UI-02` and `UI-06` as
**`unclassified` / `unresolved`** — no shape category could be assigned
automatically. Surfaced here rather than dropped:

- **A-UI-02:** The filter is a **client-side** narrowing of the stream response
  already in memory, not a new backend query parameter — the whole webspace's
  items already arrive in one response, so filtering server-side would add a round
  trip and a second ordering contract for no benefit. Filter state lives in the
  URL query so it survives reload and deep-linking. If a future phase makes the
  stream paginated, this assumption stops holding and the filter must move
  server-side.
- **A-UI-06:** "Visible in the UI" means *ambient in the webspace header*, not a
  separate status page or a modal. Health is glanceable at all times while
  reading the stream; the tooltip carries the detail. A dedicated sync-status
  view is explicitly deferred (`UI-10`, v1.x).

```
GET  /api/sources                      -> { schema_version, sources: SourceStatus[] }

POST /api/sync                         -> { schema_version, results: RefreshResult[] }
GET  /api/webspaces/{ws}/stream        -> { schema_version, webspace, sync, items }   (sync now aggregates every source)
GET  /api/items/{id}                   -> { schema_version, item, content }
```

New TypeScript in `web/src/lib/api.ts`:

```typescript
export interface SourceStatus {
  name: string;            // config key
  source_type: string;     // matches StreamItem.source_type
  display_name: string;    // e.g. "paperless-ngx", "SilverBullet"
  reachable: boolean;
  syncing: boolean;
  last_status: '' | 'running' | 'ok' | 'error';   // '' = never run = unknown
  last_sync_unix: number;
  last_error: string;
}
export interface SourcesResponse { schema_version: number; sources: SourceStatus[]; }
export interface RefreshResult {
  source: string; source_type: string; status: 'ok' | 'error';
  item_count: number; error: string; coalesced: boolean;
  started_unix: number; finished_unix: number;
}
export function getSources(): Promise<SourcesResponse>;
export function refreshSource(name: string): Promise<{ schema_version: number; result: RefreshResult }>;
export function refreshAll(): Promise<{ schema_version: number; results: RefreshResult[] }>;
```
