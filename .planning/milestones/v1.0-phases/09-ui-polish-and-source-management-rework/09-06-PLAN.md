menu root where a single click reaches it, remove the duplicate "+" from the
create-webspace entry, and give Manage-sources instance rows the plugin icon

Manage-sources can render it.

instance rows.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → kernel | `POST /api/config/reload` re-reads and applies `config.toml`, replacing the running plugin set. Making it one click closer to the user changes how easily it can be invoked. |
| kernel → browser | The reload failure copy embeds the kernel's verbatim error message into the SPA. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-20 | Denial of Service | `Reload config` menu item | medium | mitigate | The action becomes reachable in one click instead of two, and it tears down and relaunches every plugin subprocess. Task 1 disables the item while a reload is in flight and Task 2's route handler guards re-entry, so it cannot be queued or spammed from the UI. The kernel's own Apply path is unchanged and already serialises. |
| T-09-21 | Information Disclosure | reload failure Alert | medium | mitigate | The kernel's verbatim error is rendered into the page, and a config error can quote a filesystem path or a config key. This is unchanged from the shipped modal's copy — the same string was already rendered, just in a different container — and topos is loopback-only and single-user. Rendered through Svelte's default text binding, never a raw-HTML directive, so a message containing markup cannot inject. |
| T-09-22 | Elevation of Privilege | route owns the reload call | low | accept | Ownership moves from a modal to the route; both are the same origin and the same authenticated (unauthenticated, loopback) context. No trust boundary is crossed by the move. |
| T-09-23 | Tampering | superseded D-13 assertion | low | mitigate | Loosening a test that encoded a locked rule is exactly how a guard silently rots. Task 1 requires the count assertion be updated in place with a comment naming the superseding authority, so the widening is auditable in the file itself rather than inferred from a diff. |
</threat_model>
