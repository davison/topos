<objective>
Make the advisory `12-09-PLAN.md` records actually reach the person who needs it. The kernel now
knows, and publishes, that a webspace's explicit match block matched none of a source's items; this
plan puts that fact on the source chip that was lying, and puts the rule on the form field where the
mistake was made.

**The surface that failed, and why it is this one.** In the reported failure the user's stream was
NOT empty — it held 97 paperless items. So no empty-state banner would ever have fired. The one
surface that was actively wrong was the `files` source chip: green dot, "synced 2 minutes ago",
contributing nothing. `format.ts`'s `healthTone` maps a source to `success` whenever it is reachable
and its last run status is `ok`, which was true. That chip is the fix's home, and it is why this plan
adds no stream-level treatment at all.

**Why the existing warning tone rather than a new one.** The dot vocabulary is
`success|warning|destructive|unknown`, each bound to a design token. `healthTone` already maps a
FAILED sync to `warning` rather than `destructive` — the amber tone in this system already means
"synced, but attend to this", which is precisely the advisory's meaning. A fifth tone would need a
new token, a UI-SPEC amendment and a `worstTone` rank entry for no gain a user could perceive.
The advisory reuses `warning` and gets its own tooltip branch, exactly as Phase 11's pin-mismatch
state did.

**Why the fifth branch and not a reworded one.** `09-UI-SPEC.md` Fix 3's Copywriting Contract is
enforced mechanically: `source-chip-tooltip.test.ts` reads `SourceChip.svelte`'s source and asserts
each of the four branch templates byte-for-byte. That guard must keep passing untouched — the
advisory is a new branch placed ahead of the tone switch, the same shape Phase 11 used for
`isPinMismatch`.

**Prevention, not only diagnosis.** `MatchFieldsForm.svelte` is the one form used by both add-source
flows and the chip menu's "Edit match settings…" modal — the field the user typed the glob-shaped
value into. Its helper text currently says only "Comma-separated. Matches if any value is present."
The debug session's `blind_spots` note flags this precisely: nobody checked whether the editor hints
at globs, and "if it hints at globs it compounds the trap." It does not hint at globs, but it also
never says values are literals. One sentence there closes the loop between the diagnosis (this
plan's chip) and the cause (the value being typed).

**No tracer task here, deliberately.** The end-to-end path this plan completes was traced by
`12-09-PLAN.md`'s own tracer task (correlate → sync_runs → `GET /api/sources`); Phase 12's
architectural tracer shipped in `12-01`. This plan is the client half of an already-proven path, and
its own end-to-end proof is Task 2's Playwright spec against a real kernel and a real plugin binary
— the project convention that any UAT item a browser can drive becomes a spec rather than a
remembered manual check.

Purpose: close the loop on G-12-1/G-12-3. `12-08` made the right value expressible and documented,
`12-09` made the wrong value observable, and this plan makes it visible without a debug session and
harder to type in the first place.

Output: one optional typed field, one branch in `healthTone`, one branch in `SourceChip`'s tooltip,
one sentence of helper text, two vitest guard files, and one Playwright spec that reproduces the
user's exact config in a browser.

## Non-goals (do not do these)

- Do NOT add a stream-level advisory, banner or empty-state variant. `StreamSyncDegraded` and
  `StreamEmpty` are untouched; see the objective for why they could never have fired here.
- Do NOT add a fifth `HealthTone`, a new colour token, or a `worstTone` rank entry. `worstTone`
  already ranks the advisory correctly by virtue of calling `healthTone`.
- Do NOT add a toast, alert, modal or any new dismissible surface. The advisory belongs where the
  source's other health facts already live.
- Do NOT parse, split, pattern-match or branch on the advisory's text. `docs/api.md` (12-09) states
  the field is human-readable free text and that a client must never branch on it; the SPA renders
  it and nothing more.
- Do NOT read the advisory from `POST /api/sources/{name}/refresh` — 12-09 deliberately did not
  publish it there. The SPA's existing post-refresh `GET /api/sources` poll is the path.
- Do NOT touch any Go file or any doc file. Do NOT modify an existing e2e spec or an existing
  vitest file; both new guards are new files, so no existing gate's provenance is disturbed.
