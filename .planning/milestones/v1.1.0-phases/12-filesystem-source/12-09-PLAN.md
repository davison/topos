<objective>
Close the SECOND `missing:` item of G-12-1/G-12-3: **a zero-match diagnostic when an explicit
match block matched nothing across a completed healthy sync.** This is the amplifier that turned
a one-character config mistake into a UAT-blocking mystery and a full debug session.

**The failure being closed** (`.planning/debug/filesystem-items-missing-from-stream.md`, evidence
entry 2026-08-14T09:18): `kernel/correlate`'s `matchFieldsFor` forwards an explicit
`[webspaces.<ws>.match.<instance>]` block to the plugin VERBATIM. `config.Validate` and
`pluginhost.ValidateMatchConfig` check field NAMES against the plugin's declared vocabulary — match
VALUES are never validated, warned about, or observed at all. So a value that can never match any
label loaded cleanly, launched cleanly, synced to `last_status: "ok"` with `reachable: true`, and
produced zero rows. Every surface in the system agreed everything was fine. The diagnosis states it
exactly: *"a match value that can never match any label loads silently, syncs 'ok', and produces an
empty stream with zero diagnostics at any layer — the silent-failure shape that turned a config
mistake into a UAT-blocking mystery."*

This plan gives that state a name, at the one layer that can see it: after a successful `Match`,
`kernel/correlate` knows the block was explicit, knows the exact values it sent, and knows the
plugin answered with nothing. It records a notice on that (webspace, source) result; the
coordinator persists it beside the run's own outcome; `GET /api/sources` publishes it as
`last_notice`. Because it lives in `correlate`, it is plugin-agnostic — it fires for the
filesystem instance in the report and for `test-ext`, the second dead instance the same debug
session noticed in passing.

**Why post-sync and advisory, never a config rejection.** A load-time or save-time rejection of a
glob-shaped value is the obvious alternative and it is wrong here: the user's live `config.toml`
contains that value right now, so a load-time rejection would stop their kernel from booting, and a
save-time rejection would block the very edit that fixes it. Only a completed sync can know a value
matched nothing — an empty folder and a mistyped value look identical to a validator. So the
mechanism is: observe, record, publish. Never refuse.

**Why a dedicated channel and not the error column.** `sync_runs.error` already carries non-fatal
per-item rejections with `status: "ok"`, so the temptation is to reuse it. Doing so would make
every advisory render as a red/degraded source (`format.ts` maps a non-empty error to a warning
tone and `aggregateSyncStatus` folds an errored source into the webspace's degraded banner). A
false alarm on every legitimately-empty match block would be as corrosive as today's silence. The
notice gets its own column, its own API field, and leaves `status`/`error` untouched.

**Index rebuild is expected and sanctioned.** A new `sync_runs` column requires the schema to be
real on an already-existing index file, and this repo's policy (`kernel/index/schema.go`'s own
`schemaVersion` comment, D-07) is drop-and-recreate rather than data migration: every row in the
index is re-derivable from a fresh sync. Bumping the version therefore means the next kernel start
rebuilds the index and every source re-syncs once. Record this consequence in the SUMMARY — it is
a deliberate, documented cost, not a surprise.

Purpose: SRC-04's failure was diagnosable in twenty minutes by someone reading five Go files. It
must be diagnosable in five seconds by someone hovering a source chip. This plan supplies the
fact; `12-10-PLAN.md` (next wave) makes it visible in the browser.

Output: one new `WebspaceResult.Notice` field and the detection behind it, one new `sync_runs`
column with the bumped schema version, one deterministic bounded aggregation in the coordinator,
one new published API field, and the tests for every boundary of the rule — including the ones
that prove it stays quiet when it should.

## Non-goals (do not do these)

- Do NOT change `kernel/config` or `kernel/pluginhost/matchconfig.go`. No new validation, no new
  rejection, no new load-time or apply-time failure of any kind.
- Do NOT emit a notice for the keywords fallback, for a non-participating instance (allowlist or
  D-20 has-match-input), or for a source whose Match RPC errored (that is already an error).
- Do NOT add `notice` to `runStatus` (`POST /api/sources/{name}/refresh`, `POST /api/sync`). The
  SPA re-reads `GET /api/sources` immediately after a refresh, so the advisory reaches the chip
  through the field this plan does add; a second publishing surface would need its own docs, tests
  and client handling for no additional user-visible outcome. Recorded here as a deliberate
  omission so a reviewer does not read it as an oversight.
- Do NOT surface the notice in the webspace stream envelope (`aggregateSyncStatus`,
  `StreamSyncDegraded`). In the reported failure the stream was NOT empty — it held 97 paperless
  items — so a stream-level empty-state advisory would never have fired. The source chip is the
  surface that was lying, and it is the surface being fixed.
- Do NOT touch `plugins/filesystem/**`, `docs/plugins/filesystem.md` or `config.example.toml`
  (12-08 owns them in this wave), and do NOT touch anything under `web/` (12-10 owns it next wave).
- Do NOT widen `FinishSyncRun`'s existing signature. Add the sibling described below instead —
  roughly twenty-five existing test call sites depend on the current arity, and churning them all
  for one parameter buys nothing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator webspace config (match values) → notice text | Operator-authored strings are composed into a message that is persisted and republished to every `/api` client |
| plugin `Match` response → notice decision | The plugin's returned item count influences whether a notice is recorded; nothing the plugin returns may enter the notice's TEXT |
| kernel → `/api` and `/agent/v1` (last_notice) | A new published field on a route the agent surface also serves, grant-filtered per source |
| existing index file → bumped schema | An operator's live `index.db` is dropped and recreated on the next open |
| browser → kernel `/api` | Loopback, unauthenticated by design |
