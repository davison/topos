## Critical implementation note — read before Task 1

**12-REVIEW.md's suggested fix is wrong as literally written, and following it verbatim would ship a worse defect than the one being fixed.**

CR-01's "Fix" section recommends gating on `advisory !== '' && tone === 'success'`, reasoning that `healthTone` "already returns `'success'` only when `last_status !== 'error'` **and** `reachable` **and** the instance didn't launch-fail". That reasoning omits `healthTone`'s own advisory branch, which the *same* gap-closure round (12-10) added at `web/src/lib/format.ts:144`: a source carrying a non-empty `last_notice` returns `warning`, not `success`.

Therefore `tone === 'success'` implies the notice is empty, which implies `advisory === ''`. The two conditions are mutually exclusive: that gate can never fire. The advisory branch would become dead code, the healthy-with-advisory case would fall through to the tone switch's `warning` arm, and the tooltip would read "{display_name} — last error {relative}: " with an empty error string — deleting 12-10's feature and inventing a nonexistent error in one move.

The correct question the gate needs answered is: *would this source be plain healthy if it carried no advisory at all?* Task 1 adds exactly that predicate to `format.ts`, where the precedence chain already lives. The verifier's stated intent ("the same precedence rule expressed once in healthTone cannot drift from the tooltip's own copy") is honoured; its literal suggestion is not.

## Assumptions and deliberate deferrals

**Unresolved edge — SRC-04 concurrency (surfaced, not dropped).** The spec-less probe fallback reports SRC-04's `concurrency` edge as `unresolved`: "If interrupted or run in parallel, what is guaranteed?" That question concerns the filesystem sync mechanism shipped in 12-01..12-07 (the stat-diff walk, the sync-run lifecycle, concurrent refreshes). This plan changes no sync path, no store write and no coordinator behaviour — it changes one boolean expression in a Svelte derivation, one new pure predicate, and one Go comment plus test. **Assumption: concurrency behaviour is unchanged by this plan**, and the SRC-04 concurrency edge remains genuinely unresolved for the phase as a whole. It is recorded here so it is not silently absorbed; resolving it belongs to a phase that touches the sync mechanism, not to a tooltip-precedence fix.

**Whitespace-only `last_notice` (pre-existing, unchanged).** `SourceChip.svelte` trims the notice while `healthTone` does not, so a whitespace-only notice yields a warning dot with no advisory text. That inconsistency predates this plan; the gate deliberately keeps the `advisory !== ''` half so behaviour in that state is byte-identical before and after. Not in scope.

**IN-01 stays deferred**, per this round's instruction: `zeroMatchNotice`'s non-empty-fields guard counts field keys rather than non-empty values. Cosmetic, reachability unconfirmed against `config.Validate`, and `kernel/correlate` is explicitly out of this plan's `files_modified`.

**`docs/testing.md`'s `12-*` section is already stale and is deliberately NOT refreshed here.** It enumerates four filesystem specs and predates `12-include-glob-metadata-preview.spec.ts`, `12-filesystem-root-label-match.spec.ts` and `12-zero-match-diagnostic.spec.ts`. Refreshing that map is real debt, but it is three plans' worth of catch-up rather than this plan's, and doing it here would invite scope drift on a one-gate fix. The new spec carries its own rationale in its header comment, following the `g-08-3` precedent for a spec that is about SPA presentation rather than a real-plugin path.

**Proportionality choice for the browser gate (stated explicitly, as instructed).** The project convention is that a browser-drivable UAT item becomes a Playwright spec. This one qualifies: `tooltipText` is a Svelte derivation whose branch selection can only be observed for real in a rendered DOM, and the unit-level guard is necessarily a mirror (this repo's vitest config is `environment: 'node'` with no component-mount harness — the very reason CR-01 shipped past a unit guard). A unit assertion alone would repeat the mistake in a new form. Both layers are therefore included: the unit matrix for fast, exhaustive coverage of all six precedence cases, and a two-test browser spec for the two cases where being wrong is user-visible. The existing `12-zero-match-diagnostic.spec.ts` and `12-filesystem-root-label-match.spec.ts` continue to cover the advisory's real-kernel end-to-end path and are not touched.
