<objective>
Prove the whole external-plugin trust boundary end-to-end on one thin path: a plugin binary that lives only in a second, external directory is discovered, launched, synced, and rendered in the browser carrying an untrusted badge — while an in-repo binary in the same run is untouched.

Purpose: this is the tracer slice for Phase 11. Every later plan (pin verification, env allowlist, extras, add-flow UI, re-pin UI, the out-of-repo proof binary) expands outward from the seam this plan proves. Implements PLUG-06 and the chip half of PLUG-08, honoring D-09 (per-OS default dir), D-10 (same prefix + discovery semantics), D-11 (trusted shadows external, loudly) and D-06 (badge shape).

Output: two-tier discovery in `kernel/pluginhost`, a `tier` field published on `GET /api/sources` and `GET /api/config/plugin-types`, the complete Phase 11 TypeScript wire surface, a reusable `TrustBadge.svelte`, and a Playwright spec that boots a real kernel with one trusted and one external plugin and asserts exactly one badged chip.
</objective>

<assumption_delta_decision>
The deterministic detector (`gsd-tools query assumption-delta scan`) is not registered in this installation, so this was assessed by reading the phase scope. The signal is real and of the `pluralization` family: **a second plugins directory exists where there was exactly one**, and with it a second class of plugin where every plugin was previously implicitly trusted.

- **Primary noun (now generalized):** a plugin binary's *provenance* — the pair `(resolved directory tier, content hash)` — rather than "a name inside the plugins directory".
- **Decision: promote.** `pluginhost.Dirs` + `pluginhost.Tier` + `ResolveBinary`/`DiscoverAllTiered` become the primary way every call site addresses a plugin binary; the existing single-directory `DiscoverBinaries`/`DiscoverAllBinaries` are demoted to internal primitives that the tiered functions compose. No call site keeps a single-directory parameter (`Discover`, `DescribePluginType`, `NewSupervisor`, `Router` all take `Dirs`), so a later phase cannot quietly reintroduce the singular assumption by wiring one directory through a surviving one-directory signature.
- **Deliberate exception, not accepted debt:** `kernel/httpapi/whatsapplink.go` keeps resolving against the trusted directory alone. That is a narrowing (an in-repo-plugin-only flow), not a leftover singular assumption, and is recorded as a prohibition in this plan's must_haves.
- **Optional invariant test (suggested, not required):** a guard asserting every binary the kernel launches arrived through `ResolveBinary` and therefore carries a tier — it would go red the moment a future phase joins a directory and a binary name by hand.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external plugins directory -> kernel process | Binaries the project did not build are resolved and executed by the kernel with the kernel's own OS privileges |
| kernel -> browser SPA | Tier/provenance facts cross to the client, which must only ever render them, never decide them |
| operator config.toml -> kernel | `[plugins] external_dir` names a filesystem location the kernel will execute code from |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Spoofing | `pluginhost.ResolveBinary` / `SourceHealth.Tier` | high | mitigate | Tier is set from the directory the binary actually resolved from at launch, never from `DescribeResponse` or the config key; `Plugin.Tier` is written once at launch and never from RPC data |
| T-11-02 | Elevation of Privilege | `DiscoverTiered` / `DescribePluginHandler` | high | mitigate | Directory listing across both tiers stays the only launch authority; `DescribePluginHandler`'s membership check iterates `DiscoverAllTiered`, so a caller-supplied path or an undiscovered name is still refused 404 |
| T-11-03 | Elevation of Privilege | `ExcludedPluginBinaries` across two tiers | medium | mitigate | The exclusion filter is applied uniformly in `DiscoverTiered` for both tiers, with a test asserting a fixture binary in the external directory is still absent from the catalog |
| T-11-04 | Tampering | external plugins directory default (D-09) | medium | mitigate | The default resolves inside the user-owned platform data directory (`$XDG_DATA_HOME`/`~/Library/Application Support`/`%LOCALAPPDATA%`), never a world-writable shared location; the kernel never creates it implicitly |
