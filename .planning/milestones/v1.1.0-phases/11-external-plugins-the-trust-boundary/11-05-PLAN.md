<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> untrusted plugin | The confirm step is where a human knowingly accepts running code the project cannot vouch for |
| plugin Describe response -> the operator's form | A plugin influences what the operator is asked to type and what defaults they see |
| browser -> config.toml | The client composes the document that decides which binaries the kernel will execute and pin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-24 | Social Engineering / Information Disclosure | declared extras defaults | high | mitigate | A declaration's default binds to the input's `placeholder` only; a source-scan guard asserts no value binding reads it, so a `${SOME_SECRET}` suggestion can never be silently saved and expanded |
| T-11-25 | Spoofing | the pinned hash written by the client | high | mitigate | `setPluginPin` is only ever called with `binary_hash` from a describe response; the client has no hashing code, and the kernel re-verifies from disk at every launch regardless of what was written |
| T-11-26 | Repudiation | adding an untrusted source | medium | mitigate | The confirm step names the binary, shows the full hash and the variables being handed over, and requires the binary name typed exactly — an accidental click cannot produce an untrusted source |
| T-11-27 | Tampering | Save anyway on an external plugin | medium | mitigate | The control is not offered for external-tier plugin types, so no path persists an untrusted source that skipped the warning or lacks a pin |
| T-11-28 | Elevation of Privilege | best-effort describe on picker selection | medium | accept | Selecting a catalog row already labeled UNTRUSTED trial-launches the plugin describe-only, exactly as the flow's Next step does; nothing is persisted, failures are silent, and the kernel's directory-listing authority still bounds what may run |
| T-11-29 | Information Disclosure | env disclosure copy | low | mitigate | The dialog lists variable NAMES supplied by the kernel's `env_var_names`, never their values |
| T-11-SC | Tampering | npm/pip/cargo installs | low | accept | No new npm dependency: every icon and primitive used is already installed (`@lucide/svelte`, existing shadcn wrappers), per UI-SPEC Registry Safety |
</threat_model>
