## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| loopback HTTP client -> `PUT /api/config` | Any local process that can reach the loopback API supplies an arbitrary `[sources.<id>] plugin` string. This is the boundary CR-01 crosses unchecked. |
| config file on disk -> `config.Load` | A hand-edited or externally-written `config.toml` supplies the same field with no UI in the path. |
| kernel -> plugin subprocess `exec.Command` | The resolved path is executed with the kernel's own OS-level privileges; no sandbox exists by design (11-CONTEXT.md's explicit out-of-scope note). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-35 | Elevation of Privilege | `pluginhost.ResolveBinary` + `config.Validate` (`Source.Plugin`) | critical | mitigate | Task 1 rejects any non-bare name as `ResolveBinary`'s first statement, so no `filepath.Join` can escape a configured directory and no file outside `dirs.Trusted` can be classified `TierTrusted`; Task 2 rejects the same shapes at config-validation time so the value never persists; Task 3 pins the rejection at the reachable `PUT /api/config` surface.
