<objective>
Close 13-VERIFICATION.md's single recorded gap: the exclude/include undo toast silently writes its reversal against the wrong webspace when the user switches webspaces inside the toast's 5000ms window.

The fix itself is already fully specified in 13-REVIEW.md WR-01 — snapshot `webspace` and `navGeneration` into local constants at the top of `handleExclude`, `handleInclude` and `handleBulkPrimary`, exactly as `writeFilter`, `handleSearch` and `ensurePolling` in the same file already do. This plan applies it and, more importantly, pins it with a real browser regression spec so it can never silently return.

Purpose: Success Criteria 1 and 2 both claim exclusion/inclusion is "trivially reversible". Today the convenience path that word describes fails silently — `item_marks` is keyed `(webspace_name, item_id, kind)`, so the misdirected write matches zero rows, the toast dismisses as if it succeeded, and the original exclusion stands. Nothing in the codebase would catch a reintroduction, because the failure produces no error and no UI signal.
Output: the three-handler snapshot fix, a new hermetic Playwright spec covering all three write paths across a real webspace switch, its `docs/testing.md` entry, and the REQUIREMENTS.md traceability reconciliation the verification report asked for.

Wave 5 (rather than the algorithmic wave 4) because this is gap closure over an already-executed phase: every one of 13-01..13-06 has a committed SUMMARY, and this plan must run strictly after all of them, including wave 4's 13-06.
</objective>
