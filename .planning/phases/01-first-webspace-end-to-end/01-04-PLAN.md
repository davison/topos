<objective>
Turn two guarantees that are currently properties of careful authorship into properties the build enforces, and publish the two contracts this phase promised.

Purpose: PLUG-02 ("read-only by construction") and AGENT-02 ("designed for programmatic consumption") are the two Phase 1 requirements a future contributor can silently break without any test going red — one added RPC, one `PATCH` call, one renamed JSON field, and the guarantee is gone with a green build. This plan closes both with committed tests, then writes down the contract those tests protect so a third party (Phase 2, PLUG-05) and an agent (v1.x, AGENT-10/11) can both work from the document alone.

Output: three contract test files, a published plugin contract, a published HTTP API contract, a fully-commented example config, and a README that runs the stack from a clean clone.
</objective>

**Published plugin contract — `proto/webspaces/v1/plugin.proto`:**

```
service SourcePlugin {
  rpc Describe(DescribeRequest) returns (DescribeResponse);
  rpc Match(MatchRequest)       returns (MatchResponse);
  rpc Fetch(FetchRequest)       returns (stream FetchChunk);
  rpc Health(HealthRequest)     returns (HealthResponse);
}
```
Handshake: `ProtocolVersion 1`, `MagicCookieKey "WEBSPACES_PLUGIN"`. Plugin map key: `"source"`.
Kernel launches each binary found in the plugins directory with `AllowedProtocols` restricted to
gRPC, injecting that source's config as JSON in the `WEBSPACES_SOURCE_CONFIG` environment variable.

**Agent-facing HTTP surface:**

```
GET /api/webspaces
GET /api/webspaces/{webspace}/stream
GET /api/items/{id}
GET /api/items/{id}/content
GET /api/items/{id}/thumbnail

Stable id:   {source_type}:{source_id}          e.g. "paperless:42"
Envelope:    {"schema_version":1, ...}
Error:       {"schema_version":1,"error":{"code":"<snake_case>","message":"<human text>"}}
Codes:       webspace_not_found, item_not_found, source_unavailable, unsupported_rendition_type
Provenance:  {source_type, source_system, source_id, plugin, contract_version, synced_at_unix}
Link:        {"url": "<absolute source url>", "fidelity": "exact"|"anchored"|"conversation-only"}
Order:       timestamp_unix DESC, secondary_timestamp_unix DESC, id ASC
```

**Config keys (KERN-01, D-01 to D-04):**

```
[server]   listen
[index]    path
[plugins]  dir
[sources.<name>]   plugin, base_url, token, api_version
[webspaces.<name>] keywords            # list; all keywords matched in all plugins
```
Matching is exact and case-insensitive: `house` matches the tag `House` but not `Household`.
Secrets appear only as `${VAR}` references; `os.ExpandEnv` runs over the raw file before decoding.

Write three committed tests that make the phase's two unenforceable guarantees enforceable, plus the index-ordering assertion they depend on.

**`sdk/contract_test.go` — pin the RPC set as an allowlist.** Read `proto/webspaces/v1/plugin.proto` from disk relative to the test file, strip line and block comments, extract every RPC name with a regexp over `rpc <Name>(`, and assert the resulting set is exactly the four names `Describe`, `Match`, `Fetch`, `Health`. An allowlist, not a blacklist of mutation verbs: a blacklist misses a creatively-named mutating RPC, whereas an allowlist fails on *any* addition until someone deliberately widens it — which is exactly the deliberation PLUG-02 wants. Also assert the file declares `service SourcePlugin` and the two enums, and that both enums' zero values are the `_UNSPECIFIED` variants. Fail with a message that names PLUG-02 and points at this plan, so a future contributor who trips it understands the constraint rather than deleting the test.

**`plugins/paperless/readonly_test.go` — prove no plugin file constructs a non-GET request.** Parse every `.go` file under the `plugins/` tree with `go/parser` into an AST and walk it, rather than grepping — a comment or a string literal must not be able to trip or defeat the check. Flag any selector expression referencing an `http` package identifier that names a non-GET method constant or a non-GET convenience function, and any call to `http.NewRequest` or `http.NewRequestWithContext` whose method argument is a literal other than `"GET"` or `http.MethodGet`. Report every offending file and line. This is the mechanical half of the read-only guarantee that `sdk/contract_test.go` covers at the contract level; note in the failure message that plugins never mutate source data stores.

**`kernel/httpapi/contract_test.go` — pin the agent-facing envelope.** First, if `kernel/httpapi/item.go` currently reaches the plugin host through a concrete type, introduce a minimal interface in the httpapi package describing just the fetch call, and have the router accept it — a one-method seam, nothing more; the production wiring passes the real host unchanged. Then build the real router over a temp-file index seeded with three fixture items: two sharing a `timestamp_unix` but differing in `secondary_timestamp_unix`, and one with an empty preview. Using `httptest`, assert: `schema_version` is 1 on every success and every error response; every item id matches `^[a-z0-9_-]+:.+$` and is exactly `source_type` plus a colon plus `source_id`; `link.fidelity` is one of the three lowercase-hyphenated values; `provenance` contains all six documented keys; a webspace with no items returns 200 with an items array of length zero, and specifically not 404 and not a JSON null; an unknown webspace returns 404 with error code `webspace_not_found`; an unknown item returns 404 with `item_not_found`; a fetch failure returns 502 with `source_unavailable`; every error body has exactly the `error.code` and `error.message` fields. Finally, call the stream endpoint twice with no intervening write and assert the two response bodies are byte-identical, which pins both the ordering and the JSON key order.

**`kernel/index/store_test.go` — extend with the ordering assertion the above depends on.** Assert `StreamItems` orders by `timestamp_unix` descending, then `secondary_timestamp_unix` descending, then `id` ascending, using fixture rows that would come back in a different order under SQLite's natural row order, so the test would fail if the `ORDER BY` were dropped.

Wire all four into `make test`. None of these tests may require the network or a running paperless-ngx — they run against fixtures and a temp SQLite file so they stay useful in CI and on a machine with the home server offline.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published docs → future contributors and third-party plugin authors | Documentation that drifts from the code teaches an incorrect security model (e.g. implying writes are possible, or that the listener is safe to expose). |
| `config.example.toml` → the user's real config | Whatever this file models is what the user copies; a literal credential here would be copied into a file the user may share. |
| test fixtures → CI | Contract tests must not depend on network or a live source, or they degrade to skipped tests that assert nothing. |
