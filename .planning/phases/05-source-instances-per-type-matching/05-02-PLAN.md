<objective>
Replace `MatchRequest{repeated string keywords}` with a typed, plugin-declared match-field map, and make every plugin publish the vocabulary the kernel validates against (D-04, D-05). This is the wire half of KERN-07: after this plan the contract carries per-field matching, every in-repo plugin speaks it, and behaviour is unchanged because the kernel fans a webspace's `keywords` list into each instance's declared vocabulary — which is exactly D-01's fallback, not a transitional shim.

Purpose: the published contract must stabilize on typed matching before external plugin authors build against it (ROADMAP note).
Output: a republished `.proto`, regenerated SDK stubs, a bumped handshake, and five plugins that declare a vocabulary and read typed fields.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kernel → plugin subprocess | the resolved match fields the kernel sends are operator-authored config crossing into a (future third-party) process |
| plugin subprocess → kernel | Describe's declared vocabulary is untrusted input the kernel uses only to validate config, never to widen behaviour |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Information Disclosure | `correlate.matchFieldsFor` → `Plugin.Match` | high | mitigate | Each Match call carries only that instance's own resolved fields; the webspace's full match map (which names other silos' folders, tags and conversation names) is never marshalled into any plugin's request |
| T-05-08 | Tampering | `DescribeResponse.match_vocabulary` | medium | mitigate | The declared vocabulary is used only as an allowlist to reject operator config; it can never add a field the operator did not write, so a hostile plugin cannot use it to broaden what it is asked to match |
| T-05-09 | Spoofing | stale plugin binary against the new contract | medium | mitigate | `Handshake.ProtocolVersion` bump makes a stale binary fail at handshake rather than silently receiving an empty match map and returning zero items |
| T-05-10 | Denial of Service | unbounded `match_fields` map size | low | accept | The map is built from the operator's own local config file on a single-user desktop; the existing `sdk.MaxMessageSize` ceiling already bounds the request |
</threat_model>
