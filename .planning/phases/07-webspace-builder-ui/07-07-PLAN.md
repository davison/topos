<objective>
**As a** person who has just revoked an automated agent's access to one of my sources in the topos UI, **I want to** that revocation to be in force the moment the save lands, **so that** an agent client already running on my machine stops being able to read that source's personal content immediately, rather than at some indefinite point in the future when I happen to restart the kernel.

Purpose: this plan closes the first of the two blocking gaps in 07-VERIFICATION.md — 07-REVIEW.md's CR-01 (Critical, unresolved as of `ccc9449`). `MountAgentRoutes` resolves the running config exactly once at router-construction time and closes that single snapshot into `agentSourcesHandler`, `agentWebspacesHandler`, `agentItemHandler` and `agentRenditionHandler`; only `agentStreamHandler` takes the store and re-reads per request. A grant revoked through this phase's own hot-apply write path therefore takes effect on every `/api/*` route and in the UI immediately, but on four of the five `/agent/v1` routes not at all until the process restarts — a live authorization-bypass window on AGENT-01's default-deny grant model, and a direct contradiction of D-06, the decision the whole phase's config write path is built on.

Output: all five agent handlers reading the config per request from `cfgStore`, a `MountAgentRoutes` that holds no config value at all, a corrected doc comment (IN-01), an end-to-end regression suite proving revocation and grant both land on the next request against the same router, and an AST guard that fails the build if a boot snapshot ever comes back.
