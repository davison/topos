<objective>
**As a** person who just created a webspace, **I want to** land in it and see that it is empty, **so that** I can start adding sources — instead of being told the service that just answered my save is not responding, and having to click Retry to find out it was there all along.

Purpose: this plan closes 07-UAT.md `G-07-1`. Two co-causes compose to produce the reported symptom and both are fixed here. First, `kernel/httpapi/stream.go` decides whether a webspace exists by asking the INDEX (`Store.WebspaceExists`, documented as "has completed at least one sync"), whose only insert site is the sync-time `ReplaceWebspaceSourceItems`. A webspace created through the UI is config-known the moment `PUT /api/config` returns 200, but index-unknown until an eager resync — which `Supervisor.Apply` dispatches as detached goroutines AFTER that 200 — has actually run. The create flow's immediate stream GET therefore lands in a deterministic window and 404s; on an install with no configured sources at all, no sync ever runs and the 404 is permanent. Second, `web/src/routes/w/[webspace]/+page.svelte`'s `load()` collapses every `getStream` failure into one error state, so the typed `ApiError('webspace_not_found')` renders `StreamError.svelte`'s fixed service-unreachable copy — telling the user a healthy kernel is down, which is the same misclassification class 07-12 fixed on the root route.

Output: one config-aware existence gate in `kernel/httpapi`, called by all three surfaces that ask the question (stream, search, and the agent stream mirror — closing the gap's own audit item); `Store.WebspaceExists`'s doc comment corrected to describe what it answers rather than what it was being used to decide; the published contract in `docs/api.md` updated; and on the client, a distinct not-found state with its own component and its own approved copy, leaving the service-unreachable state intact for genuine outages.

**Scope discipline (gap closure).** This plan closes `G-07-1` and nothing else. `G-07-7` — removed sources lingering in the stream — is 07-16, which depends on this plan only because both edit the same route file. `G-07-3`/`G-07-4`/`G-07-5`/`G-07-6` are already closed by 07-11/07-12/07-13/07-14. No supervisor, correlate or syncer file is touched. No sync timing changes.

**Recorded planning choices.**

1. **The gate is config OR index, never config alone.** Config-known answers the gap. Index-known must stay because `TestStreamHandler_KnownEmptyWebspaceReturns200EmptyArray` serves a seeded index through an empty config store, and because a webspace whose block was removed from the file while its rows survive answers 200 today. Making the change purely additive means no request that succeeded before this plan can fail after it, which is the property that makes a gap repair safe to ship without a full regression pass.
2. **Existence is answered from configuration, not by writing an index row during save.** The debug session records both directions. Writing the `webspaces` row synchronously from the apply path would make an index write a side effect of configuration, would leave a stranded row behind when the webspace is later deleted, and would still leave the gate defining existence as sync history. The gate moves instead; nothing about sync timing has to be true for the read boundary to be correct.
3. **One gate, three call sites, fixed in one task.** The gap's `missing[2]` explicitly asks for the `search.go` and `agent.go` audit. Fixing only the stream route would leave two surfaces answering a different question from the third, which is precisely the drift that made this a gap rather than a typo. The shared helper is what makes the audit permanent rather than a one-time sweep.
4. **The not-found state is neutral, not destructive.** `StreamError.svelte` is a destructive Alert because something broke. Nothing is broken when a webspace is not configured — the kernel answered correctly and promptly. `StreamMissing.svelte` therefore mirrors `StreamEmpty.svelte`'s centred neutral treatment. A wrong tone here is a smaller version of the same defect this plan is fixing: telling the user something is wrong with their machine when it is not.
5. **No Retry button on the not-found state.** After the kernel fix a `webspace_not_found` response is definitive, not transient — retrying an unconfigured name fails identically forever, and offering Retry would reproduce the exact interaction (click Retry, hope) this gap is about. The recovery affordance already on screen is the webspace switcher in the header, which stays mounted in every stream state; the copy points at it.
6. **The guard test is a comment-stripped source scan, placed flat in `web/src/routes/`.** It follows `root-empty-state.test.ts` — this project's vitest config runs in the `node` environment with no component-mount harness, so structural scanning is the house pattern for guarding a Svelte change. It is placed at `web/src/routes/webspace-stream-states.test.ts` rather than beside the route file: the route directory is literally named `w/[webspace]`, and keeping a glob-special character out of the test path removes a class of runner-discovery surprise for zero cost.
7. **Explicitly flagged, deliberately NOT planned — the kernel-wide sync aggregate.** `streamResponse.sync` is aggregated by `aggregateSyncStatus` over `LatestSyncRunPerSource`, which is kernel-wide and not scoped to the requested webspace, so `streamVariant`'s `sync-failed` branch can render the sync-failure state for a brand-new empty webspace on an install where some unrelated source's last run errored. That is pre-existing Phase 1/2 behaviour for every empty webspace, is not what the user reported (their Retry showed "nothing here yet", so their aggregate was not in error), and scoping the aggregate to a webspace's participating sources is a distinct behaviour change with its own tests. Recorded here so it is a known boundary rather than a surprise.
8. **Explicitly flagged, deliberately NOT planned — `handleSearch`'s error classification.** `searchWebspace` can throw the same typed error, and its catch collapses to one search-error state. After Task 1 the search route answers 200 for a config-known webspace, so the case stops being reachable through the create flow. Narrowing the search error state is cosmetic once the kernel is right.
9. **Gap-closure shape, not tracer-first.** This is a repair to two named lines of an already-proven architecture, matching 07-11..07-14's shape. There is no new layer to prove end to end.
10. No package is installed by this plan; 07-RESEARCH.md's Package Legitimacy Audit needs no new row. No ORM schema files exist, so the Schema Push Gate does not fire.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser UI → kernel `GET /api/webspaces/{ws}/stream` | Loopback-only, unauthenticated per the v1 posture. The webspace name is attacker-controllable in the sense that any string can be typed into the address bar, and the handler's first decision is made from it |

| agent grant boundary → `/agent/v1` stream mirror | The agent surface answers the same existence question and must not gain a different answer from the human surface, or the two disagree about what exists |
