<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| downloaded release payload → installed prefix | Staged assets crossing into `$PREFIX` during install |
| e2e fixture key → kernel binary under test | An extra accepted verification key injected at build time |
| documentation → operator behaviour | What the operator believes about which plugins are safe |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-26 | Tampering | Unverified bytes placed into `$PREFIX` | high | mitigate | Provenance verification runs inside the existing verify stage, before the first placement; a payload carrying provenance with no resolvable verifier is a loud abort, never a skip |
| T-16-27 | Elevation of Privilege | An extra accepted key reaching a production kernel via the e2e seam | high | mitigate | The seam is `-ldflags -X` only, written in one place in the Makefile and used only by the `e2e` and `gdrive-external-rehearsal` targets; the `build`, `build-portable`, and release paths do not set it, and the plan's prohibition forbids any runtime-readable key path |
| T-16-28 | Spoofing | The e2e harness reimplementing the signature scheme and drifting from the kernel | medium | mitigate | The fixture executes the real `topos-provenance` binary; an acceptance criterion asserts no ed25519 implementation exists in the TypeScript fixture |
| T-16-29 | Repudiation | Documentation still asserting the superseded "no publisher verification" model | medium | mitigate | The stale claim is removed from both `docs/plugin-contract.md` and `kernel/pluginhost/binaryhash.go`, asserted by a grep criterion; `docs/plugin-trust.md` becomes the single source |
| T-16-30 | Denial of Service | An install aborting midway leaving a broken instance | medium | mitigate | Placement still begins only after every asset verifies; the smoke case asserts the target prefix's recursive checksum is unchanged after a failed run |
| T-16-31 | Information Disclosure | The ephemeral e2e private key committed to the repository | medium | mitigate | The key is generated into `bin/` at `make e2e` time and gitignored; an acceptance criterion confirms no key file is tracked |
| T-16-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install tasks in this plan — `make e2e` installs only the already-pinned Playwright browser it installs today, and no new Go module or npm package is added |
</threat_model>
