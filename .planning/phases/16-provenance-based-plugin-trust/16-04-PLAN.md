<objective>
Stand up the minimal `topos-plugins` sibling repository, cut one real signed
release through its own tag-triggered workflow, embed that key in the kernel,
and prove an installed topos instance verifies the released binary as
first-party trusted with no link-time manifest entry.

Purpose: D-04 — the signing path is proven once, in its final home, so Phase 17
fills a repository whose release pipeline the kernel already trusts. A verifier
proven only against a hand-crafted test double proves the crypto, not the
pipeline.

Output: the `topos-plugins` repository (signing workflow + one trivial plugin +
one tagged signed release), the topos-plugins public key embedded in the
kernel's accepted-key set, and a recorded end-to-end proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions secret store → signing step | The ed25519 private key, held only as a repository secret (D-02) |
| topos-plugins release assets → installed kernel | Downloaded binary and provenance files crossing onto the operator's machine |
| tag push → published artifact | Whoever can push a tag to topos-plugins can cause a signature (the stated trust boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-20 | Information Disclosure | Signing key in workflow logs or argv | high | mitigate | The secret is referenced exactly twice (`env:` key and `secrets.` value), passed only through the environment, never as an argv flag; no `set -x` in the job; asserted by grep acceptance criteria |
| T-16-21 | Information Disclosure | Private key left on local disk after keygen | high | mitigate | `keygen` writes at mode 0600 into a temp directory that is deleted after `gh secret set`; deletion asserted and recorded in the SUMMARY |

Recorded in the repository README so it is a documented boundary, not an unexamined one |
| T-16-23 | Tampering | The TRUST-02 proof passing against a hand-signed local artifact rather than a pipeline product | high | mitigate | The proof requires a successful workflow run URL and release assets fetched from that release; hand-signing to make the release appear is prohibited by this plan's prohibition entry |
