Close 16-VERIFICATION.md gap 1: `EvaluateTrust`'s two tamper-refusal return
paths never set `Trust.Tier`, so `GET /api/sources` reports an empty tier
instead of the documented trusted tier for every `manifest_unverified` entry —
and no test asserts the real value, which is why it shipped.

Purpose: ROADMAP success criterion 5 says the operator can see WHY a plugin
holds the tier it holds and is never silently downgraded. The wire `tier` field
is the field `SourceChip.svelte`/`TrustBadge.svelte` branch on; with the empty
value neither branch fires, so a tampered binary's chip loses its trust signal
entirely. This was reproduced live in this phase's own
`16-04-TRUST02-PROOF.md` negative case 4.

Output: both refusal paths in `kernel/pluginhost/provenance.go` setting the
tier explicitly; two real-path Go regression nets (one per refusal arm) that
fail against the current code; and the existing browser spec widened to assert
the wire field it never read.
</objective>
