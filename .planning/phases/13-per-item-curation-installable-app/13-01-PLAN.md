<objective>
Prove the per-item curation architecture end to end on the thinnest possible path, then complete the mark write/read surface and the toast layer both the bulk path and the PWA update notice will reuse.

Purpose: KERN-09's four simultaneous guarantees (survives re-sync, survives restart, survives index rebuild, outranks match rules) all rest on one structural choice — a no-FK, rebuild-exempt `item_marks` table whose only read path is a shared SQL clause inside `index.Store`. Getting that shape wrong is an architectural dead end, so it is proven first, wired to a real button, on real data.

- **PD-01** — Mark filtering lives inside `index.Store.StreamItems` and `index.Store.Search`, never in an HTTP handler.
