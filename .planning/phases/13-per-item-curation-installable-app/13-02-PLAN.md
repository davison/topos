Expand the proven mark slice into the full read surface KERN-10 asks for, and give KERN-09 its orphan-lifecycle rule.

Purpose: the tracer proved one item can be excluded and stays excluded. This plan makes the excluded bucket viewable and countable, and settles what happens when an excluded item stops existing — the single hardest correctness question in the strand, because "the item is gone" and "the sync failed" look identical from the wrong vantage point.
Output: `?view=excluded` on the stream route, `excluded_count` in the stream response, the orphan prune sweep inside the existing sync transaction, cross-surface parity tests, and the published API documentation for all of it.

## Planner decisions recorded for this phase

- **PD-02** — De-allowlisting a source from a webspace prunes that source's marks for that webspace, exactly like the existing `webspace_items` clear does. This resolves 13-RESEARCH.md Open Question 2 / Assumption A4 as a *named* decision rather than an accidental side effect of where the sweep sits: D-09's own wording is that the excluded view only ever shows items that would otherwise be in the stream, and a de-allowlisted source contributes nothing to the stream. Re-allowlisting therefore returns its items unexcluded. Documented in `docs/api.md` so the behaviour is published, not folklore.
- **PD-06** (flagged assumption, carried from 13-01) — search always filters excluded items out, in every view.

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-13 | Tampering | `?view=` parsing in `kernel/httpapi/stream.go` | medium | mitigate | The value is matched against a closed two-member set and rejected 400 otherwise; it never reaches SQL as text, only as a branch selector between two fixed clauses. |
| T-13-14 | Tampering | prune sweep driven by plugin-reported item sets | high | mitigate | The sweep is confined to `ReplaceWebspaceSourceItems`' existing transaction and scoped by the kernel's own `webspaceName`/`source` parameters (never each item's self-reported Source field), so one plugin can never sweep another source's or another webspace's marks. A Match failure never reaches the call at all, so a plugin cannot cause a sweep by failing. |
| T-13-04 | Information Disclosure | `/agent/v1` stream mirror | medium | mitigate | Both agent call sites pass `ViewIncluded` explicitly and there is no agent-facing view parameter, so an excluded item can never be read back through the agent surface. |
| T-13-15 | Denial of Service | prune sweep's generated IN placeholder list | low | accept | The kept-id list is the item set the kernel itself just wrote in the same transaction, bounded by what the source reported; SQLite's default parameter limit is far above realistic personal-data sync sizes and a breach would fail the sync loudly rather than corrupt state. |
</threat_model>
