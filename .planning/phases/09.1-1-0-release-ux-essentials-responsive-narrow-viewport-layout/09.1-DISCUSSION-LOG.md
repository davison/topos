## Narrow-layout shape

### Q1: At mobile width, what happens when you tap a stream item?

| Option | Description | Selected |
|--------|-------------|----------|
| Takeover + back (Recommended) | Detail fills the viewport with a back affordance; stream scroll position preserved. Standard mobile master-detail pattern | ✓ |
| Literal stack, auto-scroll | Detail renders below the stream in one scrollable column; tapping scrolls down to it | |
| Stack with collapsed stream | Stream collapses to a compact strip with the detail below | |

**User's choice:** Takeover + back

### Q2: Below what width does the layout switch to the takeover pattern?

| Option | Description | Selected |
|--------|-------------|----------|
| 768px + flex mid-range (Recommended) | Takeover below 768px; between 768–1024px the stream pane gives up fixed 480px and shrinks proportionally | ✓ |
| 1024px, keep 480px stream | Takeover below 1024px; above it, current layout byte-identical | |
| 768px, keep 480px stream | Takeover below 768px only; 768–1024px band keeps fixed 480px (detail ~250px, cramped) | |

**User's choice:** 768px + flex mid-range

### Q3: How does the back affordance work in the mobile detail takeover?

| Option | Description | Selected |
|--------|-------------|----------|
| Button + browser back (Recommended) | Visible back control plus a history entry so the phone's back gesture closes the detail | ✓ |
| In-UI button only | Just the visible control; browser back leaves the page | |
| Swipe + button + history | Adds edge-swipe-to-go-back; extra work, can fight iframe scrolling | |

**User's choice:** Button + browser back

### Q4: While the takeover is open, what happens to the app header?

| Option | Description | Selected |
|--------|-------------|----------|
| Hidden, slim bar (Recommended) | Header gives way to one slim detail bar: back, item title, open-in-source | ✓ |
| Header stays visible | Switcher/chips/search remain above the detail | |
| Collapsed one-row header | Minimal single-row header (switcher only) above the detail bar | |

**User's choice:** Hidden, slim bar

**Continue check:** "Next area" — remaining narrow-layout details (transitions, scroll-restoration mechanics) to Claude's discretion.

## Compact stream cards

### Q1: Where do the compact stream cards apply?

| Option | Description | Selected |
|--------|-------------|----------|
| Narrow viewports only (Recommended) | Compact below 768px alongside the takeover; mid-range band and desktop keep today's card | ✓ |
| Below 1024px | Compact in takeover range and the 768–1024px flex band | |
| Everywhere (global density) | Compact card becomes the one card, desktop included | |

**User's choice:** Narrow viewports only

### Q2: To halve the card height, what does the compact card keep?

| Option | Description | Selected |
|--------|-------------|----------|
| 1-line snippet (Recommended) | Title ~16px + merged meta ~12px + one-line snippet ~13–14px; ~55–60px total | ✓ |
| Title + meta only | Drop the snippet; ~45px, maximum density | |
| Keep 2-line snippet, shrink type | All elements at reduced sizes; ~75–80px, not truly halved | |

**User's choice:** 1-line snippet

### Q3: What survives in the compact card's single meta line?

| Option | Description | Selected |
|--------|-------------|----------|
| All, truncating (Recommended) | Icon + source name + group label + date; source/group truncate first | ✓ |
| Icon + group + date | Drop source display name; ambiguous with two instances of one plugin type | |
| Icon + date only | Minimal provenance + time | |

**User's choice:** All, truncating. (Constraint stated in the question: the degraded-sync warning dot stays regardless — accepted.)

### Q4: Do search-result rows and the date-marker ruler get the same treatment?

| Option | Description | Selected |
|--------|-------------|----------|
| Both adapt (Recommended) | Search rows go compact; ruler stays with tap-to-jump | |
| Compact cards, hide ruler | Search rows go compact; ruler hidden below 768px | ✓ |
| Stream cards only | Only StreamRow changes; accept inconsistency | |

**User's choice:** Compact cards, hide ruler — the user diverged from the recommendation here, preferring to reclaim the ruler's lane and skip touch-affordance work for it.

**Continue check:** "Wrap up".

**Final gate:** "I'm ready for context."

- Global stream density change / desktop compact toggle (declined at compact Q1)
- Touch-adapted tap-to-jump date ruler (sidestepped by hiding below 768px)
