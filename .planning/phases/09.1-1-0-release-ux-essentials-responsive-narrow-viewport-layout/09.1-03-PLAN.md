<objective>
Make the stream readable on a phone: below 768px each stream row (and therefore each
search-result row) collapses from 152px to 60px — title, one merged meta line, one-line snippet
— and the date-marker scrollbar ruler steps aside so its 12px lane returns to the content.
At 768px and above, every pixel is exactly as it is today.

Purpose: at desktop density roughly four items fit a phone screen. D-05/D-06/D-07 specify a
compact treatment that keeps every piece of information that carries meaning (source identity,
group, date, sync health, search highlighting) while dropping only what does not fit the budget
(thumbnail, tag pills). D-08 extends it to search results and reclaims the ruler's lane.

Output: a compact stream row, a hidden-below-768px ruler, a widened marker guard, and a mobile
e2e spec that measures the result rather than describing it.

<planner_resolutions>
Two calls this plan LOCKS.

**R1 — CSS breakpoint classes, not a `compact` prop.**
CONTEXT.md offers prop-driven and CSS-driven as alternatives. CSS wins: the app has zero
JS-computed layout state today, a `matchMedia` listener plus a second render path would be new
machinery for a pure width predicate, and RESEARCH verified that Tailwind v4's layer order
(`theme, base, components, utilities`) makes any `max-md:` utility on the row element beat
`.stream-row-surface`'s `height: 152px` in `@layer components` with no specificity fight and no
`app.css` edit. `web/src/app.css` is deliberately NOT in this plan's `files_modified`, and
Task 3 asserts it stayed untouched.

**R2 — The compact meta line is a different layout strategy, not a smaller version of the
desktop one.**
RESEARCH Pitfall 4: `.stream-row-meta` carries a `max-height: 40px` flex-wrap badge clip tuned
against the desktop row's own 152px budget. Reusing it unmodified inside a 60px budget would
consume two thirds of the card before the title and snippet get any space. The compact meta line
therefore switches to a single `flex-nowrap` strip with one truncating text unit — which is also
exactly what D-07's "source name / group label truncating first" needs, and what
09.1-UI-SPEC.md resolves as one jointly-truncating text node rather than two independently
truncating spans (both pieces degrade together instead of one silently vanishing at full length).
</planner_resolutions>
