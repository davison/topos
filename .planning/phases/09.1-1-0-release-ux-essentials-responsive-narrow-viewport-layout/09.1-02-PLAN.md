<objective>
Make a missing `config.toml` a first-run event instead of a fatal error: the kernel creates its
config directory, writes a canonical default config through the existing writer, logs where it
put it, and continues booting so the SPA reaches its already-shipped "No webspaces yet" screen
with a working Create webspace CTA.

Purpose: today `setup()` calls `config.NewStore(configPath())` unconditionally and a missing
file kills the process before any UI can render. Phase 7 already built the zero-webspaces empty
state and the create-webspace modal; this closes the one gap that makes them unreachable on a
fresh install.

Output: an exported `config.DefaultConfig()`, a narrowly-gated bootstrap branch in
`cmd/topos/main.go`, and Go tests covering the positive, negative, and never-overwrite cases.

<planner_resolutions>
Four discretion calls this plan LOCKS (CONTEXT.md offers this whole area to Claude's discretion;
these are the choices, recorded so an executor does not re-open them).

**R1 — Default config contents: a genuine empty shell, not a seeded example.**
`Sources` and `Webspaces` are non-nil but empty maps; the four scalar fields take the four
already-exported `Default*` constants. 09.1-UI-SPEC.md states the UI-visible reason as a
constraint, not a preference: a seeded example webspace would render a populated stream for a
webspace the user never asked for, defeating the "friendly prompt to create your first
webspace" framing outright. RESEARCH verified empirically (a `go run` against this repo's own
pinned `go-toml/v2`) that non-nil empty maps marshal to explicit `[sources]` / `[webspaces]`
table headers rather than omitted keys, so the written file documents its own shape.

**R2 — `topos sync` bootstraps too (RESEARCH Open Question 1).**
Both `runSync` and `runServe` call the same `setup()`, so the branch covers both with no extra
code and no carve-out. A `sync` on a fresh machine will report zero sources — that is the honest
outcome, and the INFO log line naming the written path is what makes it self-explaining rather
than silent. A carve-out making `sync` alone keep dying would be extra code buying a worse
first-run experience.

**R3 — `DefaultConfig()` lives in `kernel/config`, not inline in `cmd/topos`.**
RESEARCH Pattern 4 option (b). `applyDefaults` is unexported, so `cmd/topos` cannot reuse it;
building the shape inline would put a second definition of the default config a package away
from the `Default*` constants it is built from, and a fifth default field added later would
have to be remembered in two places. Co-locating it in `types.go` directly beneath those
constants keeps one definition.

**R4 — The bootstrap is tested at the Go level; the browser-visible consequence is already
pinned (RESEARCH Pitfall 1).**
A genuinely-missing-config e2e spec cannot work with the current harness: `launchKernel` always
allocates an ephemeral port and writes it into a fixture `config.toml` before spawning, so a
kernel that bootstraps its own default would bind the fixed `127.0.0.1:7777` instead, and
`waitForKernelReady` would poll an address nothing is listening on — and would collide with a
developer's running `make dev`. Making that spec possible needs NEW kernel surface (a listen
env var or flag), which grows the kernel's config surface beyond what CONTEXT.md scoped. So:
bootstrap logic is proven by Go tests against a temp dir, and the browser-visible consequence —
zero webspaces renders "No webspaces yet" with a working Create webspace CTA — is already
pinned by `web/e2e/specs/uat-04-zero-webspace-vs-outage.spec.ts`, which boots with
`webspaces: []`. The SPA cannot distinguish "just bootstrapped" from "zero webspaces
configured": both are `GET /api/config` returning an empty webspaces map. Task 3 verifies that
existing spec still passes rather than duplicating it.
</planner_resolutions>

Keeping the logic in its own function is what makes it testable: `setup()` itself also opens the
index at the configured path, which a unit test must not do on a developer's real machine.

**`bootstrapConfig(path string, loadErr error, logger hclog.Logger) (bool, error)`** — returns
whether it wrote a file:

1. If `errors.Is(loadErr, os.ErrNotExist)` is false, return `(false, nil)` immediately. This
   single gate is the whole safety property (RESEARCH Pitfall 3): a malformed TOML file, a
   permission-denied read, a directory sitting at the config path, or a validation failure on an
   existing file must all continue to reach `fatal(err)` exactly as they do today. Treating any
   load failure as "must be missing" would replace an operator's broken-but-present file with a
   fresh default — silent data loss.
2. Call `os.MkdirAll` on `filepath.Dir(path)` with mode `0o700`, wrapping any failure as
   `bootstrap config dir <dir>: %w`. This step is a genuine gap, not a safety net that already
   exists: nothing in `kernel/config` or `cmd/topos` creates the config directory today, and
   `WriteCanonical`'s own `os.CreateTemp(dir, ...)` fails with ENOENT on a machine that has
   never had a `~/.config/topos/`. `0o700` (not `0o755`) is deliberate — the config file can
   later hold `${VAR}` references and per-source connection details.
3. Call `config.WriteCanonical(path, config.DefaultConfig())`, wrapping any failure as
   `bootstrap config write <path>: %w`. Pass the raw default only — never any expanded or
   secret-resolved config, per Phase 7 D-05 and `WriteCanonical`'s own doc comment.
4. Log at INFO through the passed `hclog.Logger` that no config file was found and a default was
   written, with the path as a structured field, then return `(true, nil)`. This is what makes a
   fresh `topos sync` self-explaining rather than silently doing nothing (planner_resolutions R2).

`errors` and `path/filepath` are already imported in this file — the branch needs no new import.

**`setup()`** — restructure its first four lines only. Resolve `configPath()` into a local
`path` (it is currently called inline and would otherwise be called twice), call
`config.NewStore(path)`, and on error: call `bootstrapConfig(path, err, logger)`; return the
bootstrap error if non-nil; return the ORIGINAL load error if it reported it did not write
(so a broken file's own diagnostic reaches the user, not a generic one); otherwise re-call
`config.NewStore(path)` and return its error if that fails. Re-loading through the normal path
rather than constructing a Store in memory is deliberate: it proves the just-written file
actually round-trips through real validation on the user's own machine, so a default that
somehow failed validation would surface at first run instead of at some later reload. Everything
below (the `Expanded()` call and `index.Open`) stays byte-identical. `logger` is currently an
unused parameter of `setup` — this gives it its purpose; do not change `setup`'s signature.

**`cmd/topos/bootstrap_test.go`** — a new test file in `package main` covering:

- **Writes on a truly missing file, into a directory that does not exist yet.** Point `path` at
  `filepath.Join(t.TempDir(), "nested", "topos", "config.toml")` — the nested segment is what
  proves the `MkdirAll` step, since a bare `t.TempDir()` path would pass even without it. Pass a
  `loadErr` obtained by actually calling `config.NewStore(path)` on that missing path (not a
  hand-made sentinel), assert it returns `wrote == true` and no error, then assert
  `config.NewStore(path)` now succeeds.
- **Directory and file modes.** Assert the created parent directory's permission bits are `0o700`
  and the written file's are `0o600`.
- **Refuses a non-ENOENT error.** Call `bootstrapConfig` with a `loadErr` that is not
  `os.ErrNotExist` (wrap `fs.ErrPermission` with `%w` to mirror `LoadRaw`'s own wrapping shape),
  and assert it returns `wrote == false`, no error, and that no file was created at the path.
- **Never overwrites an existing file.** Write a deliberately malformed config file, capture its
  bytes, obtain the real error from `config.NewStore` on it (a parse failure, not ENOENT), call
  `bootstrapConfig`, and assert `wrote == false` and that the file's bytes are byte-identical to
  what was written. This is the test that would catch a bootstrap gated too broadly — RESEARCH
  Pitfall 3's explicit warning that a positive-case-only suite misses it.
- **Uses a discardable logger** — `hclog.NewNullLogger()` — so test output stays clean.

Use `t.TempDir()` throughout; never touch `configPath()`'s real resolution or the user's home.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem -> kernel | the config path and its parent directory are user/OS-controlled state the kernel reads and, for the first time, writes |
| kernel -> filesystem | the kernel now creates a directory and a file in the user's home on a path it did not previously own |
| in-memory expanded config -> disk | the expanded config carries resolved secrets; only the raw form may ever be written |
