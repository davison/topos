# Phase 09.1: 1.0 Release UX Essentials Verification Report

**Phase Goal:** The app works on a phone and survives a fresh install. Below 768px, opening a
stream item becomes a full-viewport detail takeover with a back control and a browser history
entry (superseding the roadmap entry's "stacks below" wording, per 09.1-CONTEXT.md D-01), stream
and search rows collapse to a 60px compact form, and every hover-gated header affordance gains a
touch equivalent — with layout at 1024px and above byte-identical to today. A missing
`config.toml` stops being fatal: the kernel writes a canonical default and boots into the
already-shipped "No webspaces yet" greeting.

**Verified:** 2026-08-12
**Status:** passed
**Re-verification:** No — initial verification

## Method

This verification did not trust SUMMARY.md claims. Every automated gate the four plans depend on
was re-run independently, from a clean build, in this session:

- `go build ./...` — clean
- `go test ./cmd/topos/... ./kernel/config/...` — pass (bootstrap + DefaultConfig suites)
- `npm --prefix web run check` (svelte-check) — 0 errors, 850 files
- `npm --prefix web run test` (vitest) — 786/786 passed, including the three widened structural
  guards (`pane-layout.test.ts`, `marker-overlay.test.ts`, `source-chip-pill.test.ts`)
- Fresh SPA build (`npm --prefix web run build`) embedded into a freshly built kernel binary
  (`CGO_ENABLED=0 go build ./cmd/topos`) plus the mock/mockstrict plugins, then a real Chromium
  Playwright run:
  - `09-1-mobile-takeover.spec.ts` (11 cases), `09-1-compact-cards.spec.ts` (11 cases),
    `09-1-header-touch.spec.ts` (9 cases) — **31/31 passed**
  - `uat-04-zero-webspace-vs-outage.spec.ts` (the bootstrap payoff spec) — 3/3 passed
  - Full default-project regression sweep — **101/101 passed**, zero failures, no flakes observed

All test runs used real browser geometry assertions (`getBoundingClientRect`, `scrollWidth` vs
`clientWidth`), not class-string presence alone, for every claim that depends on rendered layout.
