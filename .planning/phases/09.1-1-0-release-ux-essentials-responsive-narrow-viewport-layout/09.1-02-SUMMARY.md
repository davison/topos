# Phase 09.1 Plan 02: First-Run Config Bootstrap Summary

**A missing `config.toml` is now a first-run event, not a fatal error: `topos serve`/`topos sync` write a canonical, secret-free, loopback-bound default (zero sources, zero webspaces, mode 0600 in a 0700 dir) and keep booting, reaching the already-shipped "No webspaces yet" + Create webspace screen.**

## Accomplishments
- `config.DefaultConfig()` — a new exported function in `kernel/config/types.go`, co-located beneath the `Default*` const block, returning the first-run config shape (raw form, non-nil empty `Sources`/`Webspaces` maps per R1)
- `bootstrapConfig(path, loadErr, logger)` in `cmd/topos/main.go` — narrowly gated on `errors.Is(loadErr, os.ErrNotExist)`, creates the config directory at `0700`, writes `config.DefaultConfig()` via the existing `WriteCanonical` (never a hand-rolled write), logs the path at INFO
- `setup()` restructured to resolve `configPath()` once into a local, call `bootstrapConfig` on a load failure, and re-load through `config.NewStore` on a successful bootstrap so the just-written file proves itself against real validation — shared unchanged by both `runServe` and `runSync` (R2)
- Full test coverage: positive (missing file, nested dir, hermetic `XDG_CONFIG_HOME` end-to-end), negative (non-ENOENT refusal), and the never-overwrite guard RESEARCH Pitfall 3 explicitly warns a positive-only suite would miss
- Confirmed the browser-visible payoff (zero webspaces -> "No webspaces yet" + working Create webspace CTA) needs no new e2e spec — the existing `uat-04-zero-webspace-vs-outage.spec.ts` still passes 3/3 unchanged (R4)
