<objective>
The browser half of KERN-05: a search box in the webspace header, and a results
region that replaces the stream while a query is active.

Everything here extends the Phase 1/2 UI contract rather than adding to it — one
new control and one new list, both built from components that already exist.
Results reuse `StreamRow` verbatim, so a search result looks exactly like a
stream row with its preview region carrying the match snippet; the loading state
reuses Phase 1's skeleton rows; the error and empty states use copy locked
verbatim in `03-UI-SPEC.md`'s Copywriting Contract. The only genuinely new
primitive is shadcn-svelte's `input` block, the single new registry block this
phase introduces.

Purpose: email is the first source that brings enough volume for scrolling to
stop being sufficient. This is the control that makes that volume navigable.

Output: `SearchBox.svelte`, `SearchResults.svelte`, the typed search client, and
the pure `parseSnippet`/`searchVariant` helpers the templates branch on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keystrokes -> kernel search route | The query string leaves the browser and re-enters the page inside the no-matches heading |
| kernel search response -> rendered result rows | Snippets and titles carry third-party-authored content (email subjects, document text) into the SPA document |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-21 | Tampering | Query text echoed into the no-matches heading | high | mitigate | The query is interpolated through Svelte's default text binding, which escapes it; no raw-HTML directive exists anywhere in the search components, asserted by an acceptance grep |
| T-03-22 | Tampering | Snippet text rendered with emphasis markup | high | mitigate | `parseSnippet` returns plain-text segments and the template emits one span per segment with the text bound as content, never as markup; the delimiters are control characters that cannot occur in source content, so no snippet content can forge a segment boundary |
| T-03-23 | Information Disclosure | Search results spanning webspaces or sources the user did not ask for | medium | mitigate | The client sends only the current route's webspace name and renders exactly what the kernel returns; scoping is enforced server-side by the mandatory `webspace_items` join (T-03-15) |
| T-03-24 | Denial of Service | As-you-type requests flooding the kernel | low | mitigate | A 300ms debounce plus a request-sequence guard means at most one in-flight query per pause, and a stale response is discarded rather than rendered |
| T-03-25 | Spoofing | A stale response overwriting a newer query's results | medium | mitigate | The monotonically increasing sequence number captured before the await and compared after discards any response that is not for the latest query |
</threat_model>
