<objective>
Close `02-UAT.md`'s single gap **G-02-1**. `web/src/app.css` declares the 01-UI-SPEC
spacing scale as seven named entries inside its `@theme inline` block. In Tailwind v4 those
entries become named keys in the spacing theme namespace and **shadow the default container
scale** that every named `max-w-*` utility resolves from. The shipped stylesheet therefore
compiles `.max-w-xs` to 4px, `.max-w-md` to 16px and `.max-w-3xl` to 64px (verified directly
in `kernel/webui/build/_app/immutable/assets/0.DGXW7fvo.css`, where `--container-*` appears
zero times).

Two user-visible symptoms, one root cause:
1. The health-chip tooltip (`TooltipContent`, whose own class list is `w-fit max-w-xs`) is
   capped at 4px — a ~10px sliver with unreadable text, defeating D-08's whole purpose.
2. The index page's `<main class="mx-auto max-w-3xl px-6">` is capped at 64px; the single-word
   `h1` overflows readably, but `Card.Root`'s `overflow-hidden` clips the webspace link into a
   few-pixels-wide, text-less — yet clickable — element.

Two latent victims not yet rendered in any UAT session: `StreamEmpty.svelte` (including D-09's
filtered-empty variant) and `StreamError.svelte`, both capped by `max-w-md` at 16px.

The seven tokens are referenced by **zero** utilities anywhere in `web/src` — they were added
as documentation of the UI-SPEC scale and are pure liability in a live namespace. They were
seeded by the same Phase-01 scaffold commit (`da15f94`) that omitted the `app.css` import
(G-01-2); this collision was invisible while zero CSS shipped and only became reachable once
01-05 made the stylesheet load at all.

Purpose: restore the phase's core promise — "tell at a glance whether what you are looking at
is complete and current" (UI-05, UI-06) — for the surface that actually carries that signal,
the health chip's hover diagnostic (D-08), and repair the index page regression the same
defect caused.
Output: a corrected theme block, a reusable built-stylesheet assertion, and the e2e smoke test
wired to it as a recurrence guard.
</objective>

<interfaces>

**Tailwind v4 resolution facts this plan depends on (verified against the shipped build):**

- Named `max-w-<key>` utilities resolve from the **container** theme namespace
  (`--container-xs: 20rem`, `--container-md: 28rem`, `--container-3xl: 48rem` are the
  relevant defaults). A named key present in the **spacing** theme namespace shadows the
  container key of the same name.
- Numeric spacing utilities (`px-3`, `gap-1.5`, `size-2`, `py-12`) resolve from the base
  `--spacing: 0.25rem` multiplier, which is untouched by this change and is already healthy
  in the current build. The 01-UI-SPEC 4px-multiple scale maps onto it exactly:
  4px→`1`, 8px→`2`, 16px→`4`, 24px→`6`, 32px→`8`, 48px→`12`, 64px→`16`.
- Entries inside a `@theme inline` block are **inlined** into the generated utilities rather
  than emitted as custom properties; Tailwind's own default theme is not inline, so once the
  shadowing entries are gone the built CSS is expected to carry `--container-<key>` custom
  properties and `var()` references. Assertions must tolerate either form (custom property
  set to the rem value, or the rem value inlined into the rule).

**Build wiring (from `Makefile` / `web/svelte.config.js`):**

- `npm --prefix web run build` writes the SPA directly into `kernel/webui/build/` (adapter-static
  `pages`/`assets` point there); `kernel/webui/embed.go` `go:embed`s it. The app stylesheet is
  a single content-hashed file under `kernel/webui/build/_app/immutable/assets/*.css` — the
  filename changes on every content change, so anything that reads it must glob, never hardcode.
- `kernel/webui/build/*` is gitignored (only `.gitkeep` is tracked). The built stylesheet is a
  local artifact: assertions read it, nothing commits it.
- `make build` = `npm ci` + `npm run build` + the three Go builds. `make smoke` = `make build`
  + `scripts/e2e-smoke.sh`, which needs `PAPERLESS_URL`/`PAPERLESS_TOKEN` and a live
  paperless-ngx instance — that is why the stylesheet assertion is being factored into a
  helper that also runs standalone with no server and no credentials.

**Existing `scripts/e2e-smoke.sh` stylesheet stage (added by 01-05 as the G-01-2 guard):**
after locating `CSS_HREF` in the served SPA HTML and fetching it to `"$CSS_TMP"`, it runs
three inline checks — link present, fetch succeeded, file non-empty, plus a `grep -qF` for the
`#020617` design token. The non-empty and token checks are the ones this plan relocates into
the helper; the "links no stylesheet" and "did not fetch successfully" checks stay where they
are, as does the existing `trap` that cleans up `$SERVER_PID` and `$CSS_TMP`.

</interfaces>
