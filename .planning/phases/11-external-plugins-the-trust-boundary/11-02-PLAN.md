<objective>
Turn the tier label from plan 11-01 into an enforced trust boundary: content-hash pinning verified before every external launch, a soft per-instance failure channel so one bad pin cannot take the kernel down, a scrubbed plugin launch environment, and arbitrary per-instance extras threaded to the plugin through the published contract.

Purpose: this is the security substance of PLUG-07 and the whole of PLUG-09's kernel half, plus D-14's env hygiene — the concrete answer to the threat the user raised themselves ("a malicious plugin could hoover up any number of values from well known env vars and phone home").

Output: `HashBinary`, a pre-exec pin gate, `ErrPinMismatch` + `Host.LaunchFailures`, an allowlisted `exec.Cmd.Env`, a nested `extras` object in `WEBSPACES_SOURCE_CONFIG`, and an additive `DescribeResponse.extras` declaration in the `topos.v1` proto.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk external binary -> kernel exec | The bytes about to be executed may have changed since the operator approved them |
| kernel process environment -> plugin subprocess | Everything in the kernel's environment is readable by any child that inherits it |
| config.toml -> plugin subprocess | Operator-authored values (including secret references) cross into code the project did not build |
| plugin Describe response -> kernel/UI | A plugin's self-description influences what the operator is asked to type |
