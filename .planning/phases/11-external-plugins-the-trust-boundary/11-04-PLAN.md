Prove the mechanism with a real binary the project did not build as part of its plugin set: a standalone module, outside `plugins/`, outside the audited in-repo plugin surface, built by its own target into its own output directory, discovered from the external tier, pinned, launched, and synced end to end.

Everything downstream in v1.1.0 (Phase 12's rehearsal, Phase 14's real out-of-repo source) rests on this being demonstrated rather than assumed.

Output: `testdata/external-plugin/` (a genuine separate Go module written against the published contract), a `make external-demo` target, and a supervisor-level Go test that boots a kernel against the built binary and asserts discovery, tier, pin enforcement, extras passthrough and environment scrubbing from the plugin's own point of view.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fixture module -> repo audits | A new Go module in the tree could silently widen or evade the repo's egress/module-pin/icon audits |
| fixture binary -> a real installation | A test binary that reached an operator's trusted plugin directory would be offered as a real source |
| proof binary -> kernel | It is deliberately launched as untrusted code, exercising the very boundary under test |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-20 | Elevation of Privilege | fixture binary reaching a real plugins directory | high | mitigate | Built only by its own target into `bin/plugins-external`, never by `build`/`plugins`/`plugins-portable`; the module lives under `testdata/` and its README states it must never be copied into a trusted directory |
| T-11-21 | Tampering | repo audit coverage | medium | mitigate | The module sits under a directory `internal/audit`'s `shouldSkipDir` already skips, so audit scope is unchanged rather than silently widened; `go test ./internal/audit/...` is an acceptance criterion |
| T-11-22 | Information Disclosure | the proof plugin's environment-reporting corpus | medium | mitigate | It emits variable NAMES only, never values, so a harness that deliberately hands it a value cannot leak that value into the index or into test output |
| T-11-23 | Tampering | supply chain of a separate module's go.sum | medium | mitigate | The module depends only on packages already used by the in-repo plugin set (sdk, go-plugin, grpc, protobuf), resolved through the existing workspace — no new third-party dependency is introduced |
| T-11-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install task exists in this plan; `go mod tidy` resolves only packages already present in the workspace's module graph |
</threat_model>
