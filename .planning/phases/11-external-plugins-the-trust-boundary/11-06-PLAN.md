<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| swapped binary -> operator's decision | Re-pinning is a human accepting new bytes; the UI must not make that feel routine |
| browser -> config.toml | The re-pin write decides which bytes the kernel will execute from now on |
| clipboard | The pinned hash is copied out of the app for manual comparison |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-30 | Spoofing | re-pin write | high | mitigate | The dialog writes back the kernel-published `current_hash`; the client never hashes anything, and the kernel re-verifies from disk at the resulting relaunch |
| T-11-31 | Repudiation | re-pin as a routine click | medium | mitigate | The dialog states plainly that topos cannot distinguish a rebuild from a replacement, shows both hashes, and requires an explicit confirm — it never presents the change as safe |
| T-11-32 | Tampering | action gated on error text | medium | mitigate | The menu item is gated on the closed-vocabulary `launch_failure` field; a source-scan guard asserts no `last_error` matching is used to enable it |
| T-11-33 | Denial of Service | one bad pin blocking saves or boot | high | mitigate | The browser spec asserts a config save succeeds while a source is pin-mismatched and that unrelated sources keep streaming; a Task 4 checkpoint follow-up found and closed the boot-time half — `pluginhost.ValidateMatchConfig` now excuses a currently-launch-failed instance from its own match-vocabulary check (a third participant class alongside "launched" and "suspended"), so a kernel restart with a pin-mismatched, webspace-participating instance boots successfully instead of refusing to start entirely |
| T-11-34 | Information Disclosure | clipboard write | low | accept | Only a content hash is copied — not a secret; a clipboard failure silently no-ops with the full value still available via the row's title attribute |
| T-11-SC | Tampering | npm/pip/cargo installs | low | accept | No new npm dependency — `ShieldCheck`, `Copy` and `Check` ship with the already-installed `@lucide/svelte` (UI-SPEC Registry Safety) |
</threat_model>
