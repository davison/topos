<objective>
Close gap G-06-6: rebuild the stream date-marker overlay so it reads as a deliberate navigation
affordance rather than, in the user's words, "CSS artifacts from a broken stylesheet or a faulty
page render".

Five defects, per `.planning/debug/date-marker-tick-styling.md` — the first three conjoint, the last
two each guaranteeing a visibly-broken render on their own:

1. **Geometry.** The overlay is inset 2px from the pane's right edge while the native scrollbar is
   ~11px wide, so 7px of every 12px tick is painted ON the scrollbar and 5px sticks out to its left.
   Tick and thumb share one 35%-alpha token, so each tick renders two different tones across its own
   width — and that tonal boundary slides along the tick as the user scrolls. A bar that changes
   tone mid-length and shifts while scrolling is the textbook signature of a broken render.
2. **Tone.** The rest tick computes to #353d4f: 1.86:1 against the pane background (below WCAG
   1.4.11's 3:1 non-text floor) and only 1.35:1 from `--border`. A 2px bar in the app's own hairline
   colour is by definition indistinguishable from a stray fragment of a border rule.
3. **Form.** No rail, no labels, no major/minor hierarchy, no pointer cursor, and a focus signal
   that is only a colour swap. Nothing binds the dashes into a system.
4. A marker at the very top is ALWAYS emitted and the tick is centre-translated onto it, so a tick
   is permanently half-rendered above the pane, spilling unclipped into the layout's padding.
5. There is no scroll-overflow guard, so a multi-date stream that fits the pane renders ticks with
   no scrollbar present at all — dashes decorating nothing.

The process cause is recorded too: 06-03-SUMMARY.md logged this overlay's visual check as human
judgment and it was never exercised. Nobody looked at it before UAT.

Purpose: this is a design-contract revision, not a touch-up. 06-UI-SPEC.md's marker section
under-specified the affordance and its own "reuse the thumb token, no new colour" constraint is what
forced the 1.86:1 tone. The spec is amended alongside the code, and the tone requirement becomes a
computed, automated assertion rather than a judgement call.

Output: the overlay moves into its own lane clear of the native scrollbar, on a reserved gutter so
it sits on one uniform surface; dedicated derived marker tokens at >= 3:1; a faint rail with a
major/minor tick hierarchy; edge-safe positioning; a real scroll-overflow gate; pointer and focus
affordances; and a guard test that computes the contrast rather than trusting it.

**No tracer task.** Gap closure against a shipped, wired overlay — the data flow, click-to-scroll,
tooltips and search-hiding all already work and are confirmed by UAT. Every task below reshapes an
existing surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source plugin → kernel index → SPA | Stream item ids originate in external stores and are interpolated into a CSS attribute selector by the tick click handler. |
| browser layout engine → component | Element measurements (`scrollHeight`, `clientHeight`) drive a reactive render, so a measurement loop is a self-inflicted availability risk. |
| overlay → native scrollbar | The overlay is painted over the same region the user drags to scroll; covering it degrades the primary control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-17 | Tampering | `scrollToMarker`'s `querySelector` over a plugin-supplied item id | medium | mitigate | The id is already wrapped in `CSS.escape` before interpolation into the attribute selector, and both the missing-container and missing-target paths are no-ops rather than throws. Task 2 forbids altering that handler and Task 3's guard asserts the escape call is still present, so a restyle cannot quietly drop it. |
| T-06-18 | Denial of service | the new `scrollHeight` measurement wired through `observeResize` | medium | mitigate | `measure` writes the content height only when the value actually changed and never schedules a synchronous re-measure from inside itself; the observer is attached in a ref-driven `$effect` returning `observeResize`'s idempotent teardown. This is the same bounded pattern already proven for the chip row, and it is what prevents a resize-then-measure feedback loop from pinning the tab's main thread. |
| T-06-19 | Denial of service | overlay hit-areas painted over the native scrollbar | medium | mitigate | The lane's trailing edge is offset by at least the declared scrollbar width and each tick's hit-area is widened leftward only, so the thumb stays grabbable; the container keeps `pointer-events-none` with only tick hit-areas opting back in, so rows underneath stay clickable. Task 3's guard derives the required offset from `app.css`'s own scrollbar width rather than a second hardcoded copy. |
| T-06-20 | Information disclosure | the date ruler exposes the stream's temporal shape at a glance | low | accept | All rendered data is already on screen in the stream rows the ruler annotates, and the app is a single-user, local-only desktop tool.
