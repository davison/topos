<objective>
Close the single recorded Phase 6 gap: `WebspaceHeader.svelte`'s chip-row `ResizeObserver` never observes anything, so the overflow computation that keeps UI-07's "usable at 10+ instances" promise is correct exactly once — at initial load — and then goes silently stale for the rest of the session.

The observer is constructed in a one-shot mount hook that fires while the sources request is still in flight, when the row's render gate is false and all four measured elements are therefore unbound. Every guarded `observe` call is skipped, nothing re-attaches later, and the overflow-trigger measurement clone was never in the watch list at all. A user who narrows their browser window after the page has loaded can end up with a chip clipped by the row's hidden overflow and no '+N' trigger showing — which is precisely the silent-invisibility failure the phase's own prohibition rules out, since a hidden chip may be the unreachable one.

Purpose: restore UI-07's session-lifetime half — "stays usable as the instance count grows" — not just its initial-load half.
Output: an injectable attachment helper with real behavioural tests, a ref-driven effect in the header covering all four measured elements, and a comment-stripped source-scan guard so this defect class cannot pass a gate again while still being broken.
</objective>

**`web/src/lib/resize-observer.ts` (new).** A small module holding the app's only real observer construction site.

Export an interface `ResizeObserverLike` declaring just the two members this app uses: `observe(target: Element): void` and `disconnect(): void`. Export a type `CreateResizeObserver` as `(onResize: () => void) => ResizeObserverLike`.

Export `observeResize(targets, onResize, createObserver?)` where `targets` is a readonly array of `Element | undefined | null`, `onResize` is a zero-argument callback, and `createObserver` is an optional factory defaulting to the real constructor. Behaviour:
- Filter `targets` down to the bound ones. If none remain, construct nothing and return a teardown that does nothing — this is the state on first mount, before the sources request resolves and before the row's render gate turns true, and constructing an observer with nothing to watch would be the same dead wiring this plan exists to remove.
- Otherwise call the factory once with a callback that invokes `onResize`, call `observe` once per bound target in the order given, and return a teardown that calls `disconnect` on that observer. Guard the teardown with a local flag so a second call is a no-op — a ref-driven effect can legitimately tear down more than once, and a double disconnect should be inert rather than a second call into a released observer.
- The default factory must be referenced **lazily**, inside the parameter default or the function body, never evaluated at module scope. The test runner's environment is `node` with no DOM globals; touching the real constructor at import time would break every test that imports this module.
- Document in the module's own doc comment why the factory parameter exists — it is the seam that makes attachment provable without a component-mount harness — and state that the real observer ignores a repeated observe of the same element, so no de-duplication is needed here.
