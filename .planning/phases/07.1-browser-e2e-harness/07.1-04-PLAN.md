<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser UI state -> on-disk config.toml | The UI renders from an in-memory config document after a save; the file is the real persisted state and can diverge. |
| Route interception -> the SPA's own failure paths | Specs deliberately induce failures the app must handle; a handler registered too late induces nothing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.1-14 | Tampering | canonical config writer | high | mitigate | Every spec that ports a UAT item naming a file outcome asserts through `readConfigToml` on the parsed document (D-04). A canonical-writer regression — dropped table, reordered or requoted keys, an allowlist written as every instance rather than the chosen one — is caught on disk even when the UI still renders correctly from memory. |
| T-07.1-04 | Repudiation | route-interception assertions | high | mitigate | Every route handler is registered before the triggering action (07.1-RESEARCH.md Pitfall 5); the failed-refetch clause additionally asserts recovery after the handler is removed, so a handler that never fired cannot masquerade as a pass. |
| T-07.1-15 | Repudiation | negative assertions | medium | mitigate | G-07-1's guard is the ABSENCE of the outage state, so its absence is asserted directly (`Retry` and the outage copy) rather than inferred from the empty copy's presence; likewise item 3 asserts key absence rather than emptiness, which 07-12's collection normalisation would otherwise mask. |
| T-07.1-13 | Tampering | shipped SPA source | medium | mitigate | `git diff --stat HEAD -- web/src` must be empty in every task; a spec may not add markup to the application to make itself easier to write. |
</threat_model>
