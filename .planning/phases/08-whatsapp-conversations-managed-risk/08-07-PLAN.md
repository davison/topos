<objective>
Land the recovery affordance and the regression armor that would have caught
G-08-1 before it reached a real device.

The gap's second half is that a genuinely successful pairing was thrown away:
whatsmeow persists the device row before it dispatches `PairSuccess`, so the
user's phone really was linked, but cancelling the dialog wrote no
`[sources.*]` instance and nothing ever connected to it. Plans 08-05 and 08-06
make that recoverable — a fresh session against the same path now announces
`already_linked` and the panel carries the flow forward without a QR. This plan
proves that path, tells a user who declines the panel what their options are,
and closes the structural test gap the debug session named: the suite's success
case scripts `paired` into the START response, so the only sequence a real
device produces — `qr` then, later, `paired` — has never been exercised.

Purpose: discharge this phase's standing rule (`docs/testing.md`, Phase 07.1
D-11) for this change — a UAT item a browser can drive becomes a spec, not a
remembered manual check.
Output: three new hermetic Playwright cases, a neutral Step 1 notice, and a
human re-test of the real-device flow.
</objective>

reports a 60-second validity window for its first code — the one a user actually
scans — and under the pre-fix cadence the panel's next poll would not fire for
those 60 seconds, so the terminal event the kernel had already recorded would
sit undelivered and these assertions would time out. Give the progress and match
assertions an explicit timeout well under 60 seconds (15 seconds is generous
against a 2-second cadence and three round trips) so the case fails loudly rather
than passing slowly if the cadence regresses. Cite `08-UAT.md`'s `G-08-1` in the
case's own comment.

image is gone; the panel's Cancel button has count 0 within the dialog; the
dialog itself is still open (count 1). Comment why: cancelling here SIGKILLs the
link subprocess mid-login-handshake and strands a pairing whatsmeow has already
