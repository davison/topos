<objective>
Close the PLUGIN half of `08-UAT.md` gap G-08-4: after a real-device WhatsApp pairing, the
freshly launched serve-mode instance reported, verbatim, "Not linked — pair this device with
WhatsApp to start syncing" for a device that was in fact already paired and actively connecting.

The diagnosis (`.planning/debug/whatsapp-paired-session-not-picked-up.md`, empirically confirmed:
a zero-value `&SourcePlugin{}` reproduces the reported gRPC message byte-for-byte) names two
plugin-side defects:

1. `plugins/whatsapp/health.go` has no state meaning "linked, socket up, login handshake in
   progress", and `healthStateNotLinked` is `iota == 0` — so it doubles as the uninitialised
   Go zero value.
2. `connect.go`'s SUCCESSFUL `startBackgroundClient` path (`device.ID != nil` AND
   `client.Connect()` returned nil) calls `setHealthState` with nothing at all, leaving
   `p.state` at that zero value, and returns immediately — so `main.go` reaches
   `goplugin.Serve` (and the kernel's handshake completes) at the FIRST instant of the
   not-yet-`*events.Connected` window.

Purpose: make the plugin's reported health honest at every instant of its own process life, and
make the go-plugin handshake mean "ready" in the normal case, so the kernel's first Match after
a (re)launch no longer lands on a factually false, actionable-sounding error.

Output: a sixth named health state, an explicitly-assigned connect path, a bounded serve-mode
login wait reusing the primitive `pairwait.go` already proves against a real device, and
regression armor for the exact message identity the user reported.

Scope note: this plan touches NO frontend file and adds no new visual state (08-UI-SPEC.md's
standing "No new visual states" rule holds — the new cause maps onto the existing `destructive`
tone like the other five), so the project's standing "any UI-touching phase extends the
Playwright e2e suite" rule (`.claude/CLAUDE.md`, `docs/testing.md`) does not apply here. The
hermetic regression gate for this failure CLASS is plan 08-12's job.
</objective>
