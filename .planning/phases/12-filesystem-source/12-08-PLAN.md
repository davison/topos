<objective>
Close the FIRST `missing:` item of G-12-1/G-12-3: **make "everything from this
instance" expressible in a webspace match block**, and make the page an operator reads
say out loud that match values are exact strings, never globs.

**The failure being closed.** The user's real config carried
`[webspaces.test.match.files] folders = ['*']` (and, one save earlier, `['**']`). Every
layer compares match values as exact, case-insensitive strings — `plugins/filesystem/plugin.go`'s
`labelMatchesAny` via `strings.EqualFold`, with `kernel/correlate`'s `matchFieldsFor`
forwarding the block verbatim and no wildcard handling anywhere kernel-side. So the value
matched no label, the plugin's `Match` RPC returned zero items, `sync`/`Health` reported `ok`,
and the stream was silently empty. Two facts made that mistake reachable and then irreversible:

1. **The intent was inexpressible.** `folderLabels` gives a top-level file exactly one label
   (the configured root's base name) and gives a NESTED file only its containing-directory
   segments plus the cumulative relative path — never the root base name. So for a recursive
   source there is no single `folders` value that covers every file. An operator reaching for
   "just give me everything from this folder" had nothing correct to type, and reached for `*`.
2. **The page that documents globs never says match values are not globs.**
   `docs/plugins/filesystem.md` documents `include_glob`/`exclude_glob` as real doublestar
   patterns (`**` supported) and, a few sections later, documents the `folders` match vocabulary
   without once stating that ITS values are literals. This is the one plugin in the repo whose
   extras take globs; it is exactly the plugin where the assumption transfers.

Purpose: SRC-04's "documents appear in webspace streams" clause was false for the user's real
configuration despite 46/50 UAT items passing. After this plan the operator has a correct value
to type, a page that tells them so, and a committed end-to-end proof of both the correct value
working and the glob-shaped value not working.

Output: one label added to nested files (deduped, root-confined), the folders section of
`docs/plugins/filesystem.md` rewritten to state the exact-match rule and the worked
"everything from this instance" recipe, the same statement in `config.example.toml`'s two
relevant places, and one new e2e spec that reproduces the user's exact mistake alongside its fix.

## Non-goals (do not do these)

- Do NOT teach any layer glob or wildcard semantics for match values. No special-casing of `*`,
  `**`, `?` or `[` anywhere in the plugin, the kernel or the contract. The exact-match discipline
  (D-04, `docs/plugin-contract.md` rule 2) is a cross-plugin invariant; five plugins implement it
  identically and a sixth behaviour would be worse than the gap being closed.
- Do NOT add a new match field to the `folders` vocabulary, and do NOT change
  `matchVocabulary`. The vocabulary is unchanged; only the VALUES a file reports change.
- Do NOT build the zero-match diagnostic here. That is the SECOND `missing:` item and belongs
  to `12-09-PLAN.md`, which runs in this same wave against entirely different files. Do not
  reference a `last_notice`/advisory surface in any doc this plan touches — it does not exist yet
  when this plan's own gates run.
- Do NOT touch `docs/api.md` (12-09 owns it this wave) or any file under `web/src/` (12-10 owns
  those next wave).
- Do NOT modify any existing e2e spec. `12-filesystem-recursion.spec.ts` keys its webspace on the
  nested subfolder's own name, which this change leaves valid — it must keep passing untouched.
