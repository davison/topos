<objective>
Close the two gaps `12-VERIFICATION.md` recorded (status `gaps_found`, 4/6 truths), both of
which trace to unresolved Critical findings in `12-REVIEW.md`:

- **CR-01 (G-12-1)** — `kernel/httpapi/fsopen.go`'s `newXDGOpener` builds the child with
  `exec.CommandContext(ctx, …)` where `ctx` is `r.Context()`. `net/http` cancels a request's
  context essentially synchronously with the handler returning, and `FilesystemOpenHandler`
  returns within microseconds of starting the child — so the desktop handler is routinely
  SIGKILLed moments after launch while the kernel answers `200 {"opened": true}`. Success
  criterion 3 ("every filesystem item deep-links back to the document in the desktop's own
  file handler") is false in practice, and the API lies about it.
- **CR-02 (G-12-2)** — the two containment re-validations that actually touch bytes or exec a
  program (`plugins/filesystem/item.go`'s `resolvePath`, reached from `fetch.go`'s
  `fetchByKind`; and `kernel/httpapi/fsopen.go`'s inline check) are purely lexical
  (`filepath.Join` + `strings.HasPrefix`) and never resolve symlinks — unlike `walk.go`'s
  Match-time check, which does. A post-index symlink swap escapes the configured root on both
  the byte-serving and exec paths, breaking the phase's hard prohibition and falsifying the
  guarantee published to third-party plugin authors at `docs/plugin-contract.md:851-857`.

**WR-01** (Warning, non-blocking, carried forward by the verifier as "should be closed
alongside") is fixed here too: `walk.go` compares a resolved symlink target against a root that
is itself never resolved, so a configured root behind a symlink or bind mount (the common
`~/Documents` → `~/dotfiles/Documents` dotfile-manager pattern) silently drops every
legitimately in-tree symlinked file. It is the same "resolve the root once" discipline the
CR-02 fix introduces, applied to the third site — closing it here means the phase ships one
containment rule, not two-and-a-half.

Purpose: SRC-04's "documents appear with previews and deep links" clause is currently
unsatisfied, and `REQUIREMENTS.md` records SRC-04 as Gaps Found. This plan makes the phase's own
published guarantee true of the shipped code and gives both classes of defect the regression
tests that structurally cannot exist today — the current suite stubs the `Opener` entirely and
only ever exercises `..`-segment traversal, never a symlink swap or a context cancellation.

Output: a symlink-resolving containment rule at all three sites, an `xdg-open` child whose
lifetime is decoupled from the HTTP request, eight new regression tests across three test
files, three existing tests corrected to materialise real fixture files, and three docs brought
back into agreement with the code.

Scope discipline: this plan closes those findings and nothing else. It does not touch the
phase's UI work, the scope/classification pipeline, the read-only AST guard, the external-tier
rehearsal, `REQUIREMENTS.md`'s traceability marks (the verifier owns those), or any executed
plan or SUMMARY. Plans 12-01 through 12-05 are executed and committed; this plan is additive.

deterministic edge probe over SRC-04 reports one unresolved category: *"If interrupted or run
in parallel, what is guaranteed?"* No phase SPEC exists to answer it, so it is recorded here as

**Assumed resolution:** the existing walk/full-replace design already answers it, and this plan
does not change that design. `walk` returns the COMPLETE current set or an error — never a
partial one (context cancellation, an unreadable root, and cap exhaustion all abort with an
error), and the kernel's `ReplaceWebspaceSourceItems` treats a returned set as the whole truth.
So an interrupted sync leaves the previous complete set in the index rather than a truncated
one, and a concurrent sync either replaces the set wholesale or fails without writing. Nothing
in this plan introduces cross-request shared mutable state: `resolveRoot` and `resolvePath` are
pure functions of their arguments, and the newly detached `xdg-open` child is per-request and
independent.

**Residual, accepted:** the symlink-resolve-then-open sequence is a path-based check and
therefore retains a microsecond-scale TOCTOU window between `filepath.EvalSymlinks` and the
subsequent `os.ReadFile`/exec. Closing it completely requires `openat`/`O_NOFOLLOW`-based
traversal, which is out of scope at ASVS L1 for a single-user loopback desktop tool. Recorded
as T-12-23 in the threat model with an explicit `accept` disposition rather than left implicit.
