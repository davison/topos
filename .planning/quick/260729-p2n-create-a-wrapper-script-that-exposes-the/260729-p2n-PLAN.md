<objective>
Add a bash wrapper that runs the `bin/webspaces` binary with the credentials in the
repo-root `.env` exported into its environment, so a UAT session can just run
`./scripts/run-with-env.sh serve` from a fresh shell.

Purpose: `./bin/webspaces serve` currently fails from a clean shell because
`~/.config/webspaces/config.toml` references `${PAPERLESS_URL}`, `${PAPERLESS_TOKEN}`,
`${SB_URL}` and `${SB_AUTH_TOKEN}`, which `kernel/config.Load` expands from the process
environment. Today only `scripts/e2e-smoke.sh` knows how to source `.env`, and it always
does a full build + sync + smoke run — there is no way to just *serve* with the real
credentials. UAT sessions currently need the operator to hand-export secrets.

Output: `scripts/run-with-env.sh`, a committed behavioural check for it, and README
documentation.
</objective>

<interfaces>
Established facts this plan builds on (verified during planning — do not re-derive):

- `.env` lives at the repo root, is gitignored, and defines exactly four keys:
  `PAPERLESS_URL`, `PAPERLESS_TOKEN`, `SB_URL`, `SB_AUTH_TOKEN`. Format is
  shell-sourceable `KEY=value` lines.
- `kernel/config/config.go` `Load()` reads the raw config bytes, runs `expandEnv`
  (`os.Expand` over `${VAR}` / `$VAR`), and returns an error naming any
  referenced-but-unset variable. So the wrapper does NOT need to duplicate
  required-variable validation — the kernel already produces a precise error.
- `config.example.toml` line 85 is `base_url = "${PAPERLESS_URL}"`; `kernel/config/types.go`
  lines 42-43 document that `token` is always an env reference, never a literal secret.
- The binary is produced at `bin/webspaces` by `make build`
  (`CGO_ENABLED=0 go build -o bin/webspaces ./cmd/webspaces`).
- Existing script conventions (`scripts/e2e-smoke.sh`, `scripts/assert-stylesheet.sh`):
  `#!/usr/bin/env bash` shebang, a multi-line `#` comment header explaining intent,
  `set -euo pipefail`, `SCRIPT_DIR`/`REPO_ROOT` resolution via `BASH_SOURCE[0]`,
  `cd "$REPO_ROOT"`, failure messages to stderr prefixed `FAIL:`, executable bit set.
</interfaces>

  <name>Task 1: Add scripts/run-with-env.sh and its behavioural check</name>
  <files>scripts/run-with-env.sh, scripts/check-run-with-env.sh</files>
  <action>
Create `scripts/run-with-env.sh`, following the header/shebang/`set -euo pipefail`/
`SCRIPT_DIR`+`REPO_ROOT`/`cd "$REPO_ROOT"` conventions already used by
`scripts/e2e-smoke.sh`. Behaviour, in order:

1. Resolve `REPO_ROOT` from `BASH_SOURCE[0]` and `cd` there, so relative paths in
   the kernel's own config resolution behave the same as a manual `./bin/webspaces` run.
2. Resolve two overridable paths: an env-file path defaulting to `$REPO_ROOT/.env`
   (override via `WEBSPACES_ENV_FILE`) and a binary path defaulting to
   `$REPO_ROOT/bin/webspaces` (override via `WEBSPACES_BIN`). Document both in the
   header comment as existing so the wrapper is testable without live credentials —
   they are not a general-purpose configuration surface.
3. If no arguments were passed, print a one-line usage string to stderr
   (`usage: scripts/run-with-env.sh <webspaces-args...>` plus a `serve` example) and
   exit 2. This is both better UX than an argument-less binary invocation and it
   sidesteps `"$@"` expansion under `set -u`.
4. If the env file exists, source it with the exact `set -a` / `.` / `set +a` idiom from
   `scripts/e2e-smoke.sh` lines 15-20 so every key is EXPORTED — assignment alone is not
   enough, because the kernel expands `${PAPERLESS_URL}`-style config references from the
   process environment and passes that environment down to plugin subprocesses. If the
   env file does not exist, print a single stderr note naming the path it looked for and
   continue, so an operator who already has the variables exported is not blocked.
5. Deliberately do NOT re-validate that the four keys are present. `kernel/config.Load`
   already fails with an error naming the specific missing variable; duplicating that
   policy here would drift and would wrongly reject a config that only uses one source.
6. Verify the binary exists and is executable; if not, fail to stderr with a `FAIL:`
   message that names the expected path and tells the operator to run `make build`.
7. `exec` the binary with `"$@"` so arguments pass through verbatim and the kernel
   inherits the wrapper's PID (signals and `Ctrl-C` reach the server directly, which
   matters for a long-running `serve` during UAT).

Secret hygiene is a hard requirement of this script: it must never echo the value of any
variable it sources, must not enable shell tracing, and every diagnostic it emits may name
a variable or a path but never a value. Add an explicit `set +x` immediately after
`set -euo pipefail` as insurance against an inherited exported `SHELLOPTS`, with a brief
comment saying why. Note in the header that the env file is *sourced*, i.e. executed as
bash — acceptable at exactly the trust level `scripts/e2e-smoke.sh` already assumes for
the same file.

Then create `scripts/check-run-with-env.sh`, a committed, credential-free behavioural
check for the wrapper — same conventions, following `scripts/assert-stylesheet.sh`'s role
as a standalone committed assertion script. It must:

- Build a throwaway directory (`mktemp -d`, removed via a `trap ... EXIT`) containing a
  fixture env file with the four real key NAMES but obviously-fake values, using the
  literal `SENTINELVALUE9f3a` as both token values.
- Write a fake binary into that directory (`chmod +x`) that prints `ARGS:$*` and then
  prints presence-only lines using `${VAR:+yes}` expansion — `PAPERLESS_TOKEN_SET:${PAPERLESS_TOKEN:+yes}`
  and `SB_AUTH_TOKEN_SET:${SB_AUTH_TOKEN:+yes}` — so the check proves export happened
  without the fake binary ever printing a value.
- Run `WEBSPACES_ENV_FILE=... WEBSPACES_BIN=... "$SCRIPT_DIR/run-with-env.sh" serve --host 127.0.0.1`
  capturing combined stdout+stderr into a variable, then assert: the captured output
  contains `ARGS:serve --host 127.0.0.1` (verbatim pass-through, in order), contains
  `PAPERLESS_TOKEN_SET:yes` and `SB_AUTH_TOKEN_SET:yes` (export reached the child), and
  does NOT contain the fixture's fake token value (no leak).
- Assert the zero-argument case exits non-zero and prints a usage line.
- Assert that a `WEBSPACES_BIN` pointing at a non-existent path fails with a message
  mentioning `make build`.
- Print `check-run-with-env: PASS` on success; use `FAIL:`-prefixed stderr messages and a
  non-zero exit otherwise. None of the check script's own progress or failure messages may
  include the fixture's fake token value.

Set the executable bit on both files (`chmod +x`).
  </action>

    <automated>chmod +x scripts/run-with-env.sh scripts/check-run-with-env.sh && bash -n scripts/run-with-env.sh && bash -n scripts/check-run-with-env.sh && ./scripts/check-run-with-env.sh</automated>
  </verify>
  <done>
`./scripts/check-run-with-env.sh` exits 0 printing `check-run-with-env: PASS`, having

keys are exported into the child process; the wrapper's combined output never contains

binary each fail with an actionable message (the latter naming `make build`). Both files

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.env` file → wrapper process | Credentials cross from an at-rest gitignored file into a live process environment |
| wrapper process → `bin/webspaces` + plugin subprocesses | Exported credentials are inherited by the kernel and every go-plugin subprocess it spawns |
| wrapper process → operator's terminal / UAT transcript | The only place a credential could accidentally become visible or be captured in a log |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-QUICK-01 | Information Disclosure | `scripts/run-with-env.sh` stdout/stderr | high | mitigate | Script never echoes a sourced value; explicit `set +x` defeats an inherited `SHELLOPTS`; all diagnostics name variables/paths only. `scripts/check-run-with-env.sh` asserts a fixture token value never appears in the wrapper's combined output. |
| T-QUICK-02 | Information Disclosure | repo-root `.env` | medium | accept | `.env` is already gitignored (verified during planning) and the wrapper only reads it — it never copies, rewrites, or relocates it. Residual risk is unchanged from `scripts/e2e-smoke.sh`, which already sources the same file. |
| T-QUICK-03 | Tampering / Elevation | sourcing `.env` as bash | medium | accept | `.` executes the env file as shell code, so a tampered `.env` runs arbitrary code as the operator. Scoped to a user-owned, gitignored, repo-root file at exactly the trust level `scripts/e2e-smoke.sh` already assumes; documented in the script header rather than mitigated with a parser, which would diverge from the existing idiom. |
| T-QUICK-04 | Information Disclosure | `WEBSPACES_BIN` override | low | accept | The override lets a caller point the wrapper at an arbitrary binary that would inherit the credentials. It requires the ability to set env vars in the operator's own shell — i.e. the attacker already has that shell — so it grants no new capability. Documented as a testability hook. |
