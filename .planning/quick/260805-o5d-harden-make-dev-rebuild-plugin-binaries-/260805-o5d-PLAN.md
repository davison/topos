<objective>
Harden `make dev` against the two footguns that burned a debugging session on 2026-08-05:

1. **Silent plugin staleness** — `make dev` runs `go run ./cmd/webspaces serve` plus Vite but never rebuilds `bin/plugins/*`, so plugin source edits silently do not take effect.
2. **Silent port-race loss** — when `127.0.0.1:7777` is already bound by a stale kernel, the backgrounded `go run` child dies instantly while Vite keeps running and proxies to the stale kernel, presenting a working-looking UI backed by old code.

Purpose: the developer loop must never lie about what code is running. Both failures are silent today; both become loud, non-zero, and self-explanatory.

Output: a `plugins` make target wired as a `dev` prerequisite, a fail-loud `dev` recipe, a committed hermetic guard script that proves both behaviours, and README documentation of the new contract.
</objective>

<makefile_hazards>
Read before editing any recipe. Each of these silently corrupts a backslash-continued recipe:

- **No `#` anywhere inside the `dev` recipe.** The recipe is one backslash-continued shell line; a `#` starts a shell comment that swallows the entire remainder of the line, continuations included. Put explanatory comments ABOVE the target, in Make comment lines, as the existing file already does for `build`, `signal`, `test` and `proto`.
- `$$` for shell variables, `$$(...)` for command substitution, `$$!` for the last background PID, `$(VAR)` for Make variables.
- Lines containing `$(MAKE)` are executed even under `make -n`, which recurses in dry-run mode and prints (does not run) the sub-target's commands. This is why `make -n dev` is a valid wiring assertion.
- Command-line variable assignments (`make dev DEV_PORT=9999`) override `?=` defaults. That is the intended override mechanism.
</makefile_hazards>
