<objective>
Exclude `topos-plugin-mockstrict` from the "+" picker's installable plugin-type
catalog, exactly as `topos-plugin-mock` already is, without losing any of the
browser-harness coverage that currently drives the catalog through mockstrict.

Purpose: the user's own picker offers `Mockstrict` as an installable source
type. `plugins/mockstrict` is pure e2e-harness fixture infrastructure (its own
doc comment: "exists purely as harness fixture infrastructure"), so offering it
lets a real config enable a fixed set of fake corpus items backed by no real
data anywhere — the identical failure mode 07-RESEARCH.md Open Question 1
decided for `topos-plugin-mock`.

Root cause of the exposure: `make e2e` builds `topos-plugin-mockstrict` into
`bin/plugins/` — the same directory `make build`/`make dev` use and a real
`[plugins] dir` points at. The Makefile's own comment asserts that keeping
mockstrict out of the `plugins` target is what keeps it out of the operator's
picker; that reasoning is incomplete, which is why the bug is visible.

Output: an unconditional kernel-side exclusion, falsifiable Go and browser
gates in both directions (never offered as a NEW type / always offered as an
EXISTING instance), and corrected documentation.
</objective>
