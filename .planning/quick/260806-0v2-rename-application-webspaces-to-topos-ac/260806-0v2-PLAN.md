<objective>
Rename the application from "webspaces" to "topos" across the repository — product name, Go module paths, proto package, plugin binaries, kernel default config/data paths, handshake magic cookie, and the contract version wire value — and migrate the user's live install onto the new paths.

Purpose: the first push to `github.com/davison/topos` fixes the module path permanently for any third-party plugin author, and Phase 5 is about to republish the plugin contract. Renaming now costs one mechanical commit set; renaming after either event is a breaking change to a published contract.

Output: a repo that builds `bin/topos` + `bin/plugins/topos-plugin-*` from `github.com/davison/topos` modules against a `topos.v1` proto contract, with the user's live config and index migrated to `~/.config/topos/` and `~/.local/share/topos/`, all test suites green, and the app verified running.

**Scope decision — product renamed, concept retained.** Measured before planning: the PRODUCT-name surface is ~460 occurrences (module path 109, proto package/path 102, binary names 61, cmd/bin/config/data paths ~40, plus prose). The CONCEPT surface — the word `webspace` meaning "a configured topic space" — is ~940 occurrences across 85 files and includes the SQLite `webspace` column, the FTS5 external-content table and its triggers, `Webspace`/`ListWebspaces`/`ReplaceWebspaceSourceItems` identifiers, the `/api/webspaces` routes, the `webspace_not_found` error code, the `[webspaces.*]` config table, and the `/w/[webspace]` SvelteKit route directory. Renaming the concept would require a live schema migration against the user's real `index.db`, roughly tripling the diff and adding data-loss risk for zero pre-push benefit. Phase 5 is already a clean-break config change (05-CONTEXT.md D-06: the kernel rejects an old-shape config outright, and the live config is hand-migrated as part of that phase) — the concept rename rides that break for free if it is ever wanted. **This task renames the product only. `webspace` remains the internal and user-facing term for a topic space, and that is deliberate, not an oversight.**
</objective>
